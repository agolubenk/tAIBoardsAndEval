# Бот «Очередь владельца» (@hrhelper_owner_queue_bot)

Telegram-бот очереди владельца. С 18.10.2026 очередь живёт в ops-консоли (`/queue`, спека
[`docs/specs/owner-queue.md`](../../docs/specs/owner-queue.md)), а не в артефакте claude.ai.

Бот умеет всё, что страница очереди:
- разделы «Решения / Мёржи / На сервере / Проверить руками»;
- карточки с командами, выбор варианта, «Влил / Выполнил / Проверил»;
- комментарий или вывод команды, в том числе файлом;
- «Изменить ответ», «Показать выполненные»;
- статусы агентов, «Ход работ» и графики, Гант и роадмап картинками.

**Входящие из Telegram (с 21.10).** Перешлите боту алерт, жалобу или мысль. Бот угадает тип и срочность
(`classify.mjs`, без ИИ) и покажет черновик с кнопками: 🐞 / 💡 / 📝 / 🚨, ⚡ сейчас или 🗂 в очередь, важность,
«✏️ Дописать». «Отправить» создаёт пункт `kind: inbox` (`inbox.mjs`), его ведёт агент-сессия. Подробности — спека
[`docs/specs/owner-queue.md`](../../docs/specs/owner-queue.md), «Входящие из Telegram». Боты алертов — `alertBots` в
`config.json` или `OQB_ALERT_BOTS`, по умолчанию бот консоли.

**Вложения (с 22.10).** Документ и фото в черновике — файлы задачи: альбом — один черновик, фото без имени —
`фото-1.jpg`; что не прикрепится (лимит консоли, больше 20 МБ), видно на карточке до «Отправить». После записи пункта
файлы грузятся в консоль по одному: скачать у Telegram в `<OQB_HOME>/files-tmp` один раз, при сбое связи — повтор
через 1, 5 и 30 с, очередь в `state.json` переживает перезапуск (не дольше часа). Итог — строкой в карточке «Принято»,
при сбоях связи — «🔁 Повторить файлы». «📎 Прикрепить файл» в карточке — режим на 10 минут для докрепления.
Код — `uploads.mjs` (очередь), `attach.mjs` (режим), `files-setup.mjs` (лимиты и правка карточки); голос и видео
агенту недоступны — их бот просит описать словами. Подробности — спека, «Вложения».

Сверх страницы:
- **«🚀 Влить сейчас…»** у пункта мёржа: экран подтверждения с SHA и последствием (деплой или `[skip ci]`), затем «Да»;
- **«♻️ Перезапустить деплой»** в разделе мёржей;
- живая сводка, «Следующий», поиск, уведомления о новых пунктах и статусах агентов.

## Как устроено

```
Telegram ⇄ bot.mjs ⇄ mirror.mjs ⇄ headless Chromium ⇄ ops-консоль /queue ⇄ /api/oq/v1 ⇄ oq_docs (SQLite)
                   ⇄ api.mjs (мёрж, деплой) ──────────────────────────────┘
```

- Бот не дублирует логику страницы. Он держит открытой `/queue` и нажимает её же элементы, а ответ сохраняет
  код страницы через API консоли. Новые поля и пункты бот подхватывает без правок.
- Токен очереди (`queueToken`, область `owner`) уходит заголовком `Authorization` **только в запросы к
  консоли**. Шрифтам Google он не передаётся.
- Сохранение подтверждается своей подпиской на `checks/`: «Сохранено ✓» — только когда в базе появилась новая
  запись. Кнопка ответа несёт версию пункта: если агент поменял пункт, ответ не записывается.
- HTML от агентов проходит белый список (`tg-html.mjs`): https-ссылки показываются с доменом, невидимые символы
  в командах — метками. Команда длиннее 3000 символов приходит файлом `.sh`. Серверные команды бот только
  показывает и не выполняет.
- Доступ — только у привязанного владельца (`owners`), только в личном чате.

| Файл | Что делает |
|---|---|
| `bot.mjs` | вход: long polling, команды и кнопки, мёрж и деплой, фоновые уведомления |
| `mirror.mjs` | Chromium под Playwright: страница `/queue`, снимок, действия с подтверждением, скриншоты, перезапуск зависшего браузера |
| `frame-scripts.mjs` | функции, выполняемые внутри страницы |
| `api.mjs` | клиент API консоли: мёрж, перезапуск деплоя, входящие и их вложения |
| `uploads.mjs` · `attach.mjs` · `files-setup.mjs` | вложения: что прикрепляется и очередь загрузок; режим «📎 Прикрепить файл»; лимиты консоли и строка хода в карточке |
| `view.mjs` · `tg-html.mjs` | отрисовка в HTML Telegram, клавиатуры, белый список HTML |
| `notes.mjs` · `watch.mjs` | ввод текста в поле; фон: уведомления, связь, живая сводка |
| `telegram.mjs` · `store.mjs` | клиент Bot API; конфиг и состояние в `~/.hr-owner-queue-bot` (700/600), привязка по коду |
| `setup-telegram.mjs` | разовая настройка: бот у @BotFather через Telegram Web и привязка владельца |
| `deploy/` | сервер: `run-server.sh`, seccomp-профиль Playwright; Mac: `install-launchd.sh` |

Тесты: `node --test test/*.test.mjs`.

## Конфиг (`config.json`)

`token` — токен Telegram; `queueToken` — токен очереди консоли с областью `owner` (`npm run oq -- token-create
queue-bot owner` на сервере консоли); `owners` — Telegram id владельца; `artifactUrl` — адрес очереди, по умолчанию
`https://ops.admin.hrhelper.space/queue`. Переменные окружения: `OQB_TOKEN`, `OQB_QUEUE_TOKEN`, `OQB_QUEUE_URL`,
`OQB_HOME`, `OQB_HEADLESS=1`, `OQB_CHANNEL` (`chromium` в контейнере, `chrome` на Mac), `OQB_WATCH_SEC`.

## На сервере

Отдельный контейнер `owner-queue-bot` вне стека HR Helper: в консоль он ходит по публичному адресу. Образ
— Node с одним Chromium, 1,43 ГБ. Внутри:
- песочница Chromium (seccomp-профиль Playwright v1.64.0 + `SYS_CHROOT`);
- остальные capabilities сняты, `no-new-privileges`, файловая система только для чтения, пользователь не root;
- лимит памяти 1 ГБ, куча Node 256 МБ (`--max-old-space-size`), 1 CPU, `--restart unless-stopped`. Раз в час бот
  открывает страницу в свежей вкладке: Playwright держит объекты запросов вкладки, пока она открыта, а страница
  опрашивает консоль раз в 4 с. При лимите 768 МБ и перезагрузке в той же вкладке раз в 6 ч контейнер за 28 ч дошёл
  до 767 МБ (19.10).

Шаги — в пункте очереди «Бот очереди на сервер»: `run-server.sh` собирает образ и запускает контейнер. До его
запуска бота на Mac нужно остановить (`bash deploy/install-launchd.sh --remove`): один токен Telegram
опрашивает только один процесс.

## Отказы

| Что случилось | Что делает бот |
|---|---|
| Консоль недоступна или токен отозван | Страница в режиме «local» или на входе. Бот сообщает владельцу и перезагружает страницу с нарастающей паузой (1–30 мин) |
| Страница зависла или упала | Потолок 45 с на операцию; браузер перезапускается перед следующей операцией |
| Процесс встал целиком | Сторож через 10 минут выходит из процесса, docker (на Mac — launchd) поднимает его заново |
| Пункт изменился, пока карточка висела в чате | Ответ и мёрж не выполняются; бот присылает свежую версию |
| В ветку PR допушили после показа · идёт деплой · PR закрыт | Консоль отказывает в мёрже с причиной; кнопки «Да» на экране подтверждения нет |
| Второй экземпляр бота | После 3 ответов 409 подряд — ожидание без уведомлений и запись в лог |
