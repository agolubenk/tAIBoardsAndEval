# llm-gateway — один вход в LLM для Continue и чата VS Code

Локальный OpenAI-совместимый шлюз `http://127.0.0.1:8789/v1`. Клиенты шлют запрос как обычно, а шлюз
перебирает ключи и модели трёх провайдеров: **OpenRouter** (ротация ключей и моделей, паузы, лимиты),
**GLM Z.AI** (ротация моделей Coding-подписки) и **локальную Ollama** (ротация по возможностям запроса,
строго по одной). Пул `cascade` проходит все три по очереди: провайдер с 3 отказами подряд
пропускается целиком. Ответ возвращается клиенту как есть, потоковый тоже. Зависимостей нет, нужен Node ≥ 20.

## Запуск

1. Впиши ключи и модели в `infra/llm-gateway/.env` **основной папки репо**. Файл gitignored, права 600;
   при первом `start` он создаётся из `.env.example`. OpenRouter: `OPENROUTER_KEY_n`, `OPENROUTER_MODELS_n`
   (точные id или глобы `*:free`, `deepseek/*`), `OPENROUTER_RPM_n`. GLM: `ZAI_CODING_KEY` (+ `GLM_MODELS_CODING`),
   опционально `ZAI_GENERAL_KEY` + `GLM_MODELS_GENERAL` (General-контур добавляется только с явным списком моделей).
2. Перезапусти шлюз и обнови клиентов: `npm run llm-gateway:restart && npm run llm-gateway:sync`.
3. VS Code: **Developer: Reload Window**. В выборе модели чата появится группа «HR Gateway».
   Continue: ассистент «HR Gateway — OpenRouter + GLM + локальные (ротация)».

`.env` и `.state/` всегда лежат в основной папке, даже если шлюз запущен из worktree: удаление worktree
ключи не сотрёт.

**Расширение OpenRouter for Copilot** (`abbalochdev.openrouter-copilot`) по умолчанию ходит в OpenRouter напрямую
своим ключом — мимо ротации, «только бесплатных» и потолка ответа (отсюда 402 «can only afford N» на платной модели).
Через шлюз: в настройках VS Code `"openrouter-for-copilot.baseUrl": "http://127.0.0.1:8789/v1"`, ключ расширения —
токен шлюза (`pbcopy < infra/llm-gateway/.state/token`, затем команда «OpenRouter: Set API Key»). Список моделей
расширение всё равно берёт из каталога OpenRouter: платный id шлюз заменит `:free`-вариантом или пулом `free`.
Пулы шлюза добавляются в `openrouter-for-copilot.customModels` объектами `{ "id": "cascade", "name": …, "maxInputTokens": 128000 }`.

## Модели

| Имя в клиенте | Что внутри |
|---|---|
| `auto` | точные модели всех OpenRouter-ключей по очереди; если ключам модели не заданы — топ бесплатных с tools из каталога |
| `free` | бесплатные текстовые модели (каталог OpenRouter обновляется раз в час) |
| `glm` | ротация моделей GLM Coding-подписки Z.AI (дефолт `glm-4.6,glm-4.7,glm-5,glm-5.2` — решение владельца 2026-10-29); каждая ступень доступна и отдельной моделью |
| `cascade` | OpenRouter (`auto`) → GLM (`glm`) → локальные (`local`); 3 отказа подряд провайдера — его остаток пропускается |
| `local` | локальные модели по возможностям запроса (vision-запрос — только vision-модели, tools — только с tools, длинные — только влезающие в окно), по кругу |
| `local/auto` | модель, которая уже загружена в Ollama, если запрос влезает в её окно; иначе `GW_LOCAL_DEFAULT` или первая подходящая |
| `local/code` `local/reason` `local/long` `local/fast` | тиры локальной ротации: явные списки `GW_LOCAL_*` или авто (code — `coder/tiel` в имени, reason — reasoning-имена, long — окно ≥ 64k, fast — до ~7 ГБ) |
| `local/<имя>` | конкретная модель Ollama; список определяется автоматически |
| `<alias>` | свой пул из `GW_ALIAS_<NAME>=a,b,local/c` |
| любой другой id | модель OpenRouter с этим id; за ней запасные из `free` (снятая или упёршаяся в лимит модель не роняет запрос, подмена видна в `x-gateway-model`; пауза выбранной до 10 с — шлюз ждёт её, а не подменяет). Платный id при `GW_OPENROUTER_FREE_ONLY=1` (по умолчанию) в OpenRouter не уходит: вместо него `:free`-вариант, если он есть, иначе пул `free` |

Автокомплит и эмбеддинги Continue идут не через шлюз, а прямо в Ollama: `tiel-coder-fim:latest` и
`nomic-embed-text:latest` (`GW_CONTINUE_AUTOCOMPLETE`/`GW_CONTINUE_EMBED`). FIM-эндпоинта `/completions` у Z.AI нет —
облачный GLM в роли autocomplete давал `HTTP 404 … api.z.ai/api/paas/v4/completions`. Шлюз запрос на
`/v1/completions` в GLM не отправляет и не подменяет локальной чатовой моделью (та вернула бы текст вместо
дополнения кода и на каждой паузе набора меняла бы модель в памяти Ollama): GLM-модель на этом пути — сразу 503 с причиной. FIM-модель (`fim` в имени или `num_predict` ≤ 256) в чатовые пулы не входит.
Прямой путь в Ollama обходит очередь шлюза: строгую последовательность для всех клиентов держит только сам Ollama
с `OLLAMA_MAX_LOADED_MODELS=1` (`infra/scripts/dev-ai/ollama-setup-models.sh`).

## Как работает ротация

- **Темп ключа.** Каждый ключ ограничен своим RPM (token bucket) и минимальным интервалом `GW_MIN_INTERVAL_MS`.
- **Ошибки ключа** (429, 402, 401, 403). Ключ уходит на паузу, тот же запрос повторяется с другим ключом.
  На 429 пауза растёт экспоненциально, а `Retry-After` от апстрима главнее. После исчерпания суточного
  лимита бесплатных моделей бесплатные модели ставятся на паузу для всего ключа. У Z.AI 429
  «Insufficient balance / no resource package» = исчерпано окно подписки: на паузу уходит весь ключ
  (перебор моделей ничего не даёт — правило 04).
- **Модель не тянет запрос** (404, «no endpoints», не хватает контекста или tools). Такая модель
  пропускается на 30 минут, запрос идёт на следующую модель пула.
- **Ошибка самого запроса** (обычный 400). Возвращается клиенту как есть, без ротации.
- **Только бесплатные и потолок ответа.** Платные модели OpenRouter отсекаются (`GW_OPENROUTER_FREE_ONLY`).
  `max_tokens` выше `GW_MAX_OUTPUT_TOKENS` (32 768) или максимума модели срезается: OpenRouter резервирует
  кредиты под весь запрошенный объём, и «до 131 072 токенов» давало 402 «can only afford N».
  `models[]` (свои запасные OpenRouter) в апстрим не уходит никогда — запасные выбирает шлюз; `plugins`
  (платный веб-поиск) — только при `GW_OPENROUTER_FREE_ONLY=0`.
- **Поток.** Ротация возможна только до первого `data:`; после этого клиент получает байты апстрима
  без изменений. Пока шлюз ждёт ключ, он шлёт клиенту SSE-комментарии, чтобы тот не оборвал соединение
  по таймауту.
- **Локальная модель.** Получает запрос только если он помещается в её окно. Окно — загруженное (`/api/ps`),
  иначе `num_ctx` из Modelfile (`/api/show`, только метаданные), иначе тег `:24k`, иначе обученное, но не больше
  `GW_LOCAL_MAX_CONTEXT` (32 768). Запросы к Ollama идут строго по одному. Модели без `thinking` в возможностях
  Ollama поля рассуждений (`reasoning_effort`, `reasoning`, `include_reasoning`) не передаются: Ollama отвечает на них
  400 «does not support thinking», а расширение OpenRouter for Copilot шлёт `reasoning_effort: max` в каждом запросе.
- **Каскад.** Провайдер (OpenRouter или GLM) с `GW_PROVIDER_SKIP_AFTER` отказами подряд в рамках
  одного запроса пропускается целиком — например, OpenRouter лежит: первая же модель GLM отвечает.

## Команды

`npm run llm-gateway:start|stop|restart|status|models|sync|logs` · проба `bash infra/llm-gateway/bin/llm-gateway.sh ask "текст" [модель]`
· журнал запросов `bash infra/llm-gateway/bin/llm-gateway.sh requests 20` · тесты `npm run llm-gateway:test`.

## Важно знать

- Лимиты OpenRouter считаются на аккаунт. Три ключа одного аккаунта ёмкость не утроят; утроят — ключи
  трёх разных аккаунтов.
- Подписка GLM Coding тарифицируется вызовом за окно, не токенами: ротация между `glm-4.6…5.2`
  не экономит квоту — она переживает отказы конкретной модели. Дешевле спрашивать одним вызовом.
- Бесплатные модели у части провайдеров могут логировать промпты. Это информация к сведению, шлюз ничего
  не блокирует.
- Безопасность. Шлюз слушает только loopback. Каждый запрос требует токен из `.state/token`; клиенты
  получают его через `sync`. Чужой `Host` отклоняется, это защита от DNS rebinding. Ключи OpenRouter
  и Z.AI в клиенты не попадают.
- `sync` перезаписывает только свою запись «HR Gateway» в `chatLanguageModels.json` и только строку
  `LLM_GATEWAY_TOKEN` в `.continue/.env`. Перед записью копирует оба файла в `.state/backups/`. Файл, который
  не изменился, не переписывается. Перезапись заставляет VS Code заново регистрировать модели, и выбранная модель
  слетает. Имена моделей постоянные, без счётчиков: Continue запоминает выбор по имени.
