Локальный контур бесплатен и безлимитен. Облако — конечный ресурс двух разных видов, и путать
их нельзя:

- **Z.AI (GLM Coding Lite)** — подписка. Деньги уже уплачены, тратится **квота промптов за
  окно**. Дорого не «много токенов», дорого — **много вызовов**. Один вызов на 20k токенов
  стоит столько же, сколько вызов на 200 токенов. Endpoint подписки — только
  `/api/coding/paas/v4`.
- **Z.AI General API** — второй биллинговый контур того же провайдера: `/api/paas/v4`,
  **отдельный ключ `ZAI_GENERAL_API_KEY` и отдельный кошелёк**, оплата по токенам. Модели те
  же, но здесь возвращается прежняя арифметика: длинный промпт стоит дороже короткого.
  В конфигах он последней моделью в списке («General API (платный)») и выбирается **руками**,
  когда окно подписки кончилось, а работа важнее экономии. Ключа нет в `.continue/.env` →
  модель просто не отвечает, остальные работают.
- **Gemini** — внешние лимиты частоты. Жёсткий потолок: **4 вызова за 2 минуты, 10 за 30 минут**
  (правило `gemini-rate-limits`).

## Порядок эскалации

1. **Локально** — Architect → Analyst → Executor → Reviewer. Дефолт для всего. Три локальные
   попытки не стоят ничего; одна облачная тратит квоту.
2. **Z.AI по лестнице моделей** — `glm-4.6` → `glm-4.7` → `glm-5` → `glm-5.2`. Вверх по
   лестнице только когда предыдущая ступень отработала и не справилась (правило
   `model-rotation`).
3. **Gemini** — не «фолбэк после трёх попыток», а специалист по невозможному локально: PDF,
   изображения, видео, UI-скриншоты, релевантный контекст за пределами локального окна,
   недоступность Z.AI.

## Когда облачный вызов разрешён

Все условия одновременно:

- существуют `brief.md`, `recon.md`, `hypotheses.md`, `evidence.md` в `.ai/task/<TASK-ID>/`;
- сформулирован ОДИН точный вопрос в `cloud-question.md`;
- и выполнено хотя бы одно: локальные модели дали два правдоподобных, но несовместимых
  объяснения · факты собраны, а причинная связь не восстановлена · решение имеет высокий blast
  radius (auth, RBAC, JWT, refresh token, HMAC/webhook, миграции БД, биллинг, конкурентность,
  массовое изменение или удаление данных) · нужно выбрать из двух патчей, оба проходят тесты,
  но имеют разные системные последствия.

Исключение из требования артефактов — vision/PDF/видео: там локальный контур неприменим в
принципе, идти к Gemini сразу.

## Когда запрещён

- Рутинная правка, рефакторинг, переименование, форматирование, boilerplate.
- «Локальная модель звучит неуверенно» — это интонация, а не факт.
- Автокомплит, эмбеддинги, индексация кодовой базы — никогда: они срабатывают на каждое
  нажатие клавиши и выжгут квоту за минуты. Это относится и к `glm-only.yaml`: там роли
  `embed`/`autocomplete` намеренно оставлены локальными, а не переведены на GLM.
- Три одинаковые перегенерации одной роли в надежде на лучший ответ. Если ответ не устроил,
  меняется вопрос, а не счётчик попыток.
- Фоновая обработка каждой задачи «чтобы качественнее».
- Дробление одного вопроса на пять сообщений: на подписке это пять списанных промптов вместо
  одного. Собирать полный контекст и спрашивать один раз.

## Что нельзя отправлять наружу

- Весь репозиторий, всю историю чата, файлы целиком «на всякий случай» — только отобранный
  evidence pack.
- Секреты, `.env`, токены, ключи, дампы БД, PII кандидатов и сотрудников.
- Логи с внутренними URL и токенами.

## Права

- У облачных моделей нет ролей `edit`/`apply` и не будет. Облако возвращает решение,
  аргументацию, риски и проверяемый следующий шаг. Патч применяет только
  «Qwen3 Coder 30B — Executor».
  **Единственное исключение — отдельный ассистент `.continue/agents/glm-only.yaml`**
  («HR Helper — GLM only»), где локального Executor нет вовсе: он выбирается вручную
  на время, когда локальный контур занят прогоном консилиума (модельный лок + 17–19 ГБ
  VRAM под L-моделью). Там право на патч тоже принадлежит ровно одной модели —
  GLM-4.7. В основном конфиге запрет остаётся в силе без оговорок.
- Облачная модель не закрывает задачу: пока есть blocker от `/code-review`, не прошли проверки
  или acceptance criteria не подтверждены evidence — задача открыта.

## Подтверждение инструментов — выключено, кроме пяти опасных действий (2026-10-30)

`permissions` в `.continue/config.yaml`: `allow: ["*"]` и `exclude` на пять действий — git push,
gh pr merge, ssh/scp на VPS, сетевые запросы наружу, чтение `.env*` (решение владельца
d-continue-allow-all = exclude-dangerous, 2026-10-30; было `allow: ["*"]` без исключений с 2026-08-18).
Прогон, который ждёт клика на каждом шаге, не агентский — поэтому остальное идёт без диалога.

Что из этого следует для расхода — прямо противоречит остальному этому файлу, поэтому
названо явно: **ручное подтверждение было единственным естественным тормозом на числе
вызовов**. Тарифицируется вызов, а не токены; авто-режим означает, что длинная задача
съест окно подписки за столько шагов, сколько агент решит сделать, и остановить его
между шагами теперь нечем. Потолки из `[models.cloud.budget]` консилиума сюда НЕ
распространяются — это разные процессы, общий у них только ключ и общая квота.

**Блок `permissions` сейчас не читает никто** (проверено по исходникам 2026-10-30): расширение
VS Code 2.1.0 держит политики инструментов в состоянии webview (иконка инструментов в тулбаре
ввода), а CLI `cn` берёт права из флагов и `~/.continue/permissions.yaml` — чтение из config.yaml
у него «when implemented», и на этой машине `cn` не установлен. В `cn` `exclude` — это запрет,
а не диалог: он проверяется раньше `allow`, первое совпадение выигрывает.

В IDE реально защищают встроенные проверки: терминальные `git push`, `gh`, ssh/scp/rsync,
curl/wget/nc спрашивают подтверждение и при «Automatic», файловые инструменты не открывают
`.env*`. Не закрыты: `fetch_url_content` (владелец выключает руками — иконка инструментов →
Excluded) и `cat .env` в терминале — на нём держится только правило «никогда» в
`00-continue-root.md`. Подробный разбор — комментарий над блоком в `config.yaml`.

## Тот же принцип в AI Council

У консилиума (`infra/ai-council/`) та же дисциплина, но принудительная, в коде: облако
выключено по умолчанию, лимиты вызовов за прогон и за окно в `[models.cloud.budget]`, лестница
моделей в `[models.cloud.roles]`, и облачный ответ принимается только если он объективно
подтверждённее локального. Текущий расход — `npm run ai-council:cloud`.

Второй контур там тоже не «фолбэк по умолчанию»: он включается ровно на `quota`/`no_balance`
(перегрузка и 5xx вторым кошельком не лечатся) и держится двумя явными потолками —
`max_calls_per_day` И `max_usd_per_day` в `[models.cloud.providers.zai.fallback]`; ноль в любом
из них = маршрут закрыт. У контура свой прайс (`…fallback.pricing`), потому что в общем прайсе
модели подписки стоят 0 — по нему платный вызов записался бы бесплатным. Модель без прайса на
платный маршрут не уходит вовсе. Связь по каждому контуру проверяется отдельно:
`npm run ai-council:cloud-ping` либо вкладка «Облако» → «Проверить связь».
