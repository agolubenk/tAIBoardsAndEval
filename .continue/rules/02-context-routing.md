Continue **не имеет** аналога хуков Claude Code (`UserPromptSubmit`/`PostToolUse`/`Stop`).
Всё, что там делает DAMS автоматически — здесь нужно вызывать сознательно. Не пытаться
"угадать" отсутствующий автоматический контекст — вместо этого явно тянуть нужное одним
из инструментов ниже.

## Контракт входа задачи

Для длинной/расплывчатой новой задачи соблюдать один и тот же маршрут, что в Claude Code и
Codex: **HEADROOM (сжать только большой входной контекст) → `/task-brief` GLM → Serena/DAMS
точечно → HEADROOM handoff**. Оригинальный текст пользователя не заменять brief-ом. Для коротких
задач не вызывать ни HEADROOM, ни GLM.

## Обязательная «прожарка» большой задачи

До правок для большой, неясной, кросс-доменной или видимой пользователю задачи дать короткий
разбор с фактами из кода: продуктовый сценарий и затронутые приложения/контракты; данные,
API/RPC, права, PII, интеграции; UI-kit (desktop/mobile, i18n, a11y, loading/empty/error);
ошибки, масштабирование, security, наблюдаемость и обратная совместимость; acceptance tests,
rollout и документы. Для неактуального пункта прямо указать причину. Материально меняющий
продукт выбор не угадывать — спросить пользователя до реализации.

## Порядок предпочтений (дешёвое → дорогое)

1. **Serena** (`mcp: serena`, тот же сервер, что и в Claude Code) — для навигации по коду:
   `find_symbol`, `get_symbols_overview`, `find_referencing_symbols` вместо чтения целых
   файлов. Особенно важно для локальных моделей — у них меньше контекстное окно, каждый
   лишний файл целиком дороже, чем для Claude.
2. **`@codebase`/`@file`** — только когда Serena не резолвит (конфиг, `.env*`, SQL, YAML,
   markdown, не-код).
3. **`headroom`** (`mcp: headroom`) — только для двух случаев, не для каждого запроса:
   - вход в длинную задачу с большим приложенным контекстом (лог, дамп, диф) —
     `headroom_compress` перед тем, как вставлять это в сообщение;
   - передача задачи между инстансами/сессиями (см. ниже "Handoff") —
     `headroom_retrieve` по id задачи в начале, `headroom_compress` в конце.
4. **`task_brief` MCP-инструмент** — структуризация задачи RU→EN (тот же механизм, что в Claude Code
   через DAMS хук). Вызывать для длинных/расплывчатых/русскоязычных формулировок ПЕРЕД тем,
   как переключиться на Executor модель (Qwen3 Coder 30B). Не на каждую реплику — только старт
   новой задачи. Возвращает компактный GOAL/CONSTRAINTS/ACCEPTANCE брифинг на английском,
   используется как дополнительный контекст рядом с исходным текстом. Алтернатива: slash-команда
   `/task-brief` (см. `.continue/config.yaml` → `prompts`), но инструмент предпочтительнее
   (явный вызов, не зависит от конфига).

## Персоны/специализация — не дублировать, ссылаться

Continue не читает `.claude/agents/*.md` напрямую (это Claude Code subagents с MCP-tool
ограничениями, которые Continue не воспроизводит). Если нужна "точка зрения" специалиста
(backend/frontend/security/telegram) — открыть соответствующий файл в `.claude/agents/`
как reference (`@.claude/agents/backend-expert.md` и т.п.) вместо повторного описания
той же экспертизы здесь. Обновлять экспертизу нужно в одном месте.

## Модель под задачу

Роли разведены намеренно, и одна из них — единственная с правом менять файлы:

| Задача | Модель | Права |
|---|---|---|
| Разбор задачи, execution path, риски | `Qwen 3.6 27B — Architect` | чтение |
| Независимое второе мнение, контрпримеры | `GLM4 Local — Analyst` | чтение |
| Быстрый разбор диффа, тестов, контракта | `Mistral Small 3.2 — Reviewer` | чтение |
| Правка кода, эксперименты, прогон проверок | `Tiel-Coder 35B-A3B — Executor` (local/tiel-coder:35b-a3b-iq3s) | **chat/edit/apply** |
| Рутинный облачный вопрос, структурирование | `GLM-4.6 — Cloud Routine` | чтение |
| Ревью диффа, разбор ошибки сборки | `GLM-4.7 — Cloud Coder` | чтение |
| Архитектура, противоречие, high blast radius | `GLM-5 — Cloud Architect` | чтение |
| Последняя инстанция | `GLM-5.2 — Cloud Judge` | чтение |
| PDF, скриншоты, видео, очень длинный контекст | `Gemini 3.6 Flash — Long Context / Vision` | чтение |

Строки Architect (`Qwen 3.6 27B`) и Reviewer (`Mistral Small 3.2`) ссылаются на модели,
удалённые с Mac 2026-10-23 (d-mac-models = drop-4) — до переработки таблицы их роли
закрывают облачные GLM-строки ниже. Executor обновлён 2026-10-28 на Tiel-Coder.

Analyst — это не «ещё один Qwen под другим промптом»: другая линейка означает другой корпус
и другие систематические ошибки, поэтому его несогласие информативно. Два прогона одной
модели независимым мнением не являются.

Когда облако разрешено — `03-cloud-budget.md`; лестница GLM и поведение при 429 —
`04-model-rotation.md`; частота Gemini — `05-gemini-rate-limits.md`.
Полный каталог моделей — проектный `.continue/config.yaml`, не дублировать здесь.

## Handoff между сессиями (если задача не влезла в одну сессию Continue)

DAMS в Claude Code пишет `.claude/memory/session/latest.md` автоматически на каждом Stop
— Continue может это ЧИТАТЬ (`@.claude/memory/session/latest.md`) в начале сессии, чтобы
понять, что уже сделано и что осталось (секция "Открытые задачи"), но не может писать
в этот файл сам (нет Stop-хука). Если ведёте отдельную от Claude Code задачу в Continue —
использовать `headroom_compress` с тем же принципом: снимок `{сделано, осталось, ключевые
файлы}` под стабильным id, читать через `headroom_retrieve` в следующей сессии.

## Не засорять контекст

- Не вставлять целиком большие логи/диффы в сообщение — `headroom_compress` или
  дать модели вызвать `Bash`/terminal-тул самой и прочитать только релевантный кусок.
- Не открывать файл целиком ради одной функции — Serena `find_symbol` возвращает тело
  символа точечно.
- Всегда загружен ровно один рул — `00-continue-root.md`. Остальные подтягиваются по `globs`
  (когда соответствующий файл в контексте) или по запросу модели: их имена и описания видны
  в списке доступных правил. Не возвращать `alwaysApply: true` другим файлам — у локальных
  моделей окно меньше, чем у облачных, и постоянный рул там дороже.
- Не добавлять сюда доменные детали (Telegram/recruiting/etc.) — за ними идти в
  `.claude/memory/chunks/` или `.claude/rules/*` по месту работы, не копировать в Continue.
