# Ротация внутри GLM Coding Lite

## Endpoint — только Coding Plan

```
https://api.z.ai/api/coding/paas/v4      ← рабочий, покрыт подпиской
https://api.z.ai/api/paas/v4             ← НЕ использовать: General API, pay-as-you-go
```

Проверено 2026-08-13 живыми запросами: на General API ключ отвечает `429 Insufficient balance
or no resource package` для всех моделей, на Coding — `200` для `glm-4.6`, `glm-4.7`, `glm-5`,
`glm-5.2`. Смешивать endpoint'ы нельзя: это два разных биллинговых контура на одном ключе.

`glm-4.7-flash` (бесплатная модель General API) в план подписки **не входит**: с ключом подписки
отвечает 429 (2026-08-13) — на нём «бесплатный ярус» не рассчитывать. Рабочий бесплатный контур —
**отдельный** ключ General API (правило `cloud-budget`) на `/api/paas/v4`: `glm-4.7-flash` отвечает
200 OK (проверено 2026-10-29). В Continue это секрет `ZAI_GENERAL_API_KEY`, в шлюзе — переменная
`ZAI_GENERAL_KEY` в `infra/llm-gateway/.env`. Платные модели этого контура тратят реальные деньги
за токены — только руками.

## Ротация через HR Gateway (шлюз)

Пул `glm` локального шлюза (`infra/llm-gateway`, `127.0.0.1:8789`) крутит все четыре ступени
по кругу — решение владельца 2026-10-29: ротация переживает отказ конкретной модели (перегруз
1305 и т.п.), а не экономит квоту. Правила «вверх по лестнице только с обоснованием» это
заменяет для запросов через шлюз; прямой вызов API (консилиум, скрипты) — лестница ниже как есть.
Пул `cascade` проходит OpenRouter → GLM → локальные; провайдер с 3 отказами подряд пропускается.
Модели из `GLM_MODELS_GENERAL` шлюз тоже кладёт в пулы `glm` и `cascade`. Модель, которая есть и в
`GLM_MODELS_CODING`, раздаётся по кругу на оба ключа (`keypool.mjs`, `acquire`), и часть запросов
уходит в платный кошелёк. Поэтому в `GLM_MODELS_GENERAL` — только модели вне подписки (`glm-4.7-flash`).

## Единица расхода — промпт, а не токен

Подписка тратится числом обращений за скользящее окно, а не объёмом. Отсюда два следствия,
которые важнее любых микрооптимизаций промпта:

- **Один вопрос — один вызов.** Собрать весь контекст и спросить один раз дороже по токенам,
  но дешевле по квоте, чем пять уточняющих сообщений.
- **Большой контекст не наказывается.** Не резать evidence pack ради экономии, если он реально
  нужен для ответа — режется только лишнее (см. что нельзя отправлять наружу).

## Лестница

| Ступень | Модель | Когда |
|---|---|---|
| 1 | `glm-4.6` | рутинный облачный вопрос: структурировать постановку, разобрать неоднозначность, объяснить чужой код |
| 2 | `glm-4.7` | дефолт для кода: ревью диффа, разбор ошибки сборки/теста, выбор из двух подходов |
| 3 | `glm-5` | архитектурное решение, противоречие между локальными мнениями, high blast radius |
| 4 | `glm-5.2` | последняя инстанция: ступень 3 отработала и не дала проверяемого ответа |

Вверх по лестнице — **только с обоснованием**: прежде чем брать следующую ступень, назвать,
чего конкретно не хватило в ответе предыдущей. «Возьму сразу самую сильную» — запрещено:
на подписке это тратит ту же квоту, но лишает дешёвого шага, который часто закрывает вопрос.

Вниз по лестнице — свободно. Если задача оказалась проще, чем казалась, следующий вопрос идёт
на `glm-4.6`.

## Поведение при 429

`429` от Coding endpoint означает одно из двух, и различать их нужно по тексту:

| Текст | Смысл | Что делать |
|---|---|---|
| `service may be temporarily overloaded` | перегрузка модели | 1 повтор с задержкой 2–5 с; не помогло — соседняя ступень лестницы |
| `Insufficient balance / no resource package` | обращение ушло на General API | это ошибка конфига, а не квоты — проверить `apiBase` |
| исчерпание окна плана | квота окна кончилась | **облако на паузу**, доработать локально; не долбить повторами |

Общее правило: `429` — не повод перебрать все четыре модели подряд. Максимум одна соседняя
ступень, дальше локальный контур. Перебор моделей на исчерпанном окне не даёт ничего, кроме
задержки.

## Квота окна

Точное число промптов за окно смотреть в кабинете Z.AI — оно зависит от тарифа и меняется;
в конфиге консилиума оно задаётся руками (`[models.cloud.budget] max_calls_per_window`,
`window_hours`) и по умолчанию занижено. Занижение намеренное: упереться в собственный
консервативный потолок безопаснее, чем в потолок провайдера посреди задачи.

Проверить расход: `npm run ai-council:cloud`.
