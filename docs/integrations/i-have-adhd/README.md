## Что это

**Скилл формата ответа для ИИ-ассистентов кода и плагин-обёртки вокруг него.** Это не CLI и не сервис. Он задаёт
форму ответа: сначала следующее действие, шаги нумеруются, состояние повторяется каждый ход, побочные темы
отсекаются, без вступлений и концовок (`README.md`). Название и ссылки на ADHD — про читателя с малой рабочей
памятью. Диагностики или медицинской части нет: скилл сам это оговаривает, кейс `medical-boundary` в
`evals/cases.jsonl`.

**Лицензия — MIT** (`LICENSE`: «Copyright (c) 2026 Ayoub Ghriss»; `license: MIT` во frontmatter `SKILL.md` и в
`package.json`). Версия плагина — 0.4.1 (`.claude-plugin/plugin.json`).

## На что ложится в tAIBE

Внимание одного владельца над многими сессиями — реальное ограничение (`docs/specs/owner-queue.md`: решения,
мёржи, серверные команды, проверки). Скилл бьёт в это место. Вторая точка, неожиданная, — замерный стенд для
пайплайна.

| Что | Часть tAIBE | Что уже есть (проверено) | Что добавляет |

## Проверка «усиливает, а не заменяет»

Проверка для A (сразу) и C2 (отдельной карточкой).

- [x] Не заменяет часть продукта и не дублирует её — дополняет: формат пунктов очереди и протокол handoff остаются, меняется только форма текста. Стенд закрывает пустое место §3.1.
- [ ] После внедрения метрика лучше, чем до: замер «до» (медиана ответа по `oq_events`) не снят. В замере источника гейт провален — переносить его цифры на tAIBE нельзя.
- [x] Инвариант «снаружи ничего не меняется» (PR, карточки, очередь владельца, бот, «мёрж = деплой») не нарушен: поля и API очереди те же.
- [x] Лицензия совместима с выбранным вариантом: MIT, вендоринг допустим с текстом лицензии рядом и строкой в `README.md` (Origins).
- [x] Ресурсы: A — сотни токенов в описании инструмента. Always-on (B) отклонён из-за ~1,7K в каждой сессии. Отказ стенда (C2) команду не останавливает: это офлайн-замер.
- [ ] Данные: для C2 кейсы из реальных карточек уйдут в API модели-судьи. Нужна чистка секретов как в R-036 и сегментация по продуктам (R-002). Не спроектировано.

## Риски и открытые вопросы

- **Конфликт с DoD и проверкой.** Правила 9 («≤ 5 пунктов») и 10 («без резюме») режут отчёт, который требует корневой
  `CLAUDE.md`. Оговорка «харнесс сильнее» (правило 6) это снимает, но только если её сохранить в патче.
- **Правило 8 и выдумывание причины.** Регрессия `partial-success` в замере источника — прямой риск для команды, где
  «не проверено» обязательно. Не брать без замены на «причина — если доказана, иначе гипотеза и проверка».
- **Сокращение текста для агентов.** Агент-наследник получает контекст из капсулы. Ужатые сообщения между сессиями
  могут терять факты. Применять только к адресованному владельцу.
- **Язык.** Правила и замер — английские, владелец пишет по-русски. Эффект на RU не проверен.
- **Качество замера источника.** Судья из той же семьи моделей, 3 прогона, 14 кейсов, один кейс непроходим
  (`agent-owned-edit`). Цифра +0.427 — ориентир, не доказательство.
- Активность репозитория (число коммитов, авторов, issues) не проверял: клон `--depth 1`.

## Вердикт и рекомендация

**Брать идею (💡).** Скилл как есть и always-on не брать: конфликт с DoD, правило 8, ~1,7K токенов на сессию.
Принципы 1, 3, 5, 6, 9 вписать в протокол пунктов очереди и в раздел действий владельца `successor-handoff`
(вариант A) после замера «до». Самое ценное для tAIBE — **замерный стенд** (C2: парный слепой судья, веса, гейт,
изоляция, потолок бюджета). Это кандидат на вендоринг в `eval/pipeline/` отдельной карточкой с «да» владельца:
он даёт команду замера, которой у пайплайна нет. Карточки разбора и внедрения в tAI-Boards из этой сессии не
заведены: нет доступа к MCP досок.

Адверсариальная проверка. Три линзы прогнал автор разбора. Независимый консилиум не запускался — нужен до
карточки в работу.
- **Корректность и отказы.** Возражение: краткость прячет риск. Решение: разрушительные действия и «не проверено»
  остаются полными (исключение 2 источника + наш DoD), правило 8 исключено.
- **Ресурсы.** Возражение: always-on стоит ~1,7K токенов на каждой сессии. Отклонено. A стоит сотни токенов в одном
  описании инструмента. Стенд — офлайн и с потолком `--max-budget-usd`.
- **Продукт и простота.** Возражение: в очереди уже есть «рекомендую первым», выигрыш может быть нулевым («на прежнем
  уровне» = отказ). Решение: внедрение закрывается только по замеру медианы ответа владельца. Нет улучшения —
  откат абзаца.
