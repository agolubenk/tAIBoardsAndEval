# cognee — разбор встраивания

> **Статус (2026-11-01):** 🔍 разобран (2026-11-01). Источник — [topoteretes/cognee](https://github.com/topoteretes/cognee),
> прочитан коммит `525b1d1` (2026-10-29, версия пакета `1.6.6`). Индекс и правила — [`../README.md`](../README.md).

## Что это

Python-библиотека и сервер «памяти для агентов»: документы, код и диалоги превращаются в граф знаний + векторный
индекс + реляционный каталог, агенты достают контекст через поиск по графу и векторам. Пути ниже — в репозитории
источника на `525b1d1`.

- **Ядро — четыре глагола** `remember` / `recall` / `improve` / `forget` (`README.md`, раздел «How Cognee works»;
  код — `cognee/api/v1/`). Под ними старые `add` / `cognify` / `search` / `prune`. `cognify` — конвейер задач
  (`cognee/api/v1/cognify/cognify.py`, ~стр. 700–800): классификация документов → чанки → извлечение графа и
  сводок LLM-ом (`cognee/tasks/graph/extract_graph_and_summarize.py`) → запись точек данных и эмбеддингов →
  provenance. Без ключа LLM граф извлекает локальная модель GLiNER; сами авторы называют это демо
  («For a production-ready version … reach out to us», `README.md`).
- **Поиск** — ~30 ретриверов в `cognee/modules/retrieval/`: гибридный (`hybrid_retriever.py` + `hybrid/`),
  графовые completion/CoT/decomposition, temporal, BM25, код (`code_retriever.py`), скиллы
  (`skills_retriever.py`), правила кодинга (`coding_rules_retriever.py`, 40 строк, по сути выборка узлов
  `coding_agent_rules`).
- **Дистилляция сессий** (`cognee/modules/session_distillation/distill.py`, 732 строки; `models.py`): LOAD
  (записи контекста сессии после watermark) → CURATE (один LLM-вызов на пачку ≤ 16 000 символов, ≤ 6 блоков) →
  ACCEPT (на каждый предложенный урок — поиск ≤ 5 похожих уроков и ≤ 20 сущностей глоссария, затем LLM
  «писатель/отклонитель» с причиной `already_known | not_durable | unsupported`) → PERSIST (урок как документ,
  снова `cognify`). Вход отбирается по оценкам `helpful`/`harmful` с порогом уверенности 0.75
  (`cognee/infrastructure/session/session_context_models.py:6,17`). Промпты —
  `cognee/infrastructure/llm/prompts/session_distillation_{curator,writer}_system.txt`.
- **Скиллы с прогрессивным раскрытием:** поиск отдаёт только метаданные (имя, описание, версия, теги, scope), тело
  грузится отдельным вызовом `load_skill` (`skills_retriever.py`, `_project_skill_payload`).
- **MCP-сервер** `cognee-mcp/src/server.py`: инструменты `remember`, `recall`, `code_search`, `forget`, `improve`,
  `cognify_status`. Плагин Claude Code — в отдельном репозитории `topoteretes/cognee-integrations` (не проверено,
  не клонировали).
- **Стек и хранение:** Python 3.10–3.14; по умолчанию SQLite (`relational/config.py:22`) + LanceDB
  (`vector/config.py:32`) + Ladybug (граф, `graph/config.py:47`); опционально Postgres+pgvector, Neo4j, Neptune.
  ~60 прямых зависимостей в `pyproject.toml` (litellm, instructor, fastapi, lancedb+pylance, onnxruntime,
  fastembed, pandas, dlt, rdflib …). `cognee/` — ~530 тыс. строк Python вместе с тестами.
- **Postgres как граф** — «demo feature. The production-ready version is available as a licensed product»
  (`README.md`, «Run the Whole Memory Layer on Postgres»). Единственный вариант «всё в одном Postgres», близкий
  к стеку tAIBE, официально демо.
- **Телеметрия включена по умолчанию:** `send_telemetry` шлёт события на `https://test.prometh.ai`
  (`cognee/shared/utils.py:23,592`) с `user_id`, `tenant_id`, анонимными id и хэшем API-ключа; выключается
  `TELEMETRY_DISABLED` или `ENV=test|dev`.
- **Ресурсы:** в `docker-compose.yml` лимиты API — 4 CPU / 8 GB (стр. 64–65), MCP — 2 CPU / 4 GB (стр. 126–127).
  Это лимиты, а не замер потребления; реальный RSS — не проверено.
- **Зрелость:** `Development Status :: 4 - Beta`; релизы v1.6.0 (2026-09-18) и v1.6.1 (2026-09-24) по `README.md`.
  Звёзды и активность — не проверено (клон `--depth 1`).
- **Лицензия:** Apache License 2.0 (`LICENSE`; `pyproject.toml`: `license = "Apache-2.0"`), `NOTICE.md` —
  Topoteretes UG. Совместима с MIT-частями tAIBE и для вендоринга: нужно сохранить LICENSE и NOTICE, пометить
  изменения.

## На что ложится в tAIBE

| Часть tAIBE | Что уже есть | Что даёт cognee | Пересечение |
|---|---|---|---|
| Блокнот `boards/apps/api/src/notebook` (R-050–R-053) | чанки (`chunk/chunk-markdown.ts`), tsvector+GIN, векторы с Mac (`embed/embed-queue.ts`), RRF k=60 (`search/fuse-ranks.ts`), чат со ссылками | граф сущностей поверх чанков, ~30 стратегий поиска | **дублирует**: второе хранилище и второй поиск по тем же источникам |
| Семена → уроки (`docs/plans/evolution-ideas.md` §2.7, мост 2.6) | идея, кода нет | готовый дизайн дистилляции: куратор → писатель/отклонитель с причиной → проверка новизны → watermark | **дополняет**: ровно недостающий механизм |
| «Один факт — одно место» (§2.2) | ручные чанки DAMS `.claude/memory/chunks`, справочный граф `.claude/memory/graph.json` | отказ `already_known` после поиска похожих уроков | дополняет как приём |
| `library_resolve(card, budget)` (§2.3), статистика скиллов (R-061), SSR `boards/apps/api/src/ssr` | реестр версий скиллов/правил, обрезка описаний в геноме | поиск по метаданным скиллов, тело — по запросу | идея совпадает с уже принятой; кода брать нечего |
| claude-mem reader `boards/packages/claude-mem-reader`, R-043 | чтение наблюдений, привязка к карточкам, план сжатия 92 дня / 9 месяцев | ретенции и сжатия по времени нет | не ложится |
| eval (stdlib Python), DAMS RAG `.claude/scripts/rag_query.py` | офлайн-поиск по индексу | — | ставить cognee в eval запрещено правилом stdlib-only |

Улучшаемая метрика — качество, а не токены: доля повторных ошибок и повторных вопросов между сессиями, число дублей
в хабе. Прямого снижения $/PR или первого вызова (≤ 55K) cognee не даёт: его выход — дополнительный контекст.
`cognify` вызывает LLM на каждую пачку чанков, а это расходует лимит R-053 (0–10 000 облачных вызовов в сутки) и
противоречит правилу «компилятор контекста LLM не вызывает» (`boards/docs/t-boards-spec.md`, R-043).

|---|---|---|---|---|

| C — вендоринг части кода | два промпта `session_distillation_{curator,writer}_system.txt` и схемы `ProposedLesson` / `WrittenLesson` (`models.py`), переложенные на TS/Zod | модуль варианта A | Apache-2.0: LICENSE + NOTICE рядом, изменения помечены, строка в Origins; промпты англоязычные, их нужно адаптировать под RU-карточки | тот же замер, что у A; выигрыш против A — только время на первую версию промпта |

## Проверка «усиливает, а не заменяет»

- [x] Не заменяет часть продукта и не дублирует её — дополняет. Только A/C: дистилляции в tAIBE нет. B дублирует блокнот — отклонён.
- [ ] После внедрения метрика лучше, чем до: замер «до» записан, замер «после» — в приёмке. Замера «до» нет: уроков пока нет, повторы ошибок по claude-mem не считались.
- [x] Инвариант «снаружи ничего не меняется» (PR, карточки, очередь владельца, бот, «мёрж = деплой») не нарушен. A — внутренний модуль досок.
- [x] Лицензия совместима с выбранным вариантом. Apache-2.0 → MIT допустимо при сохранении NOTICE.
- [x] Ресурсы: сервер, сеть, машина владельца; отказ инструмента не останавливает команду. Для A: дистилляция идёт фоновой очередью, при сбое LLM уроки просто не появляются. Для B — нет: +4–8 GB лимита, новый сервис.
- [ ] Данные: секреты, PII и сегментация по продуктам не утекают. Для A уроки собираются из сессий и карточек и уходят в GLM. Нужен скан секретов перед вызовом: сейчас `scanSecrets` (`boards/apps/api/src/ssr/secret-scan.ts`) вызывается только в SSR (`ssr/sync.ts:64`), в `notebook/` его вызова не найдено. Сегментация по продуктам — уроки в области сектора/продукта.

## Риски и открытые вопросы

- **Утечка данных (B):** телеметрия включена по умолчанию (`cognee/shared/utils.py`); `cognify` отправляет
  чанки внешней LLM; хэш API-ключа уходит в телеметрию. Для кода и карточек с PII это неприемлемо без
  `TELEMETRY_DISABLED` и локальной модели.
- **Коммерческая граница:** граф в Postgres — демо, «production-ready … licensed product». Значит, сервис из B
  пришлось бы держать на SQLite/LanceDB/Ladybug вне Postgres досок, отдельно бэкапить и закладывать в RPO ≤ 2 ч.
- **Поддержка:** зависимости с жёсткими пинами (lancedb↔pylance, transformers<5 для GLiNER — комментарии в
  `pyproject.toml`), Beta-статус; обновления будут ломать сервис.
- **Качество дистилляции на русском** и на коротких записях claude-mem — не проверено; промпты источника
  англоязычные.
- **Откуда брать оценки полезности:** у cognee их ставит его же сессионный слой (`helpful`/`harmful`). В tAIBE
  аналога нет; первым кандидатом выглядит статистика R-061 и исход карточки (принята / переделка) — это нужно
  решить до A.
- Плагин Claude Code и TypeScript SDK (`docs.cognee.ai/typescript`) не проверены.

## Вердикт и рекомендация

**Брать идею (вариант A, при желании — C только для промптов).** cognee — тяжёлая Python-платформа с собственным
трёхкомпонентным хранилищем. Поиск и хранение в tAIBE уже закрывает блокнот на Postgres, и вариант B его
продублировал бы, оставив продукт «на прежнем уровне» при большей сложности и рисках телеметрии и egress.
Ценность — в дизайне дистилляции `session_distillation/`: куратор → писатель/отклонитель с типизированной
причиной → проверка новизны по уже накопленному → watermark. Это готовая схема для «семена → уроки» (§2.7) и
моста блокнот → хаб (§2.6), и она прямо поддерживает «один факт — одно место» через `already_known`. Идея
прогрессивного раскрытия скиллов в tAIBE уже принята (§2.3), брать оттуда нечего.

Условия приёмки A: замер «до» на 2–3 секторах (повторные ошибки и вопросы, дубли), скан секретов перед LLM и
решение по сигналу полезности. При вендоринге промптов — атрибуция в разборе, в доке модуля и в корневом
`README.md` (Origins).

Адверсариальная проверка: три линзы (корректность/отказы · ресурсы сервер→сеть→устройство · продукт/простота)
применены автором разбора; это самопроверка, а не независимая проверка. Её должен провести консилиум, до неё
решение не выбрано. Карточка tAI-Boards по разбору — не заведена (из этой сессии нет доступа к MCP досок).
