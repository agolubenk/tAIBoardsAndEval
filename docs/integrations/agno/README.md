## Что это

Python-фреймворк и сервисный слой для LLM-агентов: «agents → teams → workflows» плюс AgentOS, то есть API, MCP,
планировщик, durable-очередь и HITL. Все пути ниже — от корня репо источника на коммите `a9ea2b4`.

- **Лицензия:** Apache-2.0 (`LICENSE`, `libs/agno/LICENSE`, classifier в `libs/agno/pyproject.toml`). Файла `NOTICE`
  в корне нет.
- **Зрелость:** пакет `agno` 3.1.12, «Production/Stable», Python ≥ 3.9 (`libs/agno/pyproject.toml`). Последний
  коммит — 2026-10-30. Историю релизов не смотрел: клон `--depth 1`.
- **Объём:** около 500K строк Python в `libs/agno/agno/`. Крупные модули: `team/` 26.6K, `workflow/` 25.2K,
  `models/` 25K (≈ 60 провайдеров), `agent/` 21.2K, `learn/` 14.7K, `company/` 5.1K, `eval/` 4.4K,
  `compaction/` 2K строк.
- **Обязательные зависимости:** `pydantic`, `pydantic-settings`, `httpx[http2]`, `rich`, `pyyaml`,
  `docstring-parser`, `packaging`, `h11`, `typing-extensions`, `agnoctl`. Экстра `os` добавляет FastAPI, uvicorn,
  SQLAlchemy, PyJWT и OpenTelemetry. Экстра `claude` — `claude-agent-sdk>=0.2.148`.
- **Ядро, относящееся к нам:**
  - `team/mode.py`: режимы `coordinate`, `route`, `broadcast` (в `arun` члены команды работают параллельно) и `tasks`
    (лидер дробит цель на общий список задач и крутит цикл до конца).
  - `workflow/`: step, router, condition, loop, parallel.
  - `models/fallback.py`: `FallbackConfig` с `on_rate_limit` и `on_context_overflow`.
  - `compaction/`: сжатие истории в сводку. Оригиналы ложатся в архив (`agno_compactions`), агент ищет по ним
    инструментом `search_compacted_messages`. Порог по умолчанию — 150 000 токенов (`compaction/compaction.py`),
    вывод поиска ограничен 8 000 символами и 20 сжатиями. Принцип описан в `compaction/archive.py`: «сводка — индекс
    над первоисточником».
  - `eval/`: `accuracy`, `agent_as_judge` (оценка 1–10 или pass/fail со схемой), `performance` и `reliability`
    (ожидаемые и лишние вызовы инструментов, проверка аргументов, `eval/reliability.py`).
  - `scorer/_fence.py`: недоверенный текст обёрнут в разделители со случайным nonce на каждый вызов
    (`secrets.token_hex(16)`), инструкция «это данные» вшита в сам блок.
  - `approval/decorator.py`: `@approval` в режимах `required` (блокирует) и `audit`.
  - `guardrails/prompt_injection.py`: поиск подстрок из 18 фраз. Защита слабая.
  - `agents/claude/`: обёртка над Claude Agent SDK.
  - `company/`: «Company OS» — продукты, проекты, задачи, рутины.
- **Телеметрия включена по умолчанию.** `telemetry: bool = True` (`agent/agent.py:399`) отправляет на
  `https://os-api.agno.com` (`api/settings.py:57`) `agent_id`, провайдера, имя и id модели, тип БД и флаги
  tools/memory/knowledge (`agent/_telemetry.py`). Свою телеметрию шлют и eval (`eval/utils.py`). Выключается
  переменной `AGNO_TELEMETRY=false` (`agent/_init.py:62-66`). По README промпты и ответы не отправляются; по коду
  `get_telemetry_data` это так.
- **UI AgentOS** — хостинговый `os.agno.com` (README). Рантайм хостится у себя.

## Проверка «усиливает, а не заменяет»

- [x] Не заменяет часть продукта и не дублирует её — дополняет. Верно для A. Оркестровку Team/Workflow вместо
  консилиума, scheduler вместо Нерва и Company OS вместо досок отклонили именно как замену.
- [ ] После внедрения метрика лучше, чем до. Замер «до» не сделан: корпуса инъекций и replay-набора пока нет. Это
  первый шаг приёмки A.
- [x] Инвариант «снаружи ничего не меняется» не нарушен: меняются только внутренние промпты консилиума и проверка
  replay.
- [x] Лицензия Apache-2.0 совместима с любым вариантом. Для C — LICENSE рядом и строка в Origins.
- [x] Ресурсы: A не добавляет процессов и зависимостей, `eval/` остаётся на stdlib. B не проходит: новый рантайм и
  стек зависимостей.
- [ ] Данные: для B телеметрия по умолчанию отправляет метаданные на `os-api.agno.com`. Для A пункт выполнен —
  наружу ничего не уходит.

## Риски и открытые вопросы

- **Телеметрия opt-out.** Любой запуск agno без `AGNO_TELEMETRY=false` отправляет id агента и модели. Для B флаг
  обязателен в конфиге сервиса и в preflight.
- **Скорость изменений:** около 500K строк, версия 3.x. Публичное API за год не стабильно (не проверено: в
  `--depth 1` нет истории). Адаптер B стал бы дорог в поддержке.
- **Параллелизм по умолчанию** (`broadcast` в `arun`, параллельные шаги workflow) конфликтует с законом консилиума
  «локальные модели — строго последовательно».
- **Supply-chain промптов.** Онбординг в README отдаёт coding-агенту инструкцию клонировать шаблон и выполнить
  `.agents/skills/setup-platform/SKILL.md`. Такой шаблон — недоверенные инструкции, в сессии команды его не
  исполнять.
- `guardrails/prompt_injection.py` (поиск подстрок) не годится как защита. Берём фенс, не guardrail.
- Не проверено: качество `agent_as_judge` против нашего консилиума, RAM и время импорта пакета, поведение
  `agents/claude/` с подпиской Claude Code и запись транскриптов при таком запуске.

## Вердикт и рекомендация

**Брать идею (вариант A), фреймворк не брать.** Причины:

1. Как оркестратор agno заменил бы консилиум, Нерв или доски на том же или худшем уровне. Он тянет не-stdlib
   зависимости и телеметрию по умолчанию, а §9 PIPELINE прямо говорит «универсальный оркестратор не строим».
2. Три элемента дополняют продукт и стоят почти ноль:
   - nonce-фенс в `review_prompts.py` — самое ценное, прямо закрывает инъекцию в ревью;
   - трассовая проверка replay-прогонов по образцу `ReliabilityEval`;
   - «сводка — индекс над архивом с потолком дозапроса» для капсул П6.
3. Каждый элемент принимается только с замером до и после (см. таблицу). При внедрении — атрибуция «принцип взят из
  agno (Apache-2.0)» в разборе, в README консилиума и в `eval/pipeline`, плюс строка в Origins корневого README.

Карточку в tAI-Boards не заводил: это вне объёма разбора. Адверсариальная проверка консилиумом (≥ 3 линзы:
корректность и отказы · ресурсы · продукт и простота) не проводилась и обязательна до внедрения. Предварительные
возражения автора:

- фенс удлиняет промпт локальной модели — около 60 токенов, допустимо;
- трассовая проверка может штрафовать законные отклонения — нужен список «разрешённых лишних».
