## Что это

Веб-система управления проектами для людей: портфели, work packages, Гант, Scrum/Kanban, учёт времени и бюджета,
wiki, встречи (`README.md`). Стек: Rails `~> 8.1.3` (`Gemfile:42`), Ruby 4.0.9 (`.ruby-version`), Angular 22 + Hotwire
(`frontend/package.json`), PostgreSQL ≥ 16 с `pg_trgm`, `btree_gist`, `unaccent`. Версия в
`lib/open_project/version.rb` — 18.0.0. Релизные теги и частоту релизов не проверял (клон `--depth 1`).

**Лицензия — GPLv3, без «or later»:** `COPYRIGHT`, `COPYRIGHT_short` и заголовки файлов (например `app/models/relation.rb`)
говорят «GNU General Public License version 3». Унаследованный код ChiliProject/Redmine — GPLv2-or-later. `LICENSE` —
полный текст GPLv3. Это не AGPL. Часть возможностей в том же коде закрыта `EnterpriseToken.allows_to?`: baseline
дальше «вчера» (`app/models/timestamp.rb:108`), встроенный MCP-сервер (`lib/api/mcp.rb:46`).

## На что ложится в tAIBE

Здесь усиливается модель леса в tAI-Boards: целостность деревьев, свёртка и «что изменилось». Планирование по датам
не нужно: агентам важен порядок работ, а не календарь.

| Идея из OpenProject | Часть tAIBE | Что есть сейчас (проверено) | Пробел |
|---|---|---|---|
| Правила допустимости связи | `boards/apps/api/src/task-relation/controllers/create-task-relation.ts` | При записи отсекается только связь задачи с собой и дубль *того же* типа (`:25`, `:90-110`). Чтения леса терпят циклы через лимит глубины 20 и `UNION`, родителем считается самая старая связь `subtask` (`forest/tree/card-place.ts:9-11`, `get-tree.ts:20`, `list-trees.ts:19`) | Цикл `subtask`, второй родитель, пара «subtask + blocks» записываются без отказа. От корректного дерева зависят вырубка (R-028) и секторы (R-029, `forest/sector/detect-sectors.ts:38` идёт по `blocks/related`) |
| Готовность по блокерам (порядок без дат) | аренда `forest/lease`, «Пульс» (R-090), Нерв | Есть тип `blocks`, производного «готово к взятию» нет | Агент может арендовать карточку, у которой не закрыты блокеры. Нерв не знает, что карточка разблокировалась |
| Свёртка вверх по дереву | `card_meta` (`database/forest-schema.ts:335`: `tokens`, `costUsd`, `files`), контекст-пакет корня, «Пульс» | Поля на каждую карточку, суммы по дереву нет | «Сколько стоило дерево и сколько веток закрыто» — это N чтений вместо одного поля |
| Baseline на уровне набора | `card_history` (`forest-schema.ts:391`, `changes` jsonb, `kind task/meta`), `since` в MCP (R-031), идея 1.3 в `openproject:docs/plans/evolution-ideas.md` | Есть дифф карточки и «изменилось с T». ## Проверка «усиливает, а не заменяет»

Проверка для рекомендованного варианта A.

- [x] Не заменяет часть продукта и не дублирует её — дополняет: правила и производные поля ложатся на `task_relation`, `card_meta` и `card_history`, ничего не удаляется.
- [ ] После внедрения метрика лучше, чем до: замер «до» не записан. Способы замера — в таблице вариантов; без них внедрение не закрывается.
- [x] Инвариант «снаружи ничего не меняется» (PR, карточки, очередь владельца, бот, «мёрж = деплой») не нарушен. Новое — отказ 400/409 на недопустимую связь. Ответ должен сразу говорить, что делать дальше (идея 1.4).
- [x] Лицензия совместима с выбранным вариантом: берём только идеи, кода GPL нет. Атрибуция — здесь, в спеке досок и в корневом `README.md` (Origins), когда идея войдёт в код.
- [x] Ресурсы: нового сервиса нет, один CTE на запись связи. Отказ проверки — обычная ошибка API, команда не встаёт.

## Риски и открытые вопросы

- **Дрейф продукта.** OpenProject строит менеджер проектов для людей: даты, часы, Гант, ресурсы. Если взять
  планирование целиком, tAI-Boards поедет в сторону MS Project, а это противоречит «агенты первыми» и отсрочке
  таймлайна (R-090). Поэтому берём порядок (`blocks` → готовность), а даты и `lag` не берём.
- **Правило «одна связь на пару» — продуктовая развилка.** В tAIBE пара `subtask` + `blocks` сейчас допустима.
  Запрещать ли её и что делать с уже записанными парами — решает владелец.
- **Существующие нарушения.** Сколько циклов и вторых родителей уже лежит в данных — не проверено (доступа к БД нет).
  Чистка — правка данных на проде, только с «да».
- **Baseline по `card_history`.** Все ли пути записи (колонка, статус, приоритет kaneo, импорт, зеркало Notion)
  попадают в `card_history` — не проверено. Без этого «как было на T» соберётся с дырами.
- **Свёртка `costUsd`/`tokens`.** Кто пишет производное поле: сервер (триггер или воркер), не агент. Иначе под арендой
  будут гонки (R-026).
- **Документация OpenProject описывает Enterprise.** Baseline с диапазонами и MCP в Community нет. Ссылаясь на
  поведение, проверять код, а не доки.
- Записи импортёров (`packages/importers`) в `task_relation` на циклы не проверял.

## Вердикт и рекомендация

**Брать идею (💡), вариант A. B и C не брать.** Ценность — в правилах целостности графа, а не в продукте целиком:
OpenProject как сервис тяжелее всего ядра досок в 4+ раза и решает задачу людей с датами. Код GPLv3 в MIT-часть
не войдёт.

Порядок, если владелец скажет «да»: (1) правила допустимости связи при записи — дёшево, закрывает пробел, от
которого зависят R-028/R-029. (2) Готовность по блокерам в аренде и контексте. (3) Baseline набора для «Пульса» и
сектора. (4) Свёртка по дереву. (5) Статус вехи `locked` — при сверке R-020. Отсутствие проверки цикла и второго
родителя при записи (`create-task-relation.ts`) — завести карточкой в «Ошибки» tAI-Boards. Из этой сессии карточка
не заведена: нет доступа к MCP досок.

Адверсариальная проверка вердикта. Три линзы прогнал автор разбора. Независимый консилиум не запускался — это
нужно сделать до карточки в работу.
- **Корректность и отказы.** Возражение: строгие правила сломают импорт из Notion и Jira с «грязными» связями.
  Решение: импортёр пишет нарушения в отчёт прогона, а не падает. Правило — только для новых записей.
- **Ресурсы.** Возражение: CTE на каждую вставку связи. Ответ: глубина ≤ 20, вставки связей редки. Сервис
  OpenProject (≥ 4 GB) отклонён.
- **Продукт и простота.** Возражение: 6 пар типов OpenProject усложнят MCP-ответы. Решение: типы не берём,
  оставляем `subtask/blocks/related`, берём только правила.
