## Что это

- **Назначение.** Локальный MCP-сервер «знаний о коде»: индексирует репозиторий в граф (узлы `Function`, `Route`,
  `Resource`, `EnvVar`…, рёбра `CALLS`, `IMPORTS`, `HTTP_CALLS`, `DEPLOYS`, `CONFIGURES`…) и отдаёт агенту точечные
  запросы вместо чтения файлов (`README.md`, разделы «Features», «Graph Data Model»). Генеративная модель серверу не
  нужна — «интеллект» остаётся в клиенте (`README.md`, «How It Works»).
- **Ядро.** Чистый C, один бинарник: `src/pipeline/` (многопроходная индексация), `src/store/` (SQLite: граф,
  FTS5/BM25, Louvain), `src/cypher/` (read-only подмножество openCypher), `src/mcp/` (17 инструментов, JSON-RPC),
  `src/daemon/` (общий демон на учётную запись), `src/watcher/` (авто-переиндексация). Парсинг — 162 вендоренные
  грамматики tree-sitter (`internal/cbm/vendored/grammars/MANIFEST.md`) плюс «Hybrid LSP» — собственная C-реализация
  разрешения типов для Python, TS/JS, Go, Java, Rust и др. без процесса language server (`README.md`, «Hybrid LSP»).
  Семантический поиск — встроенные int8-векторы `nomic-embed-code` (`THIRD_PARTY.md`, Apache-2.0).
- **Инструменты MCP** (`src/mcp/mcp.c`, таблица `TOOL_ANNOTATIONS`): `search_graph`, `trace_path`, `query_graph`,
  `get_code_snippet`, `get_file_outline`, `get_architecture`, `detect_changes` (diff → затронутые символы и «радиус
  поражения»), `check_index_coverage`, `search_code`, `manage_adr`, `ingest_traces` и служебные. Три
  (`search_graph`, `trace_path`, `get_code_snippet`) помечены `_meta["anthropic/alwaysLoad"]` — грузятся в первый
  вызов мимо ToolSearch, ≈ 4,6K символов (комментарий `src/mcp/mcp.c:903–908`).
- **Экономный вывод — сильная сторона дизайна** (`README.md`, «CLI Mode»): компактное дерево по умолчанию, таблицы
  `<section>_refs` с общими префиксами путей (включаются, только если ответ короче ≥ 15 %), усечение по целым
  строкам с `has_more` и курсором, `max_output_tokens` с жёстким потолком 4 байта/токен.
- **Установщик** (`src/cli/`) пишет конфиг в 45 клиентов; для Claude Code — `~/.claude.json`, скилл, три агента
  Scout/Verify/Auditor и fail-open хуки `SessionStart`, `SubagentStart`, `PreToolUse` на `Grep|Glob|Bash`,
  `PostToolUse` на `Read` (`README.md`, «Multi-Agent Support»). Есть `--skip-config` — только бинарник.
- **Сеть.** Индексация и запросы офлайн. Демон по умолчанию в сеть не ходит: продовый провайдер проверки обновлений
  удалён намеренно (`src/daemon/application.c:70–82`); сеть — только явный `update`/установщик (GitHub Releases) и
  опциональная модель чата CBM Lens с Hugging Face.
- **Зрелость.** Версия 0.x, тегов до `v0.12.1` (`git ls-remote --tags`); `src/` ≈ 281K строк C. Подписи cosign, SLSA 3,
  CodeQL (`README.md`, «Security»). Звёзды, частота релизов, число мейнтейнеров — **не проверено** (GitHub API из
  сессии недоступен).
- **Заявленный эффект.** «10× меньше токенов и 2,1× меньше вызовов инструментов» против пофайлового обхода — из
  препринта авторов arXiv 2603.27277 (`README.md`, «Performance»); на наших репо **не проверено**. Методика замера —
  `codebase-memory-mcp/docs/MEASURING_SAVINGS.md` (замороженный SHA, два чистых worktree, одинаковые вопросы и бюджет).
- **Лицензия.** MIT, `Copyright (c) 2025 DeusData` (`LICENSE`). Вендоренное — MIT / CC0-1.0 / Apache-2.0 / ISC /
  BSD-3-Clause (zstd выбран BSD) — `THIRD_PARTY.md`. Копилефта в поставке не найдено.

## На что ложится в tAIBE

- **Разведка кода (`.claude/agents/scout.md`)** — сейчас Serena + Grep, бюджет ~8 вызовов. `search_graph` →
  `trace_path` → `get_code_snippet` закрывают тот же вопрос («точки входа, ключевые символы, поток данных») за
  меньшее число вызовов и без чтения файлов целиком. Метрика — токены задачи навигации, хвост `результат:Read/Bash`
  (П9 в `eval/pipeline/PIPELINE.md`: $93.5 + $20.7 в Т2).
- **Serena в MCP-хабе (`infra/mcp-hub/README.md`)** — ~2 ГБ RAM на копию, переиндексация на каждый worktree,
  `start` до минуты. CBM — один демон на учётную запись для всех клиентов (Claude Code, Codex, Continue — те же, что у
  зеркал `.agents/`, `.continue/`), с watcher'ом. Метрика — RSS, время старта; RAM CBM на наших репо **не замерена**.
- **Граф консилиума (`infra/ai-council/graph_build.py`, `graph_index.py`)** — сейчас graphify code-only (AST без LLM,
  сообщества под номерами) ради «что ещё сломается». `detect_changes` даёт это напрямую: diff → символы → риск, плюс
  `scope: "tests"`. Метрика — доля дефектов ревью, найденных консилиумом (калибровка линз, `evolution-ideas.md` §3.3).
- **Первый вызов (П1, геномы `eval/pipeline/genome/*.json`)** — подключение добавляет ≈ 4,6K символов (~1,2–1,5K
  токенов, оценка) за три alwaysLoad-схемы; остальные 14 — отложенные. Это расход, не экономия: окупается только
  через меньшие хвосты чтения.
- **MCP tAI-Boards и DAMS-RAG** — принцип компактных ответов (`_refs`, курсоры, бюджет вывода) применим к нашим
  MCP-ответам независимо от внедрения самого сервера.

## Проверка «усиливает, а не заменяет»

Отмечено для рекомендованного пути (A сразу, B — пилот с замером).

- [x] Не заменяет часть продукта и не дублирует её — дополняет: Serena (правки по символам, LSP-переименование) и
  graphify остаются до замера; CBM добавляет межфайловые/инфраструктурные связи и `detect_changes`, которых у Serena
  нет. Пересечение по поиску символов — частичное и осознанное; решение «что уходит» — только после замера.
- [ ] После внедрения метрика лучше, чем до: замера «до» нет — сначала золотой набор на Serena+Grep, затем CBM.
- [x] Инвариант «снаружи ничего не меняется» не нарушен: только чтение кода, PR/карточки/очередь не затрагиваются.
- [x] Лицензия совместима: MIT для A, B и даже C; атрибуция обязательна при A (дизайн вывода) — в доке MCP досок и в
  корневом `README.md`.
- [ ] Ресурсы: RAM индексации на монорепо HR_Helper-v2 не замерена; отказ демона = нет инструментов CBM, Serena и
  Grep остаются (fail-open хуки мы не ставим) — это закрыто, но пункт целиком не отмечен до замера RAM.
- [ ] Данные: код не покидает машину (проверено по `src/daemon/application.c:70–82`), но индекс общий на учётную
  запись — разные `CBM_CACHE_DIR` одновременно запрещены (`README.md`, «Session Coordination Daemon»), сегментация по
  продуктам только по имени проекта; файлы `.env` индексируются как язык DOTENV (`src/discover/language.c:103`) и
  исключаются лишь через `.gitignore`/`.cbmignore` — нужен явный `.cbmignore` (`.env*`, `*.pem`, дампы).

## Риски и открытые вопросы

- **Установщик меняет глобальный слой.** Полный `install` пишет в `~/.claude.json`, добавляет хуки на
  `Grep|Glob|Bash|Read` и три агента — это в обход геномов П1 и хуков `.claude/hooks/` (вопрос 6 в
  `evolution-ideas.md` §5: подмешивание `additionalContext` «не туда»). Только `--skip-config` и ручной `.mcp.json`.
- **Обновление = остановка всех CBM-сессий.** Все процессы обязаны быть одной сборки; активация отменяет работу и
  ждёт выхода (`README.md`, «Session Coordination Daemon»). Для долгоживущих сессий команды — только в окно ротации.
- **Worktree.** Каждый worktree — отдельный индекс (поддерживается, `README.md`, «Auto-Index»); стоимость N индексов
  по RAM/диску не замерена. Командный артефакт `.codebase-memory/graph.db.zst` раздувает историю git (пример авторов —
  ~6 ГБ за ~350 коммитов) — не включать.
- **Точность графа.** TS/Python — ярус «Good (75–89 %)» по бенчмарку авторов (`README.md`, «Language Support»); пропуск
  ребра не означает отсутствие связи — агент обязан сверять `check_index_coverage` и исходник.
- **PIPELINE §9 «не строим графовую БД».** CBM — внешний локальный SQLite-инструмент, а не наша БД; но владелец должен
  подтвердить, что это не противоречит решению.
- **Молодой проект (0.x), очень высокий темп изменений** — интерфейсы инструментов могут меняться; пин версии.
- Открыто: RSS индексации и покоя на HR_Helper-v2; реальные токены на наших задачах; совместимость с
  `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH=600` (длинные описания будут урезаны — влияние на качество не проверено).

## Вердикт и рекомендация

**Брать идею сразу (A) и вернуться к адаптеру (B) пилотом с замером.** Почему: MIT, локально, без сети, бьёт ровно в
наш рычаг (хвосты чтения, навигация, «что ещё сломается» для консилиума) и даёт то, чего нет у Serena и graphify
(`detect_changes`, связи код ↔ инфраструктура). Но заявленные «10×» — цифра авторов; RAM на нашем монорепо и цена
первого вызова не измерены, а полный установщик ломает дисциплину геномов. Порядок: (1) золотой набор навигации на
Serena+Grep — замер «до»; (2) CBM в `.mcp.json` только для `scout` и консилиума, `--skip-config`, `.cbmignore`,
`CBM_MEM_BUDGET_MB`; (3) приёмка — ≥ 30 % меньше токенов на задачу при той же точности `file:line`, первый вызов
≤ 55K, RSS ниже Serena. Не прошло — остаётся только A.

Карточка tAI-Boards — не заведена (доски недоступны из этой сессии), завести «Разбор: codebase-memory-mcp — пилот B».
Адверсариальная проверка консилиумом (≥ 3 линзы) — **не проведена**; ниже только предварительные возражения автора:
корректность — граф неполон, нужен `check_index_coverage`; ресурсы — RAM индексации и +1,5K токенов первого вызова
не замерены; продукт/простота — второй навигатор рядом с Serena усложняет слой, оправдан только замером.
