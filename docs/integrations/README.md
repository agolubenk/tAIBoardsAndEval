# Аналитика встраивания внешних решений

> **Статус (2026-11-01):** первая волна — 8 инструментов разобрано по коду источников (коммиты — в разборах);
> взято: идея OpenProject (циклы связей), идеи i-have-adhd и agno (судья A/B и nonce-фенсы, `eval/evolve/`). Сводка
> вариантов и предложений — ниже, подробный разбор — в папке инструмента. Адверсариальная проверка разборов — пока
> только авторская (по три линзы в каждом файле); прогон линз консилиума — следующий шаг.

## Главный принцип

Внешнее решение встраивается, только если **усиливает и дополняет** tAIBE — делает его эффективнее (токены,
контекст, время владельца, простои) или качественнее (ревью, память, поиск, планирование). Не встраиваем то, что
заменяет часть продукта, ухудшает её или оставляет на прежнем уровне. «На прежнем уровне» — тоже отказ: сложность
выросла, ценности нет.

Приёмка предложения:

1. **Замер до и после** по метрике продукта (≤ $20/PR, средний контекст ≤ 120K, первый вызов ≤ 55K, «прочитать
   задачу и начать» на 55–75 % дешевле Notion, RPO ≤ 2 ч, ноль простоев без ведома владельца) или по метрике
   качества с командой замера. Без замера «после» внедрение не закрывается.
2. **Инвариант** «снаружи ничего не меняется»: PR, карточки, очередь владельца, бот, «мёрж = деплой».
3. **Отказоустойчивость:** отказ инструмента не останавливает команду и не теряет состояние (задача живёт вне
   окна модели, корректность детерминирована — контракты ContextFlow, `boards/docs/architecture-overview2.0.md`).
4. **Лицензия** совместима с вариантом: идея/принцип — всегда; адаптер — по условиям API; вендоринг кода — только
   совместимые с MIT лицензии (GPL/AGPL — только как отдельный сервис или идея).
5. **Адверсариальная проверка** ≥ 3 линз (`.claude/memory/chunks/process/adversarial-review.md`).

## Атрибуция — обязательна

Если взято ядро, базовые возможности, дизайн или принципы внешнего решения, оно упоминается:

- в разборе инструмента (вердикт «взято»: что именно и куда);
- в документации той части продукта, куда встроено (README/спека рядом с кодом);
- в корневом [`README.md`](../../README.md), раздел «Origins, forks & licenses» — строкой «что взято → где».

Вендоренный код — с лицензией источника рядом (как `eval/context/supertick-src/LICENSE`).

## Варианты и предложения

Сводка первой волны. Ни один инструмент не ставится целиком: каждый либо дублирует часть продукта (память, блокнот,
консилиум, harness), либо тяжёл для VPS, либо несовместим по лицензии. Ценность — в конкретных механизмах, которые
усиливают уже существующие части. Порядок — по отдаче на цену; у каждого предложения — замер «до/после».

| # | Предложение | Откуда | Куда в tAIBE | Замер | Цена |
|---|---|---|---|---|---|
| 1 | Целостность графа связей при записи: без циклов ✅ (E6); один родитель и запрет связей «предок–потомок» — решение владельца (E7) | [openproject](openproject/README.md) (идея) | `boards/apps/api/src/task-relation/` | нарушений в данных до/после (запрос по `task_relation`); тесты | часы |
| 2 | Шаблоны секретов в `@kaneo/redact` (вендоринг шаблонов, MIT, с атрибуцией) | [ai-memory](ai-memory/README.md) | `boards/packages/redact`, блокнот (E5), журнал MCP | доля секретов из тестового набора, которые проходят вычистку | часы |
| 3 | Разделители недоверенного текста со случайным nonce — ✅ судья `eval/evolve/ab.py`; 🔲 консилиум, блокнот | [agno](agno/README.md) (идея) | `infra/ai-council/review_prompts.py`, `notebook/chat/build-prompt.ts` | набор инъекций в источниках: доля, на которые модель среагировала, до/после | часы |
| 4 | «Инструкция ≠ граница прав»: каждый Never-запрет закрепить хуком или `deny` в геноме | [oh-my-openagent](oh-my-openagent/README.md) (принцип) | `.claude/rules` ↔ `.claude/hooks`, `eval/pipeline/genome/roles.json` | число правил без проверки; нарушения в транскриптах до/после | 1–2 дня |
| 5 | Слепое A/B-сравнение версий скилла/промпта судьёй — ✅ стенд `eval/evolve/ab.py` (перестановка сторон, отбор «качество, потом токены»); 🔲 замер согласия судьи с владельцем | [i-have-adhd](i-have-adhd/README.md) | `eval/pipeline/` — фитнес-функция эволюции промптов (`docs/plans/evolution-ideas.md` §3.1) | согласие судьи с владельцем на размеченной выборке | 1–2 дня, «да» владельца |
| 6 | Пилот: граф кода по MCP (`detect_changes`, вывод курсором) против Serena | [codebase-memory-mcp](codebase-memory-mcp/README.md) | `scout`, консилиум (`infra/ai-council`), хаб `infra/mcp-hub` | токены и время на 10 задач навигации, RAM | день, замер |
| 7 | Дистилляция сессий: куратор → писатель/отклонитель (`already_known`), проверка новизны, watermark | [cognee](cognee/README.md) (дизайн) | семена → уроки, хаб (`evolution-ideas.md` §2.7), ночная консолидация | доля дублей среди уроков; ручная оценка владельцем | 2–3 дня |
| 8 | Пункты очереди владельца: действие первым, один следующий шаг, без пересказа | [i-have-adhd](i-have-adhd/README.md) (принципы 1/3/5) | протокол `oq_*` (`docs/specs/owner-queue.md`), скилл `successor-handoff` | время владельца на пункт, переспросы | часы |

Не берём сейчас: warp (AGPL, не улучшает метрик), фреймворк agno, сервисы cognee и ai-memory, OpenProject как сервис,
harness oh-my-openagent. Пересечение по памяти (cognee, ai-memory, claude-mem): канон остаётся claude-mem + блокнот,
из внешних берём только механизмы 2 и 7.

## Как добавить инструмент

1. Папка `docs/integrations/<имя-репозитория>/` с `README.md` по шаблону [`_template.md`](_template.md).
2. Строка в реестре выше, статус 🔲.
3. Карточка в tAI-Boards (задача разбора) — статус и обсуждение живут там, здесь — результат.
