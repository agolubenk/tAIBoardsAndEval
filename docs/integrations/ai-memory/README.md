# ai-memory — разбор встраивания

> **Статус (2026-11-01):** 🔍 разобран (2026-11-01). Источник — [akitaonrails/ai-memory](https://github.com/akitaonrails/ai-memory),
> прочитан коммит `1c50622` (2026-10-31, workspace-версия `3.3.1`). Индекс и правила — [`../README.md`](../README.md).

## Что это

Долгая память для агентов-кодеров. Один бинарник на Rust: хуки жизненного цикла молча собирают наблюдения, сервер
сводит их в markdown-вики, следующая сессия в любом харнессе получает ограниченный бриф и поиск, межагентные
handoff передаются явно. Пути ниже — в репозитории источника на `1c50622`.

- **Конвейер** capture → consolidate → recall → handoff (`README.md`, «How it works»;
  `ai-memory:docs/ARCHITECTURE.md`). По умолчанию работает без LLM: захват, поиск и handoff обходятся без ключа (`README.md`).
- **Хранение** (`ai-memory:docs/ARCHITECTURE.md`, «Storage architecture»): источник правды — git-вики из `.md` (`git2`, коммит
  на каждую консолидацию). `memory.sqlite` (WAL, один писатель, пул читателей ≤ 4) — производный индекс, его
  можно пересобрать из файлов. Векторы — упакованные строки в SQLite и brute-force cosine, `sqlite-vec` отложен
  сознательно (`ai-memory:docs/vector-backend-policy.md`). Локальный эмбеддер `all-MiniLM-L6-v2` опционален.
- **Поиск** `memory_query`: RRF по потокам FTS5 + сущности + соседи по ссылкам + (опц.) векторы + поток
  наблюдений, затем ограниченная поправка «авторитета» страницы. `explain=true` отдаёт ранги и время каждого
  потока (`ai-memory:docs/ARCHITECTURE.md`, «MCP tool surface (25 tools)»).
- **Старение без LLM:** тиры working / episodic / semantic / procedural. Формула decay учитывает salience, давность
  и частоту доступа; использование замедляет забывание (таблица «Memory tiers»). Опциональный **A2 tier-down**
  сжимает холодную эпизодическую страницу до L0 `abstract`, L1 первого абзаца и L2 набора keep-токенов (пути, URL,
  код, коды ошибок, идентификаторы, regex), полная версия остаётся в git и цепочке supersession. Ничего не
  удаляется жёстко (`ai-memory:docs/design-memory-aging.md`).
- **Обратная связь:** `page_feedback` (`helpful / not_helpful / stale / wrong` по версии страницы) → производная
  `pages.salience`. `page_evidence` — «уверенность» по числу независимых сессий-подтверждений, по умолчанию на
  ранжирование не влияет.
- **Бриф на старте сессии:** бюджет в байтах `BRIEF_BUDGET_DEFAULT = 4_000`
  (`crates/ai-memory-hooks/src/router.rs:3091`, границы 1 500–20 000). С 3.1 тиры L0/L1/L2 заменили жадную
  обрезку хвоста (`ai-memory:docs/design-tiered-session-brief.md`).
- **Санитайзер секретов** `crates/ai-memory-core/src/sanitize.rs` (1 694 строки): типизированная граница
  `Sanitized<T>` (без скраба в хранилище не записать), PEM/PGP-блоки, ключи Anthropic/OpenAI/OpenRouter, Stripe,
  все префиксы GitHub, Google, Slack, AWS, Telegram-боты, креды в URL, общий шаблон `*_(KEY|TOKEN|SECRET|PASSWORD…)=`,
  расширение и allowlist по конфигу.
- **Учёт токенов** — таблицы `session_usage` (V91) и `token_calls` / `token_call_tools` (V92–V94): счётчики
  input/output/cache на сессию, ответ и инструмент, без содержимого.
- **Handoff и почта агентов:** `handoffs` (open / accepted / expired), `agent_messages` — claim-once через
  compare-and-set.
- **Замеры** — собственный харнесс `evals/`, LongMemEval-S, 470 вопросов
  (`ai-memory:docs/benchmarks/longmemeval-s-3.3.0-release.md`). FTS-only: hit@1 0.857, hit@5 0.951, p50 11 мс. С локальными
  эмбеддингами: hit@1 0.762, hit@5 0.945, p50 141 мс. Средний контекст ≈ 535 токенов. Цифры авторские, на Ryzen 9
  7950X3D; не воспроизводили.
- **Дизайн «продвижение памяти в правила»** (`ai-memory:docs/design-rules-promotion.md`) — предложение, не реализовано.
  Главный довод — бюджет AGENTS.md около 100 строк инструкций, раздувание снижает послушание. Сноска: цифры там из
  внешних источников, не проверены.
- **Стек и зрелость:** Rust edition 2024, toolchain 1.95+; 11 крейтов в `crates/`, ~556 тыс. строк `.rs` с тестами
  (`router.rs` один — 26 561 строка). Релизы частые: 3.2.9 (10-27), 3.2.10 и 3.3.0 (10-29), 3.3.1 (11-01)
  (`CHANGELOG.md`). Телеметрии нет: «does not phone home» (`DATA_HANDLING.md:10–13`). RSS сервера — не проверено,
  в compose лимитов памяти нет. Звёзды — не проверено.
- **Лицензия:** MIT, «Copyright (c) 2026 Fabio Akita» (`LICENSE`; `Cargo.toml`: `license = "MIT"`). Вендоринг
  в MIT-части tAIBE допустим с сохранением копирайта.

## Проверка «усиливает, а не заменяет»

- [x] Не заменяет часть продукта и не дублирует её — дополняет. Только A и C; вариант B заменял бы claude-mem и отклонён.
- [ ] После внедрения метрика лучше, чем до: замер «до» записан, замер «после» — в приёмке. «До» не снят: нет медианы капсулы, A/B keyword/hybrid, числа срабатываний скана на корпусе блокнота.
- [x] Инвариант «снаружи ничего не меняется» (PR, карточки, очередь владельца, бот, «мёрж = деплой») не нарушен. A и C — внутренние модули досок.
- [x] Лицензия совместима с выбранным вариантом. MIT → MIT, с сохранением копирайта.
- [x] Ресурсы: сервер, сеть, машина владельца; отказ инструмента не останавливает команду. A/C без нового сервиса и LLM; скан — чистые regex.
- [ ] Данные: секреты, PII и сегментация по продуктам не утекают. C закрывает только секреты. PII (имена кандидатов host-проекта) шаблонами не ловится, это отдельная задача. Сегментация не затронута.

## Риски и открытые вопросы

- **Пробел в tAIBE (находка разбора):** в `boards/apps/api/src/notebook` нет вызова скана секретов перед LLM
  (чат через GLM/OpenRouter, R-052) и перед отправкой текста Mac-воркеру. Проверено только grep по
  `secret|redact|scanSecrets`. Нужна карточка в «Ошибки»; из этой сессии она не заведена.
- **Ложные срабатывания** широкого шаблона `*_(KEY|TOKEN|SECRET…)=value` на доках и правилах: SSR отклоняет
  версию целиком (`ssr/sync.ts`). Для SSR нужен режим «предупредить», для LLM-пути — «вырезать».
- **Перенос цифр:** LongMemEval-S — диалоговая память на английском. Вывод «FTS не хуже векторов» для русских
  карточек и docs не переносится, его даёт только свой замер (вариант A-4).
- **Темп релизов** (4 версии за 5 дней) — при вендоринге фиксировать коммит, не следить за веткой.
- **Обратная связь (A-3)** требует миграции схемы — это решение владельца (`boards/apps/api/drizzle/`).
- RSS сервера, работа на слабом VPS и качество LLM-консолидации — не проверены.

## Вердикт и рекомендация

**Брать идею (A) + вендоринг шаблонов санитайзера (C); сервис (B) — не брать.** Как продукт ai-memory —
альтернатива claude-mem и частично доскам (handoff, учёт токенов). Встраивание целиком заменило бы источник R-040
и добавило 25 MCP-описаний в старт, а это против принципа и цели ≤ 55K. Ценность — в инженерных приёмах с
измеримым эффектом.

Порядок по отдаче:
1. Санитайзер перед LLM-путями блокнота (C) — закрывает реальный пробел egress, это дёшево.
2. Упаковка капсулы и `library_resolve` по тирам L0/L1/L2 — бьёт в первый вызов и размер капсулы.
3. Извлекающая проверка keep-токенов для R-043 — детерминированная гарантия «сводка не потеряла идентификаторы».
4. A/B keyword против hybrid в блокноте — решает, оправдан ли Mac-воркер на запросе.

При вендоринге — атрибуция в разборе, в доке модуля и в корневом `README.md` (Origins).

Адверсариальная проверка: три линзы (корректность/отказы · ресурсы сервер→сеть→устройство · продукт/простота)
применены автором разбора; это самопроверка, а не независимая проверка. Её должен провести консилиум, до неё
решение не выбрано. Карточка tAI-Boards по разбору — не заведена (из этой сессии нет доступа к MCP досок).
