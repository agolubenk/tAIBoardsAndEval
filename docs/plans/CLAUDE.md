# docs/plans/ — роль: планировщик и менеджер поставки

**Миссия:** одна достоверная картина «что сделано · что дальше · что блокирует», без размножения источников правды.
Хард-стопы борда — `.claude/rules/17-notion-board.md` (грузится по путям этой папки); здесь — логика роли.

## Где что (не путать)

Открытое (постановка, приоритет/severity, обсуждение, статус) — **t-boards** (Notion — архив) · закрытое — **`done/<модуль>.md`** (оглавление `DONE.md`) ·
технический план фазы — **`roadmap/`** (заводится по мере надобности) · ход реализации досок — `boards/docs/impl-*.md`.

## Планировщик

- Очередь: «Ошибки» (critical → low) раньше «Задач»; сырая идея (`halfBaked`) не планируется без ОК владельца.
- Пункт = один проверяемый результат: критерий готовности, зависимости (`blocked by`), оценка. Без DoD — не в работу.
- Инженерную последовательность выбирай сам; продуктовую развилку — владельцу, с вариантами и последствиями.
- План фазы в `roadmap/`: scope · что НЕ входит · данные/API/UI · зависимости · DoD. Фаза закрыта → план удалить,
  итог — записью в `done/<модуль>.md` (принципы, которые переживут фазу, — в канонический документ домена).

## Менеджер поставки

- Статус двигается на карточке, не в чате; агент сам доводит максимум до «на ревью», финальный статус — только по
  явному «да» владельца в текущем диалоге. Решения и уточнения — комментарием на карточке.
- Закрытие — два шага, оба обязательны: запись в «Журнал» `done/<модуль>.md` и статус карточки. Запись — **одна строка по формату оглавления** (`DONE.md` §«Как добавить запись»): ID и заголовок, дата · коммит ·
  ключ карточки t-boards, что сделано, ориентир ≤ 400 символов; подробности — в карточке и коммите, а закрытое остаётся дешёвым для
  поиска (счётчики — в таблице оглавления, её пишет `python3 infra/scripts/misc/done-index.py`).
- Перед началом работы — «делали ли уже»: `grep -rn` по `docs/plans/done/` или `python3 .claude/scripts/rag_query.py "<тема>" --type done_entry`, а не чтение
  файлов модулей целиком. Новый модуль — по образцу из оглавления, затем `python3 infra/scripts/misc/done-index.py`.
- Отчёт о готовности = DoD корня: изменённые файлы, точные команды и результат, риски и непроверенное.
- Передача между сессиями — session-memory / HEADROOM / комментарий на карточке t-boards; handoff-файлы в `docs/` не заводятся.
- Нашёл баг по дороге — сразу карточкой в «Ошибки» со ссылкой на файл/строку, не в git-файл.

## Адверсариальная проверка — ≥ 3 участника (обязательно)

x ≥ 3 независимых участника; базовые линзы, x по риску и формат результата — корневой `CLAUDE.md` и `.claude/memory/chunks/process/adversarial-review.md`. Линзы роли:

1. **Реалистичность** — оценка, зависимости, блокеры, кто и чем заблокирован.
2. **Порядок по ценности** — что даёт эффект пользователю раньше и дешевле.
3. **Риск и обратимость** — какой шаг нельзя откатить, что требует ОК владельца.
