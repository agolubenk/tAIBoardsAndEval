## 1. Что показывают данные (а не предложения кластеризатора)

**42 новых предложения — не дефекты, а темы.** Паттерны вида «Проблемы с качеством решений и проработкой задачи»
(hits 77), «Система ушла не туда / не выполнена задача» (6 строк с разными наборами мишеней), «Поиск продуктового
развития» (название карточки), «Проблемы с DAMS RAG…» (тема карточки), #106/#107 — в pattern записан список мишеней.
Причины: локальный кластеризатор (qwen2.5/glm4) не держит правило «кластер — дефект, не тема»; `target` — свободная
строка (мульти-мишени «p.code, p.arch, critic…» делают дедуп по мишени бесполезным); кластеризатор не видит, ЧЕМ
закончился прогон. 65 применённых предложений уже раздули промпты (правила 9–12 в каждом), а дефекты повторяются —
промпт перестал быть рычагом.

**Механика, которую нашли замеры:**
- *Модель не видит постановку.* `council.context.pinned_tokens = 600`: на постановку+обсуждение остаётся ~940
  символов; обрезано **126 из 150** карточек (медиана текста 2 730 симв., p90 14 516). Реальный промпт —
  3 072 токена (медиана), max 4 210 из `num_ctx = 8192`: запас ~4 000 токенов не используется.
- *Время уходит в очередь локального слота, а не в модель.* `local_inference_slot` ждёт до 300 с, вызов — до 300 с,
  1 ретрай, у proposer.arch 2 сэмпла → «вызов» до 40 мин (замер: glm4-предложение 1 979 с). Таймаут слота
  записывается как отказ модели. Дедлайн карточки (900 с) истекает до рецензий → у предложений 0.0/15 →
  «лучшая оценка 0.0» (13 прогонов). Это инфраструктура, но владелец получает её как воздержание консилиума.
- *Fast — две модели.* proposer.code = qwen2.5:7b, proposer.arch = glm4, арбитр = glm4 (сам сливает своё
  предложение). Ворота расхождения считают max по ОДНОЙ паре.
- *Языковая политика нарушается при правиле в каждом промпте* (украинский, казахский, китайский в ответах).
  Незавершённая работа GLM-сессии — детерминированный детектор `textutil.has_foreign_script` — не подключён.
- *Таблица «модель/роль» на вкладке «Качество»* (`gateway.quality`, `SUM(ok)` по всей истории `messages`):
  нули glm-5.3/skeptic 1017, glm-5.1/arch 762, glm-5/code 339 — **все** HTTP 429 code 1310 (недельная квота)
  13.10 16:04–22:08; среднее время и токены усреднены вместе с отказами.

## 2. Решения (механизмы, не новые фразы в промптах)

| # | Механизм | Закрывает | Цена |
|---|---|---|---|
| M1 | `pinned_tokens` 600 → 1600: модель видит постановку целиком (медиана карточки помещается; промпт ~4.1k из 8k) | все воздержания «не читали постановку», «файл назван в постановке» | +~1000 токенов prompt-eval на вызов (~2–3 с локально) |
| M2 | **Раунд сверки (R2.5)** вместо немедленного воздержания при расхождении файлов/цели: каждый proposer видит анонимные краткие версии других (goal + файлы + 2 пункта), сверяется с постановкой, правит своё или явно аргументирует расхождение в `open_questions`. Затем детерминированные ворота; прошли — рецензия и дальше по протоколу; нет — воздержание с уже сформулированными вопросами | 70 вердиктов (42+28) | +1 вызов на proposer (2 в fast, ~1 мин); рецензии — только если ворота прошли |
| M3 | **Дожим при 7–8/15** (порог 9): автор лучшего предложения получает блокирующие возражения рецензентов и правит; одна повторная рецензия; порог не снижается | 21 вердикт | +1 правка + 1–2 рецензии |
| — | M2 и M3 — один дополнительный раунд на прогон (не оба), только при остатке времени ≥ 3 мин | | |
| M4 | **Инфраструктура ≠ воздержание.** Отказы по таймауту слота/демона считаются отдельно; «ни одного предложения», «рецензий не было (время)», «арбитр не ответил» при инфраструктурных отказах → исход `deferred`: прогон возвращается в очередь через 15 мин без сожжённой попытки, не больше 2 раз, затем воздержание с явной причиной «ресурс локальных моделей». Дедлайн карточки считается и для предложений (таймаут вызова = остаток) | 12 + 12 + часть 4 | 0; меньше пустых прогонов у владельца |
| M5 | **Арбитр не ответил** → повтор с компактным пакетом (2 лучших предложения: goal, пункты, файлы, критерии; без рецензий), max_tokens 1500; снова нет → лучшее предложение, прошедшее все ворота, идёт дальше без слияния (provenance «без слияния», confidence ≤ 0.5) | 4 | +1 вызов только при сбое |
| M6 | **Языковой гейт в `_ask`:** строковые поля структурного ответа проверяются `textutil.has_foreign_script`; нарушение → один повтор с конкретной поправкой («фрагменты «…» — перепиши по-русски»); цитаты из постановки (слово есть в капсуле) — не нарушение. Посторонний язык в самой постановке → пометка в капсуле «не переносить» | язык (вердикты 15, 53, 68, …) | повтор только при нарушении |
| M7 | **Детерминированная чистка:** маски (`*.spec.ts`, `**/*.ts`) убираются из привязок до верификатора (не «выдумки», а не пути); `verification_cmd` с pytest/jest/mocha при TS-файлах в `apps/*`/`packages/*` заменяется на `turbo run test:run --filter=<пакет>` по package.json затронутых файлов (замена — в `removed_by_verifier`) | 5 + «pytest для .spec.ts» | 0 |
| M8 | **Промпты — точечно, не 13-м правилом везде:** арбитр — корень первым пунктом, пункты вне цели удалять, конкретное значение вместо «оба варианта», противоречие постановки — вопрос с вариантами; критик — «класс дефекта» (смежные пути и тест на чужую компанию для security), стек проверки; proposer.code — «не воспроизведено → первый шаг репро», маски не пути; arch/skeptic — продуктовая развилка → решение-запрос (варианты, цена, рекомендация) | 26 «выдан, но отклонён» | 0 |
| M9 | **Уже закрыто?** Если запись в `docs/plans/done/*.md` ссылается на Notion-id карточки — в капсулу первым блоком «Карточка закрыта: …», и задача консилиума — план проверки и закрытия, а не повтор | 3 «устаревший снапшот» (+ будущие) | 1 grep по 25 файлам |
| M10 | **Кластеризация дрейфа:** `target` — enum одной мишени; паттерн-тема/список мишеней отбрасывается; кластеризатору даётся исход прогона рядом с комментарием владельца (дефект механизма, не тема карточки); модель кластеризации — облачная (glm-5) не чаще раза в 12 ч при доступной квоте, иначе локальная | шум 42 «новых» | ≤ 2 вызова GLM в сутки |
| M11 | **Роли:** третьей независимой S-модели нет (deepseek-r1:7b — дистилл Qwen, GLM-4.6V — та же линейка, что glm4) → без изменений; рекомендация владельцу — поставить независимую S-модель (gemma3/llama3.x/mistral-nemo, 5–8 ГБ) как арбитра fast | арбитр сливает своё | решение владельца |
| M12 | **Экран «модель/роль»:** период (сутки/7 дней/30/всё, по умолчанию 7), колонки «попыток / успех / без ответа / не разобран», среднее время и токены — только по успешным, строка-разбивка облачных отказов (квота 1308/1310, бюджет, HTTP/сеть) из `cloud_usage`; подпись «контур консилиума; ревью — вкладка «Ревью»» | рекомендации владельца по экрану | 0 |

## 3. Отклонённые альтернативы

- Новые правила во все промпты по 42 предложениям — 65 уже применены, дефекты повторяются; слабые 7–9B модели
  деградируют от длинного системного промпта.
- Снизить пороги ворот (0.25/0.15/9) — больше «ложного согласия», те же планы мимо цели уйдут владельцу.
- Убрать ворота для fast — то же.
- Третий proposer в fast той же моделью — «иллюзия консилиума» (зафиксировано в config.toml).
- Облачный арбитр для каждой карточки — квота Coding Plan (~46 вызовов glm-5 на 5 ч) — узкое место.

## 4. Приёмка

- selftest: каждый механизм — проверка на подставных моделях (сверка: расхождение → раунд → ворота прошли/нет;
  дожим 7–8; инфраструктурный отказ → deferred → после 2 раз abstained; арбитр: повтор → без слияния; языковой гейт:
  нарушение → повтор, цитата постановки — не нарушение; маски и verification_cmd; done-ссылка; кластеризация
  отбрасывает тему/список мишеней; quality() — период и разбивка).
- Живая проверка на 3–5 карточках fast (локально, строго последовательно) после синхронизации: доля воздержаний,
  время прогона.
- Метрика через неделю: доля воздержаний (база 80% с 01.10) и доля accept/edit среди вердиктов.
