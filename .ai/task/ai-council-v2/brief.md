та# AI Council v2 — UI, сессионный контекст, граф, знания

## Оригинал задачи (авторитетный, RU)

Продумать и придумать план улучшения продукта ИИ консилиума (infra/ai-council/):

1. Главная страница с формой ввода задачи; упоминание задач из Notion через
   `@[название задачи]` для связи прогона с конкретной задачей.
2. Дополнительный MCP + RAG как хранилище контекста в сессии; сохранение итогового
   контекста предыдущих сессий перед их завершением; использование его в новых сессиях.
3. В области графа: определять связи по функциям, классам, вызовам, файлам и данным
   в БД; управлять количеством узлов шкалой
   150 / 300 / 500 / 1000 / 1500 / 2500 / 5000 / 8000 / 10000 / 15000 / 25000 / все.
4. В области знаний: выводить все доступные в моменте знания с пагинацией
   (без запроса выводятся все данные).

## GOAL

План развития подсистемы (не реализация): четыре фичи, вписанные в существующую
архитектуру (stdlib-Python, SQLite WAL council.db, одностраничный HTML на gateway.py,
инварианты «шлюз — читатель», «ноль зависимостей», белый список записи в Notion).

## CONSTRAINTS

- infra/ai-council/ — только stdlib, без сборки фронта; UI — один index.html.
- gateway.py: 127.0.0.1, без авторизации (замена ей — отсутствие внешнего сокета);
  шлюз пишет в БД только вердикты и очередь; в Notion не пишет.
- Notion-гварды: Status и Half-baked не пишутся никогда; создание страниц —
  require_apply_flag, dry-run по умолчанию.
- Капсула ≤ ~2400 токенов; бюджеты per-source; модельный лок; облачный бюджет.
- Граф: graphify-out/graph.json ~68k узлов; текущий потолок отдачи /api/graph — 1200;
  3D-раскладка canvas 2D рассчитана на ~1000 узлов.

## ACCEPTANCE CRITERIA (плана)

- Каждая фича разложена на: изменения схемы/файлов, API, UI, миграции, риски, проверки.
- Развилки с материальным продуктовым эффектом вынесены владельцу (не решены молча).
- Указан порядок фаз с обоснованием и оценкой.
- Ничего не ломает инвариантов раздела CONSTRAINTS.

## RISKS

- «Все» узлов (68k) в текущем рендере убивают вкладку — нужен другой режим отрисовки.
- Ad-hoc задачи без карточки ломают emit/обучение/вердикты (всё завязано на card_id).
- «Сессия» не определена в терминах подсистемы (прогон? цепочка прогонов? рабочий день?).
- MCP: неизвестно, нужен ли наружный MCP-сервер или новый инструмент в пуле источников.
