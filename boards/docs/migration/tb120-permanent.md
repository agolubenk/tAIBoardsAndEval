# TB-120 — перманентные задачи: чего нет в проде и что нужно для завершения

Версия 1.0 · 30.10.2026 · замечание владельца 30.10: «перманентные задачи, если ещё не существуют в
продакшен версии… создай отдельные небольшие документы». Прод = d4dev, сейчас бандл b5 — **из перманентного
там ничего нет** (спека R-100–R-105, этап 2 после перехода; заметка «учесть перманентные задачи» в решении
`d-tb-kinds` 30.10).

## Что уже решено (спека v0.3.2, R-100–R-105; impl-remaining «Этап 2»)

- Категории: **проверка** (разовая проверка с результатом) · **период** (повтор по расписанию) · **фокус**
  (пока не закрыт — держим на виду) · **принято** (осознанно живём с этим; только с «да» владельца и датой
  пересмотра).
- Эпизоды — дочерние карточки по расписанию и по триггеру (R-102, R-103). Сторожа: приём результата из
  CI/скрипта, серия зелёных, красный → ошибка без дублей (R-101). «Пульс»: просроченные эпизоды и сроки
  пересмотра (R-090, R-104). Разбор импорта: агент предлагает категорию, владелец подтверждает пачкой
  (R-100, R-081 — срез П5).

## Чего нет и что нужно (срезы П1–П5, порядок из impl-remaining)

| Срез | Что сделать | Заметки |
|---|---|---|
| П1 | Миграция `card_meta`: поле `permanence` + параметры категории; вид с четырьмя полосами; `forest_get/set_card_meta`; «принято» — только с «да» и датой пересмотра | одна миграция; канон полей R-024 |
| П2 | Эпизоды: дочерние карточки по расписанию/триггеру | планировщик тот же, что у сверки зеркала (`impl/impl-b1-mirror-schedule.md`) |
| П3 | Прогоны сторожей: приём из CI или скрипта, серия зелёных, красный → ошибка без дублей | вход — существующие гейты репо |
| П4 | «Пульс»: просроченные эпизоды и сроки пересмотра; контекст-пакет «известно, не чинить» | панель «Пульс» уже есть (b5+) |
| П5 | Разбор импорта: агент предлагает категорию, владелец подтверждает пачкой | сюда же раскладка «Разбора» (`tb120-projects.md`) |

Адверсариальная проверка срезов — перед стартом П1 (Q-108 спеки).

## Первые перманентные карточки (уже живут в правилах репозитория, готовы к заведению после П1)

1. **Проверка** — `parse_mode` на всех путях отправки Telegram; refresh-токен только в cookie.
2. **Период** — апстрим kaneo раз в 2 месяца (R-004); восстановление бэкапа (AC-004).
3. **Фокус** — обрывы Telegram-сессий (`AUTH_KEY_DUPLICATED`); красный `ci-frontend` (циклы madge с 07.10).
4. **Принято** — остаток `npm audit`: `js-yaml` через `@nestjs/swagger`, только dev.

## Связь с переносом TB-120

- В Notion перманентного типа **нет** — при переносе эти карточки не приезжают; заводятся на доске после
  перехода (П1+П5) из списка выше и разбора «Разбора» (49 карточек без Module, 32 живых — часть из них
  кандидаты в перманентные, например «Ops: алерт на нехватку памяти»).
- До П5 зеркало не трогает перманентные поля — конфликтов с R-081 нет.
