# TB-120 — разбивка карточек Notion по проектам HR Helper / Lavaeon

Версия 1.0 · 30.10.2026 · решение владельца 30.10 (~11:20): 9–10 направлений по ролям репозитория,
карточки без Module — в проект «Разбор». Вход в прожарку спеки v0.4, не замена ей.

## Фактура (снято с Notion 30.10, 1070 карточек)

- «Задачи» — 461 (231 завершённых), «Ошибки» — 609 (256 закрыто). Живых (не в конечных статусах) — 582.
- 668 карточек с 2+ метками Module → нужен приоритет: **первая метка списка в Notion** (порядок выставлен
  вручную, первый = главный). 49 карточек без Module (32 живых) → «Разбор».
- Метки Module шумят, нормализация обязательна: `security` и `auth` → `security/auth`; `ai` и `ai-council` →
  `ai-tooling/mcp`; `meeting-intelligence` → ИИ-инструменты; `platform`, `billing`, `hr-ops` → инфраструктура.

Правила:

1. Проект = по **первой** метке Module после нормализации (см. таблицу). Пример нормализации в коде —
   `NORM`/`GROUP` из этого документа (проверено 30.10: неразложимых меток нет, `unrouted = {}`).
2. Нет Module → проект «Разбор». Раскладывает владелец/агент при разборе (этап П5, `tb120-permanent.md`):
   в Notion проставляется Module — карточка переезжает сама следующим прогоном зеркала.
3. Смена Module в Notion → карточка переносится между проектами зеркалом (R-081: Notion канон).
4. Вторичные метки Module теряются как проекты, но сохраняются метками карточки — маппинг уже кладёт все
   multi_select в labels (`packages/importers/src/notion/mapping.ts`).
5. Идемпотентный ключ — `продукт + notion + page id` (R-080), проект в ключ не входит → перенос безопасен,
   дубли не возникают.
6. Зеркальная карточка: перенос вручную на доске запрещён (поля Notion только для чтения, R-081) — меняют
   Module в Notion.

## Что нужно для завершения (реализация)

- Правило маршрутизации в импортере: вместо «проект на базу» (`write-notion-project.ts`) — «проект на базу
  × направление»: проект-владелец определяется первой меткой Module; проект создаётся при первом попадании,
  дальше переиспользуется. Перенос при смене первой метки — обновлением `projectId` существующей задачи.
- Таблица нормализации — в код (один источник, тест на каждую шумную метку).
- Тесты: маршрутизация по первой метке; смена метки переносит; без метки — «Разбор»; повторный прогон — +0.
- Приёмка AC-002 считается по проектам: суммы по таблице выше (1070 всего / 582 живых) должны сойтись.
