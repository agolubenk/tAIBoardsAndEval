## Чинилось в этой сессии (сессия 27.10 оборвалась на 2 падающих тестах)

1. `shortenLongestString` имел неподвижную точку: строка длиной `MIN_STRING_FLOOR + len(«… [truncated]»)` (78)
   укорачивалась сама в себя, `fitToBudget` крутил цикл до guard=1000 и никогда не доходил до обрезки массивов
   (тест с 200 комментариями выдавал 3257 токенов при бюджете 400). Фикс: строки короче `2 * MIN_STRING_FLOOR`
   (128) не считаются укорачиваемыми — цикл переходит к массивам и сходится.
2. Тест «строки раньше массивов» ждал конкретные `≤ 520` символов — калибровка от старого дизайна с фиксированным
   потолком. Прогрессивный халвинг наоборот сохраняет максимум текста в бюджете, поэтому контракт переформулирован:
   `tokens ≤ 250`, описание укорочено минимум втрое (≤ 1500 от 4500), массив нетронут.
3. `attachFullRef` возвращал `unknown` — 2 ошибки tsc на вызовах `shortenLongestString/trimLongestArray`.
   Возвращает `JsonContainer`.

## Замер токенов JSON vs TOON (bench.ts, счётчик o200k_base)

| карточка | JSON tokens | TOON tokens | TOON/JSON |
| --- | ---: | ---: | ---: |
| card-1 (малая, без комментариев) | 142 | 117 | 0.82 |
| card-2 (8 комментариев + история) | 1188 | 830 | 0.70 |
| card-3 (40 комментариев + история) | 5316 | 3582 | 0.67 |

TOON даёт −18…−33 % токенов против pretty-JSON; выигрыш растёт с долей табличных массивов. Сам по себе это не
достигает «вдвое дешевле» из AC-001 — там экономия должна идти против ответа Notion API (шумные поля, rich_text
блоки, пагинация), что замеряется на шаге S5/бенчмарке AC-001 на реальных карточках.
