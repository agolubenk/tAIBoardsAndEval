## Изменённые файлы (всё новое, 7 файлов, +507)

- `packages/redact/src/index.ts` — `redact(text): { text, hits }`, чистая функция без I/O. На месте секрета —
  метка `[REDACTED:<kind>]`; `hits` — позиции в **исходном** тексте, в порядке документа. Детекторы в порядке
  приоритета (пересечения выигрывает более ранний): `pem` → `db_url` → `bearer` → `jwt` → `api_key` →
  `password_assignment` → `base64_blob`. Покрытие по спеке:
  - префиксы: `sk-`, `sk-ant-`, `ghp_`, `gho_`, `github_pat_`, `xox[abp]-`, `AKIA…`, `glpat-`, `AIza…`;
  - JWT — три base64url-сегмента, обязательный префикс `eyJ` (отсекает случайные «a.b.c»);
  - PEM-блоки `-----BEGIN … KEY-----` многострочные;
  - строки подключения `postgres(ql)://`, `mysql://`, `mariadb://`, `mongodb(+srv)://`, `redis(s)://`, `amqp(s)://`
    — только при наличии пароля (`user:pass@` / `:pass@`);
  - `Authorization: Bearer …` (чистится только токен, имя заголовка остаётся);
  - присваивания `password=` / `passwd:` / `pwd=` / `"password": "…"` (регистронезависимо) и `SECRET=`
    (только верхний регистр — чтобы не трогать прозу «the secret: …», есть тест);
  - base64-блобы: длина ≥ 64 (`BASE64_BLOB_MIN_LENGTH`), обязательное смешение регистров и цифр, энтропия
    Шеннона ≥ 4.5 бит/символ (`BASE64_BLOB_MIN_ENTROPY`). Обоснование порога: base64 случайных байт даёт ~6 бит/сим,
    текст и hex — заметно ниже; 4.5 оставляет запас для коротких структурированных ключей и при этом пропускает
    hex-дайджесты (они отсеиваются уже проверкой смешения регистров: sha256/git SHA однорегистровые, UUID содержит
    дефисы и не попадает в алфавит).
- `packages/redact/src/index.test.ts` — 27 тестов. Корпус секретов собирается в рантайме конкатенацией фрагментов
  (`join(...)`), литералов, похожих на секреты, в репозитории нет.
- `packages/redact/bench.ts` — бенчмарк (`pnpm --filter @kaneo/redact bench`, node с type-stripping).
- `package.json` / `tsconfig.json` / `vite.config.ts` / `vitest.config.ts` — по образцу `packages/permissions`
  (vite-plus tasks: `compile`, `test:run`; тесты через `vite-plus/test`).
- `pnpm-lock.yaml` — регистрация нового workspace-пакета после `pnpm install`.

Отступления/решения по ходу:
- Идемпотентность: значения после `Bearer`, `password=`, `SECRET=` с lookahead `(?!\[REDACTED)` — повторный прогон
  по уже вычищенному тексту не даёт новых срабатываний (есть тест).
- `bearer` ловится раньше `jwt`, поэтому JWT в заголовке — один hit `bearer`, а не два.

(`openaiKey: z9y8…`, plain alnum, ниже порога base64-блоба) намеренно НЕ вычищается. Расширение покрытия — решение

## Что не проверено / риски

- Бенчмарк — синтетический наполнитель (проза + git SHA + sha256 на строку); на реальных транскриптах с плотными
  PEM/логами числа могут отличаться, порядок — десятки МиБ/с, для пайплайна вычистки это не узкое место.
- Регулярки префиксов задают минимальную длину хвоста (`{20,}`, у AWS/Google/GitHub — точная по их формату);
  укороченные/битые ключи не ловятся — сознательно, во имя низких ложных срабатываний.
- Пакет никуда не подключён — вызов со стороны `apps/api`/MCP делает Claude по интерфейсу выше.
