# R-034, AC-013 — набор инструментов по роли

Обновлено: 2026-10-28 10:10. Код в `boards`, не закоммичен.

## Что сделано

- **Роль сессии** задаёт заголовок `x-t-boards-role` на запросе к `/api/mcp`. Роли: `reader`, `developer`, `reviewer`,
  `planner`, `forester`.
  - Без заголовка — полный набор, как в kaneo: старые клиенты и хаб не ломаются.
  - Неизвестная роль — `400 unknown_role` со списком ролей. Опечатка не должна молча открыть всё.
- **Наборы ролей** — `apps/api/src/mcp/tool-scope/roles.ts`. У всех — ядро чтения (10 инструментов), у всех, кроме
  `reader`, — аренда. Дальше по работе:
  - `reader` — только чтение;
  - `developer` — правка карточки и статуса, комментарий, поля агента, запрос «да»;
  - `reviewer` — статус, комментарий, лента активности, запрос «да»;
  - `planner` — создание и раскладка карточек, исполнители, сроки, метки, связи, секторы;
  - `forester` — секторы, вырубка, рост, логи.
  - Юнит-тест сверяет каждое имя с настоящим каталогом: переименование инструмента в пакете не оставит роль с дырой.
- **`tools_find`** (`scoped-tools.ts`). Агент описывает действие и получает ближайшие недостающие инструменты со
  схемами. Они добавляются сессии.
  - За вызов — не больше 3, на сессию — не больше 5 сверх роли. Когда 5 взяты — отказ «Ask the owner for a role…».
    Полный набор не выдаётся никогда (AC-013).
  - Ранжирование (`rank-tools.ts`) — TF-IDF и косинус по имени (вес 2) и описанию; множественное число сводится к
    единственному. Совпадения слабее половины лучшего отбрасываются, иначе случайное общее слово занимает место.
- **`tools_call`** вызывает взятый инструмент по имени. Он нужен клиентам, которые не перечитывают `tools/list`; новое
  подключение видит взятые инструменты прямо в списке. Инструмент вне набора сессии — отказ.
- **Хранение** — таблица `mcp_tool_grant`, миграция 0070 (сгенерирована drizzle-kit, только DDL).
  - Ключ — роль и sha256 bearer-токена; сам токен в БД не попадает.
  - Предел держит advisory-lock по ключу в транзакции: две одновременные находки не проходят 5 вместе.
  - Строки старше 30 дней удаляются при каждой выдаче.
- **Журнал R-036.** `tools_find` пишется как обычный инструмент. `tools_call` не пишется: вызванный через него
  инструмент записан под своим именем, двойного счёта нет.
- `@kaneo/mcp/tools` экспортирует `createRegisterTool`: API регистрирует `tools_find` с той же валидацией и журналом.
  `registerMcpTools` стал асинхронным — читает выдачу из БД.

## Отступления от буквы R-034

- «По вектору» — TF-IDF, не нейронные эмбеддинги. Эмбеддинги придут с памятью (K-5) и решением Q-105; `rankTools`
  заменяется, остальное не меняется.
- «Роль и задача»: роль задаёт клиент заголовком, задача входит только текстом запроса `tools_find`. Привязка роли к
  ключу — вместе с ключом на сессию (R-010).
- Роль сужает видимость, а не права. Права по-прежнему проверяет API: аренда, «да», запреты S4. Клиент без заголовка
  видит всё.
- stdio-пакет `@kaneo/mcp` ролей не знает.
- `tools_find` понимает английские слова инструментов. Русский запрос получит «No tool matches».
