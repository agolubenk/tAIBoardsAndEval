# Шаг 4 — поля карточки (R-024) и формат ответа MCP (детали)

Сделано 28.10, не закоммичено. Ветка `t-boards` в `boards`.

## Поля

Отдельная таблица леса `card_meta`, одна строка на задачу kaneo; строки нет — поля по умолчанию. Миграция
`apps/api/drizzle/0068_t_boards_card_meta.sql`, в dev-базе применена.

| Группа | Поля | Пишет |
|---|---|---|
| Notion | `kind` (task/bug), `severity`, `backlogId`, `halfBaked`, `report` | владелец; агент — только на своей карточке |
| Агент | `executor`, `branch`, `pullRequests`, `files`, `tokens`, `costUsd`, `contextPack` | агент под арендой, владелец |
| Зеркало | `notionPageId`, `notionStatus` | только импорт S5 (K-4) |

Ограничения: `backlogId` уникален в workspace, `notionPageId` — глобально; `pullRequests` ≤ 20, `files` ≤ 200;
`costUsd` — `numeric(12,4)`. Статус и приоритет остаются полями kaneo, их правила — в `impl-s4-rights.md`.

## Правила записи

`apps/api/src/forest/card/decide-card-write.ts`, порядок проверок:

1. Агент — сначала аренда и fencing, как у остальных записей (AC-010).
2. Карточка из Notion (`notionPageId` есть) — поля Notion только для чтения, в том числе для владельца (R-081).
   Поля агента пишутся.
3. `halfBaked` меняет только сессия владельца в UI (`owner-ui`), в обе стороны (Q-011).
4. Агент меняет поля Notion только на карточке, которую сам создал.
5. Агент не берёт аренду на half-baked карточку: 403 `half_baked`, отказ — в журнал (`assert-not-half-baked.ts`).

Записи и отказы агента пишутся в журнал действием `card.meta` со списком полей.

## Маршруты и MCP

- `GET /forest/{workspaceId}/cards/{taskId}/meta` — право `task:read`.
- `PUT` там же — право `task:update`; пустая правка → 400, занятый Backlog ID → 409.
- MCP: `forest_get_card_meta` (чтение через вид R-031: etag, `fields`, бюджет) и `forest_set_card_meta` (запись агента,
  заголовки аренды вынимаются из аргументов). `halfBaked` в MCP не принимается вовсе.

## Формат ответа MCP — отклонение от буквы R-033

R-033 говорит «по умолчанию TOON». Замер на живом стенде показал, что на вложенных ответах TOON дороже JSON. Поэтому
без параметра `format` ответ уходит в том из двух форматов, где меньше токенов o200k (D-018). `format: "toon"` или
`"json"` задаёт формат явно. Ошибка кодека TOON → ответ в JSON с записью в журнал (AC-022), как и было.

Замер 28.10 08:59, `../tools/mcp-wire-measure.mjs`, синтетический проект на 8 задач, токены o200k:

| Инструмент | по умолчанию | TOON | JSON |
|---|---:|---:|---:|
| list_workspaces | 81 | 81 | 85 |
| list_projects | 1147 | 1325 | 1147 |
| get_project | 127 | 139 | 127 |
| list_tasks | 1503 | 1778 | 1503 |
| get_task | 185 | 202 | 185 |
| list_workspace_members | 54 | 54 | 57 |
| list_workspace_labels | 18 | 18 | 18 |
| forest_list_approvals | 609 | 609 | 719 |
| forest_get_card_meta | 111 | 123 | 111 |
| **Всего** | **3835** | **4329** | **3952** |

Выбор дешевле чистого TOON на 11% и чистого JSON на 3%. Выигрыш TOON — плоские списки (approvals −15% к JSON), проигрыш —
вложенные (list_tasks +18%). Нужно решение владельца: оставить выбор или вернуть букву R-033.

Обёртка бюджета R-032 фиксирует формат по целому ответу и усекает уже в нём, чтобы формат не прыгал между раундами.
