# S4 — права агента на маршрутах kaneo (детали)

Обновлено: 2026-10-27 19:34. Код в `boards` (ветка `t-boards`, **не закоммичено**). Сводка — `../impl-progress.md`.
Правила спеки: R-022, N-004, AC-007, AC-008, AC-010, AC-027.

## Что агенту можно

| Действие | Агент | Владелец в UI |
|---|---|---|
| Создать карточку | да, кроме сразу закрытой | да |
| Статус между открытыми колонками (to-do → in-progress → in-review) | да, под своей арендой | да |
| Исполнитель, срок, перенос в другой проект | да, под своей арендой | да |
| Текст карточки, которую создал агент | да, под своей арендой | да |
| Текст карточки владельца (заголовок, описание) | **нет**, только комментарий | да |
| Закрыть (колонка `isFinal` или `archived`) | только с «да» на этот статус | да |
| Сменить приоритет | только с «да» на это значение | да |
| Удалить карточку, проект, workspace | **нет** | да |
| Массовые правки, `reorder`, импорт | **нет** | да |
| Новый маршрут `/task/*`, которого нет в таблице | **нет** (fail closed) | да |

«Агент» — любой запрос с токеном: API-ключ, bearer, `x-api-key`. Cookie-сессия — человек. «Да» даёт только владелец
в UI (N-011), своё «да» агента отклоняется (AC-027).

## Как устроено

Апстримовские обработчики не тронуты. Перед маршрутами kaneo стоят три middleware (`apps/api/src/index.ts`):

- `api.use("/task/*", agentTaskGuard)`;
- `api.use("/project/*", agentProjectDeleteGuard)`;
- `api.use("/auth/organization/delete", agentWorkspaceDeleteGuard)` — до better-auth.

Аренда и «да» едут в заголовках, тела запросов остаются апстримовскими:

| Заголовок | Что |
|---|---|
| `x-t-boards-session` | метка сессии; держатель аренды — `key:<id>:<метка>` |
| `x-t-boards-fence` | `fencingToken` из `POST /api/forest/{ws}/leases` |
| `x-t-boards-group` | `groupKey` общей аренды связки сессий |
| `x-t-boards-revision` | ожидаемая ревизия задачи, иначе `revision_conflict` |
| `x-t-boards-approval` | id одобренного запроса `close_task` / `set_priority` |

Модули — `apps/api/src/forest/agent-guard/`, по одной функции на файл, тесты рядом:

| Модуль | Что делает |
|---|---|
| `classify-task-request.ts` | чистая таблица маршрутов `/task/*`: pass, forbidden, create, edit с изменениями из тела |
| `decide-task-write.ts` | чистое решение: текст владельца → отказ; закрытие → «да» на статус; приоритет → «да» на значение; закрытие и приоритет в одном запросе → отказ |
| `closing-status.ts` | закрывающий статус: `archived` или колонка с `isFinal` |
| `agent-authored.ts` | карточку создал агент, если в журнале есть его `task.create` |
| `assert-agent-lease.ts` | `assertFence` + держатель: своя аренда или тот же `groupKey` |
| `hold-approval.ts` | тратит «да» до обработчика, возвращает при ошибке обработчика |
| `task-guard.ts` | собирает всё; каждый отказ пишет в журнал агентов (`outcome: denied`) |
| `delete-guards.ts` | запрет удаления проекта и workspace |

«Да» расширено (`apps/api/src/forest/approval/`): действия `close_task`, `set_priority`, поле `value` в запросе, колонка
`owner_approval.params` (что именно разрешено, видно владельцу). Хэш параметров — тот же `approvalParamsHash`, ключ
`treeIds` оставлен, чтобы старые хэши совпадали. Запрос «да» на задачу требует права `task:update`, на вырубку — как
раньше `task:delete`.

Миграция `0067_t_boards_agent_rights.sql`: `owner_approval.params jsonb` и индекс `agent_journal_target_idx` по
`(target_type, target_id)` — guard ищет автора карточки по нему. Апстримовские таблицы не тронуты. В dev-базе
применена (API применяет миграции при старте).

## MCP

- `packages/mcp/src/tools/agent-write.ts`: у `create_task`, `update_task`, `move_task`, `update_task_status`,
  `update_task_assignee`, `update_task_due_date` появились `session`, `fencingToken`, `groupKey`, `expectedRevision`,
  `approvalId`. Обёртка `createRegisterTool` вынимает их из аргументов и шлёт заголовками; обработчик получает клиент
  этого вызова вторым аргументом.
- `forest_request_approval`: действия `close_task`, `set_priority` и `value`.
- `update_task` шлёт полное тело. Неизменённый текст владельца правкой не считается, поэтому смена статуса через
  `update_task` проходит.

## Известные зазоры

0. ~~HIGH (автоматическое ревью безопасности, 27.10)~~ — **закрыто 28.10.** Guard читал тело только при
   `content-type` с `application/json`, а валидатор Hono принимает и `application/<x>+json` — правка прошла бы мимо
   N-004 и «да». Теперь запись агента обязана прийти ровно `application/json` (`agent-guard/json-media-type.ts`), иначе
   403 `agent_forbidden` с записью в журнал. Тест — девятый в `forest-agent-rights.test.ts`.
1. **TOCTOU.** Аренда проверяется в своей транзакции, обработчик kaneo пишет в своей. Между ними аренду может
   перехватить другая сессия, если первая истекла ровно в этот момент. Закрыть можно только переносом записи в одну
   транзакцию, а это правка апстрима.
2. **«Да» вне транзакции записи.** Тратится до обработчика, возвращается, если обработчик упал или ответил не 2xx.
   Если процесс умрёт между тратой и записью, «да» пропадёт — владелец даст новое.
3. **Без аренды:** комментарии, метки, связи, вложения, `duplicate`. `duplicate` может скопировать закрытый статус.
4. Удаление workspace агентом отклоняется, но **в журнал не попадает**: better-auth отвечает до того, как известен
   пользователь.
5. Человек в UI может править карточку, пока её арендует агент. Fencing — только для агентов.
6. Агент может переоткрыть карточку из `done` без «да». В спеке это не запрещено; решить вместе с полями статусов.
7. ~~Полей Notion нет~~ — **сделано 28.10**: поля карточки и запрет аренды half-baked, см. `impl-s4b-card-fields.md`.
8. Заголовки дублируют имена между API и MCP (`agent-headers.ts` и `agent-write.ts`); общий пакет ради пяти строк не
   заводил.
