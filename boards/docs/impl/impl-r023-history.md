# R-023, AC-009 — история карточки и откат одним действием

Обновлено: 2026-10-28 09:26. Код в `boards`, не закоммичен.

## Что сделано

- **Таблица `card_history`**, миграция 0069. Одна строка — одна правка.
  - `kind`: `task` — поля карточки kaneo; `meta` — поля R-024.
  - `revision`: для `task` — ревизия, которую правка заменила.
  - `changes`: только изменённые поля, в виде `{поле: {from, to}}`.
  - `actor_id`: кто правил. `created_at` берётся из `clock_timestamp()`, поэтому две правки в одной транзакции тоже
    упорядочены.
- **Строки пишут триггеры БД**, поэтому ни один путь правки их не обходит: UI, агент, bulk, импорт, вебхуки
  GitHub/GitLab.
  - `task_history` срабатывает после UPDATE задачи, если выросла ревизия. Ревизию поднимает существующий триггер
    `task_revision` — только при правке содержимого, перестановки историю не засоряют.
  - `card_meta_history` срабатывает после INSERT или UPDATE в `card_meta`. Первую запись он сравнивает с умолчаниями.
  - Поля читают SQL-функции `t_boards_task_fields` и `t_boards_card_meta_fields`. Даты — UTC ISO с миллисекундами.
    Разницу считает `t_boards_diff`.
- **Кто правил:**
  - `meta` — `updated_by` строки, точно;
  - собственные записи t-boards (откат) — `set_config('t_boards.actor', …)` в транзакции, точно;
  - маршруты kaneo пишут без актора. Агента дописывает guard после успешной записи: строки с ревизией от прочитанной
    им и без актора;
  - правки людей через kaneo остаются с `actor_id = null`, их называет лента активности kaneo.
- **Маршруты** (`forest/routes/history-routes.ts`):
  - `GET /api/forest/{ws}/cards/{taskId}/history?take=` — правки, новые сверху; по умолчанию 50, не больше 100;
    право `task:read`.
  - `POST /api/forest/{ws}/cards/{taskId}/history/{historyId}/rollback` — отменяет одну правку; право `task:update`.
- **Правила отката** (`forest/history/`):
  - Откат возвращает каждому полю правки значение `from`.
  - Если поле с тех пор правили снова, ответ `409 history_conflict` с перечнем полей: сначала откатите более позднюю
    правку. Откат не затирает чужую работу. Откат отката возвращает правку обратно.
  - Агенту — `403 agent_forbidden`. Иначе откатом можно обойти guard: закрыть карточку без «да», вернуть чужой текст.
    Утёкший ключ всё равно разбирает человек.
  - `task`: под блокировкой строки (`withLockedTask`) с проверками kaneo — статус есть в проекте, исполнителя можно
    назначить. Колонка следует за статусом. Эффекты те же, что у обычной правки: активность и live-события
    (`publishTaskMutation`, `task.updated`). Смена проекта не откатывается: верните карточку переносом.
  - `meta`: через обычную запись `setCardMeta`, поэтому её правила действуют. Half-baked меняется только из сессии
    владельца, Notion-поля зеркальной карточки (R-081) — только чтение. `notionPageId`/`notionStatus` не откатываются,
    их ставит следующий импорт.
  - Оба исхода пишутся в журнал: `card.rollback`, allowed или denied.

## Отклонение от буквы спеки

- Откат — **отмена одной правки** (как `git revert`), а не «вернуть карточку к версии N». К любой версии можно прийти
  цепочкой откатов, от новых к старым, и ни одно поле при этом молча не затирается.
- Агент откатывать не может (см. выше).
