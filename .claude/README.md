# .claude/ — конфигурация Claude Code и память проекта (DAMS)

Документация для человека: что лежит в этом каталоге, зачем, и что делать при проблемах.

## Карта каталога

| Путь | Что это | Коммитится |
|---|---|---|
| `settings.json` | Хуки DAMS (общие для команды) | ✅ |
| `settings.local.json` | Личные permissions (не трогать руками без нужды) | ❌ |
| `rules/` | Модульные правила; `paths:` в frontmatter = грузятся только при работе с указанными файлами | ✅ |
| `agents/` | Кастомные субагенты (backend-expert, telegram-expert, …) | ✅ |
| `commands/` | Slash-команды (`/init-worktree`, …) | ✅ |
| `memory/` | **DAMS L1/L2**: чанки памяти + индексы | ✅ (кроме `session/`) |
| `rag/` | **DAMS L3**: SQLite FTS5 RAG-индекс | ❌ (генерируется) |
| `hooks/` | Python-хуки DAMS (stdlib-only, fail-safe) | ✅ |
| `scripts/` | Инструменты DAMS: rebuild индекса, CLI-поиск | ✅ |

## DAMS — Dynamic Adaptive Memory System (v1, 2026-07-12)

Задача: не грузить всю память проекта в каждую сессию, а подтягивать ровно то,
что нужно текущей задаче. Три слоя:

```
L1 — всегда:      CLAUDE.md (операционная модель + карта ролей) + rules/00,01 + session/latest.md (только своей сессии)
L2 — по задаче:   memory/chunks/* (инжектит хук по ключевым словам промпта)
                  + rules/* c paths:-гейтингом и вложенные CLAUDE.md — карточки ролей (грузит сам
                    Claude Code при работе с файлами; указатели — роутер корневого CLAUDE.md)
L3 — по запросу:  rag/index.db — FTS5-поиск по Prisma-моделям, REST-роутам, Connect RPC,
                  rules, внешним API, ролевым папкам docs/ (doc_type "spec") и записям
                  docs/plans/done/ — одна запись = один документ (doc_type "done_entry");
                  индекс локальный — после pull: index_rebuild.py --clean
```

Карточка роли (`CLAUDE.md` в каталоге) = кто ты здесь, логика решений, команды, гейт; закон (`rules/`) =
Never/Always с примерами. Карточки законы не пересказывают — ссылаются. Гигиена ссылок документации —
`python3 .claude/scripts/docs_linkcheck.py` (код 1 при висячих ссылках).

### Как это работает (поток одного промпта)

1. **UserPromptSubmit** (`hooks/user-prompt-submit.py`): читает `memory/capital.json`,
   матчит ключевые слова промпта (RU+EN) против `load_condition` чанков,
   инжектит до 3 релевантных чанков (~4k токенов max) + до 5 **указателей**
   из RAG-индекса (doc_id + title + путь, без тел — детали Claude читает сам) +
   (для достаточно длинных промптов, см. «Task-brief» ниже) GLM-структуризацию
   задачи RU→EN. Всё инжектированное запоминается в state-файле — в рамках сессии
   повторно не инжектится (экономия токенов на каждом следующем промпте).
   Отдельно от DAMS — подсказка `<grill-task-auto>` (~90 токенов) на каждую реплику, кроме явного
   продолжения (`grill_hint()`): начать задачу со скилла `grill-task`. Отключить: `GRILL_AUTO=off`.
2. **PostToolUse** (`hooks/post-tool-use.py`): после Write/Edit по
   `schema.prisma` / `*.proto` / `*.controller.ts` / rules / docs точечно
   помечает записи индекса stale и подсказывает Claude команду частичного rebuild.
3. **Stop** (`hooks/post-session.py`): в конце каждого хода парсит transcript и
   обновляет `memory/session/latest.md` (тема, изменённые файлы, последний итог,
   открытые пункты `TodoWrite`) — это «мостик» контекста в следующую сессию/инстанс.

**Правило сборки контекста.** Разнородные пулы (чанки, RAG, правила) — сначала по кругу между категориями, потом
бюджет; что бюджет отбросил, считается по каждой категории, иначе голодание пула не видно. Сравнимые оценки —
общий рейтинг; несравнимые (BM25 и косинус) — слияние по рангу (RRF), а не по сырым числам.

### Файлы DAMS

| Файл | Назначение |
|---|---|
| `memory/capital.json` | Индекс chunk heads: id, путь, теги, `load_condition`, статус (`active`/`stale`/`deprecated`), provenance |
| `memory/graph.json` | Граф зависимостей чанков (пока справочный; каскадная инвалидация — V2) |
| `memory/chunks/arch/*` | Архитектурные чанки: connect-rpc, agents, security, db, realtime, ops-ci |
| `memory/chunks/domain/*` | Доменные: telegram, mobile, recruiting |
| `memory/session/latest.md` | Авто-резюме последней сессии (не редактировать, gitignored) |
| `rag/index.db` | SQLite FTS5: `rag_docs` (BM25), `rag_meta` (пути/SHA), `rag_query_log` (аналитика запросов) |
| `rag/.dams-state.json` | Дедуп инжекций по сессиям (gitignored) |

### Команды обслуживания

```bash
# Полный rebuild RAG-индекса (первый запуск / после больших изменений)
python3 .claude/scripts/index_rebuild.py --clean

# Частичный — после изменения одного среза
python3 .claude/scripts/index_rebuild.py --type prisma_model
python3 .claude/scripts/index_rebuild.py --type api_route,proto_rpc

# Поиск руками (то же, что делает Claude)
python3 .claude/scripts/rag_query.py "candidate merge duplicate" --full
python3 .claude/scripts/rag_query.py "sendMessage" --type proto_rpc

# Статистика индекса
sqlite3 .claude/rag/index.db "SELECT doc_type, COUNT(*) FROM rag_docs WHERE status='active' GROUP BY doc_type;"

# Какие запросы реально задавались (оптимизация ключевых слов capital.json)
sqlite3 .claude/rag/index.db "SELECT query, results_count FROM rag_query_log ORDER BY id DESC LIMIT 20;"
```

### Как добавить новый чанк

1. Создать `memory/chunks/<arch|domain>/<id>.md` (короткий дистиллят, 30–60 строк;
   детали — ссылками на rules/docs, не копипастой)
2. Добавить запись в `memory/capital.json`: `id`, `path`, `load_condition`
   (`task_contains:ключ1|ключ2` — RU и EN стемы), `token_estimate` (≈ символы/3)
3. При зависимостях — ребро в `memory/graph.json`
4. Устаревший чанк не удалять сразу: `"status": "deprecated"` (хук перестанет грузить),
   удалить после проверки

### GLM-слой (V3, подключён 2026-07-12; task-brief добавлен 2026-08-09)

Лёгкая LLM Z.ai General API: основная `glm-4.7-flash` (~2 с), при недоступности — платная `glm-4.7` (~5,5 с,
~$0,001 за вызов). Вызовы идут через dev-прокси Headroom с меткой `dams-glm` (расход — в `npm run ai-pipeline:status`),
прокси не поднят — напрямую. Используется в трёх местах, все fail-safe:

1. **Task-brief**: для промптов длиннее `BRIEF_MIN_CHARS` (280 символов, `user-prompt-submit.py`) — GLM переводит и упаковывает задачу в `GOAL/CONSTRAINTS/ACCEPTANCE` (≤80 слов, англ.), инжектится как `<!-- DAMS task-brief -->` рядом с оригиналом промпта. Не заменяет исходный текст — при разночтении источник истины он. Английские термины брифа заодно уточняют L3-поиск у чисто русских промптов. `BRIEF_MAX_PER_SESSION=50` — предохранитель от зацикливания, не бюджет. Отключить только этот слой: `DAMS_TASK_BRIEF=off`.
2. **Query rewriting** — только `rag_query.py` (флаг `--rewrite` форсирует). Из хука убран: у коротких русских реплик указатели по нему почти всегда шли мимо (сессия 2026-10-15: «на каком этапе?» → маршруты hr-tasks/status), у длинных термины теперь даёт бриф. Короткая реплика без латинского идентификатора или SHA L3-поиск не запускает вовсе.
3. **Session summary**: Stop-hook сжимает итог сессии в 2–3 предложения (маркер «(GLM)» в `latest.md`); бюджет — 12 с на цепочку моделей при таймауте хука 20 с; при недоступности — сырой текст, как раньше.

Системные уведомления (`<task-notification>`, `[SYSTEM NOTIFICATION…`, отчёт субагента, сообщение другой сессии) хук
не обрабатывает вовсе: они длинные, проходили порог брифинга и к середине сессии исчерпывали прежний лимит 8 — дальше
реплики владельца брифа не получали («схема оборвалась», 2026-10-15).

Почему ответы не переводятся (решение 2026-10-15): хуки Claude Code только добавляют контекст, текст промпта и ответа
заменить нельзя. Полный английский перевод промпта рядом с оригиналом — лишние токены без пользы (модель читает русский
и рассуждает по-английски). Перевод ответа Stop-хуком сэкономил бы ~1–2 % стоимости: вывод — около 10 % трафика сессии,
остальное — перечитывание контекста из кэша. Цена — +10–20 с к каждому ответу и машинный перевод вместо родного текста.

Конфигурация:
- Ключ: `.claude/rag/.glm-key` (gitignored, chmod 600) или env `GLM_API_KEY`. **В git не коммитить никогда.**
- Модели/маршрут: env `GLM_MODEL` (основная), `GLM_FALLBACK_MODEL` (запасная, `''` — без неё), `GLM_ENDPOINT`,
  `GLM_HEADROOM_URL` (`''` — напрямую; принимается только адрес на петле: Bearer-ключ по http дальше 127.0.0.1 не уходит).
  Таймаут вызова — общий бюджет цепочки: основной модели не больше max(4 с, 40 % бюджета), запасная — только если на неё
  осталось ≥ 7,5 с (её худший замер), ответ без `GOAL:` — тоже сбой основной.
- Отключить весь GLM-слой: `DAMS_GLM=off` (или удалить `.glm-key`) — система полностью работоспособна без GLM; отключить только task-brief: `DAMS_TASK_BRIEF=off`
- Диагностика: `python3 .claude/scripts/glm_client.py "текст задачи"` (печатает и rewrite, и structure_task); тесты —
  `python3 -I .claude/scripts/test_glm_client.py` и `python3 -I .claude/hooks/test_user_prompt_deadline.py`

> **Приватность:** наружу (Z.ai) уходит текст промпта (rewrite, task-brief — до 2000 симв.) и тема+пути файлов+последний итог (summary). Код проекта не отправляется.

### Handoff между сессиями/инстансами (HEADROOM)

Контракт для новой длинной/расплывчатой задачи: **HEADROOM (сжать только большой входной
контекст) → GLM task-brief → точечный DAMS/Serena → HEADROOM handoff**. Оригинальная
формулировка пользователя остаётся источником истины. UserPromptSubmit не имеет доступа к MCP,
поэтому первый и последний шаг агент вызывает сам; GLM/DAMS в середине хук делает автоматически.

Если в проекте настроен HEADROOM MCP (`headroom mcp serve`, см. `claude mcp list`) — это агентный
(не hook-овый) слой поверх DAMS: `session/latest.md` уже даёт бесплатную, всегда-инжектируемую
базовую преемственность (тема, файлы, итог, открытые `TodoWrite`-пункты), но не переживает
переполнение своих 700/300-символьных лимитов на деталях.

Для длинных многосессионных задач — вызывать `headroom_compress`/`headroom_retrieve` самому
(инструмент доступен агенту напрямую, хук вызвать их не может): перед тем как бюджет
исчерпается или явно попросили передать эстафету — `headroom_compress` со снимком {что сделано,
что осталось (из `TodoWrite`), ключевые файлы, task-brief} под стабильным id (ветка или hash
первого промпта задачи). Следующий инстанс: сначала читает `session/latest.md` (автоматически) +
`claude-mem` timeline, и только если этого не хватило — `headroom_retrieve` по тому же id.

### Отладка / отключение

- Хуки **fail-safe**: любая ошибка → пустой вывод, работа Claude не блокируется.
  Если индекса нет — просто нет L3-указателей.
- Проверить хук руками:
  `echo '{"prompt":"добавить кандидата через Connect RPC","session_id":"test"}' | python3 .claude/hooks/user-prompt-submit.py`
- Отключить DAMS целиком: убрать блок `hooks` из `settings.json`.
  CLAUDE.md содержит ручной роутер (таблица L2) — система деградирует мягко.
- Требование: `python3` в PATH (macOS — есть из коробки). Зависимостей нет, только stdlib.
