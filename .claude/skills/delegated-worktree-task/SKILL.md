# delegated-worktree-task — работа через агента

Сначала цена. Каждый агент перечитывает код с нуля — 150–350 тыс. токенов, — а лимит сессии общий для всех сессий
владельца. Больше 2 агентов — только после названной цены и «да» владельца отдельным ходом (память
`feedback_agent_fanout_cost`). Агент, убитый лимитом, теряет всё, что не записал.

## Бриф

1. **Работа переживает обрыв.**
   - Агент в своём worktree: коммит после каждого независимо проверяемого шага, не больше одного шага без коммита,
     в отчёте — SHA по порядку.
   - Агент в общем worktree (коммиты делает ведущий): журнал прогресса в scratchpad — пункт приёмки → сделано или
     осталось, плюс доказательство. Путь журнала назван в брифе, журнал обновляется после каждого пункта.
2. **Каждая промежуточная точка компилируется:** порядок «добавить новое → переключить вызовы → удалить старое»,
   узкий typecheck после каждого шага.
3. **Объём ограничен:** список файлов, никакого браузера и мутационных стендов без просьбы, предел размера отчёта.
4. **Файлы через shell не затирать:** `set -o noclobber` или `[ -e f ] && exit 1` перед `cat >`, либо инструмент
   редактора, который не перезаписывает непрочитанное. Существующий тест на меняемое поведение — запись решения:
   правится одно утверждение, остальное остаётся.

## Тяжёлые гейты у нескольких агентов

- Результат гейта засчитывается только на установке по lock: свой `npm ci` в worktree (секунды из кэша, около 2 ГБ)
  вместо ссылок на `node_modules` основного checkout. Проверка окружения — версия стороннего пакета против
  `package-lock.json` (`node -p "require('multer/package.json').version"`), а не только путь workspace-пакета: такая
  проверка ничего не говорит об общей сторонней установке.

- `tsc -b` (heap 6 ГБ), `vite build`, `vitest`, `jest` одновременно у нескольких агентов — своп-шторм. Тяжёлые
  команды идут по одной через общий замок: атомарный `mkdir`, pid-файл для зависшего держателя, ограниченное
  ожидание, код возврата наружу. Лёгкие команды — параллельно. Локальные модели Ollama — всегда строго по одной.

## Приём после обрыва

- Уведомления не жди: проверь артефакты каждого агента — дифф worktree, файлы вывода, журнал прогресса. Прогресса
  нет — останови агента и забери работу, чтобы не править одно и то же вдвоём.
- Преемник начинает с журнала прогресса и typecheck, а не с повторного аудита grep'ом.
- Работа, которой нужен браузер (визуальные проверки), — в основном цикле: браузер один, и агенты не делят его.
