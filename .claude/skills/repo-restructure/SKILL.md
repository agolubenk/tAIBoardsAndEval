# repo-restructure — переносы и чистка файлов

## До первой правки

1. **Чужие worktree.** `git worktree list`; в каждом — `git diff --name-status -M` и `git diff --cached --name-status -M`
   по целевым путям. Есть пересечение — стоп: сначала один владелец путей. Переносишь в чужой индекс — ставь только
   свои файлы, чужие неиндексированные куски оставь им.
2. **Инвентаризация по каждому файлу:** отслеживается или игнорируется, последний коммит, размер.
3. **Потребители — по разрешённому пути, не по имени.** grep по basename находит ложных «потребителей»: проверь у
   каждого, какой путь он реально собирает (`Path(...)/"…"`, `join(ROOT, "docs", "NAME.md")`, константы вида `X_PATH`).
   Ищи в скриптах и basename, и сегменты пути отдельными строками. Генератор, который пишет файл, прогони один раз и
   убедись, что он пишет уже новый путь — иначе первый `npm install` вернёт старый файл.
4. **Дубли — по байтам** (`cmp` или хэш против остающейся копии), не по имени: одноимённый вариант бывает другим.
   «Заменено каноном» проверяй по содержимому записей, а не по заголовкам.
5. **Неизменяемое — в исключения:** применённые миграции (правка меняет их checksum), lock-файлы, вендоренный и
   сгенерированный код. Сначала план переписывания по областям (dry-run), потом применение.

## Правка

- По каждому файлу — решение: удалить, перенести или оставить. Все ссылки чинятся в том же изменении; переносы —
  через `git mv`, чтобы сохранить историю.
- Текст ссылки меняй, только если он называет путь, которого больше нет. Иначе оставь исходную формулировку; файл,
  где поменялся только текст ссылки, откати.
- Сразу после массового `git mv`: `find <root> -type d -empty -delete` — пустые каталоги обманывают проверки
  существования.

## Проверка и сдача

- Висячие ссылки — `python3 .claude/scripts/docs_linkcheck.py`; генерируемые оглавления и каталоги — только их
  генератором (`npm run done:index` и подобные).
- Осмотри и соседей вне заданного списка: находка безопасности (дамп, ключ) — отдельной карточкой в «Ошибки».
- Удаление файла из git удаляет его и в чужих рабочих копиях: до снятия с учёта проверь потребителей вне репозитория
  — скрипты, сервисы, кэши.
- Адверсариальная проверка — три линзы: висячие ссылки; побочные эффекты для деплоя и чужих клонов; продукт и
  конвенции проекта.
