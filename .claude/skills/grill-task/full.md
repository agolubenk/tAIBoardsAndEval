# grill-task — полный режим

Глубокая прожарка: на выходе — спецификация, которую владелец утвердил по версии, а не код. Правила `SKILL.md`
(«Всегда», определение развилки) действуют и здесь.

## Перед началом

1. Прочитай `protocol.md` из каталога этого скилла. `templates.md` — когда создаёшь или обновляешь state/spec;
   `checks.md` — на этапе проверки. Файл не прочитан — так и скажи, не изображай.
2. Определи источник: текст запроса · карточка t-boards · `state.md` прошлой сессии. Источник уже передан — не проси
   повторить; входа нет и задачи в беседе нет — спроси источник одним вопросом.
3. Работай в основной беседе: решения принимает пользователь, автономный контекст для процесса не нужен.

## Границы (до утверждения спеки)

- Чтение и обсуждение — можно. Запись локального состояния — только после согласия (protocol §1).
- Продуктовый код, `docs/`, карточки t-boards, коммиты и push — не трогать; каждая такая запись — отдельное явное «да».
- Утверждённая спека не разрешает реализацию: разрешение на код — отдельное действие владельца.
- Найденные идеи вне scope — в раздел спеки «Предложения вне scope».
- Искусственных раундов не устраивать: нет развилки — нет вопроса.

## Возобновление

Есть `state.md` → перечитай его, сверь «Проверенные факты» с текущим кодом и карточкой, отдельно назови выводы,
которые устарели или требуют повторной проверки. Устарел факт, на который опирается утверждённая версия, —
утверждение снимается до повторного. Только потом — следующий вопрос.

## Перед выдачей спеки на утверждение (pre-flight, не пропускать)

1. Адверсариальная проверка (protocol §6) проведена в этой прожарке: перечисли фактически запущенных участников
   (агент, линза, главное возражение). Нет запусков — нет проверки, блок не пишется «по памяти».
2. Перечитай «Границы» выше и `checks.md`, прогони по черновику: FAIL/OPEN/N/A — построчно с причиной, PASS —
   одной строкой с перечнем разделов. Без этих двух блоков спека на утверждение не выносится.
