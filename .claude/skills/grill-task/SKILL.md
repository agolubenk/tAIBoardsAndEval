# grill-task — прожарка задачи

Загружен в сессии один раз — дальше применяй режим по памяти, повторно не вызывай (после сжатия контекста — можно).

Вход: $ARGUMENTS

## Режим — определи первым

- **Не задача → ничего не пиши:** продолжение или правка текущей работы, ответ на твой вопрос (в т.ч. с Q-ID),
  одобрение предложенного, вопрос о статусе или фактах без деливерабла.
- **auto** — новая задача. Разведка соразмерно задаче: нужное место кода; «делали ли уже»
  (`python3 .claude/scripts/rag_query.py "<тема>" --type done_entry`) — только для фичи или нового поведения.
  Где искать развилки — применимые категории roast (`.claude/rules/00-task-ingress.md`). Исход:
  1. **Развилок нет** — сразу работа. Строку пишешь, только если есть неочевидные допущения:
     `Допущения: <…>`.
  2. **1–3 развилки** — один раунд до правок, максимум 3 вопроса:
     `❓ Q-1: <вопрос> · почему важно: <последствие> · ➡️ <рекомендация> (цена: <что теряем>)`.
     Решения владельца — дословно в ответе, затем работа. Без state и спеки.
  3. **≥ 4 зависимых развилок, миграция схемы, auth/PII, смена контракта между приложениями** — одной строкой
     предложи полный режим с рекомендацией и дождись ответа. Видимая фича сама по себе — исход 2.
- **полный** — явная просьба прожарить или согласие на исход 3: прочитай `full.md` из каталога этого скилла
  (base directory выше; иначе `.claude/skills/grill-task/full.md`) и следуй ему.

**Развилка** — продуктовое решение владельца: что строим, для кого, границы, видимое поведение, данные и права.
Как реализовать и в каком порядке — не развилка: решай сам по канону (адверсариальная проверка решения — как
обычно, `CLAUDE.md`). Обратимый выбор с ясной рекомендацией — допущение, не вопрос; спрашивай о необратимом и о
видимом пользователю поведении.

## Всегда

- Факт, который можно проверить по коду и документам, у владельца не спрашивают.
- Перед каждым вопросом владельцу — `python3 -I eval/tools/ask_once.py check "<вопрос>"` (с `--oq <экспорт oq_list>`,
  если есть). Код 3 — кандидат-ответ: прочитай; отвечает именно на твой вопрос — сошлись как на допущение и не
  спрашивай, иначе спрашивай. Код 4 — такой вопрос уже открыт: не повторяй, делай то, что от ответа не зависит.
  Ответ владельца — `ask_once.py record --q "…" --a "<дословно>" --source "<где>"`.
- Источник недоступен (карточка не читается, MCP упал, файла нет) — назови, что не проверено; не восстанавливай
  по памяти, `docs/plans/BACKLOG.md` или догадке.
- Рекомендация ≠ решение; молчание и «понятно» — не согласие с вариантом. Scope без согласия не расширять.
- Просьба называет файл или путь для записи — сначала сверь с правилами проекта, где такой файл живёт и кто его
  пишет (`.claude/rules/*`, `docs/README.md`). Есть конфликт — вопрос с рекомендацией, а не запись по просьбе.
- Ответ владельца свободным текстом («Другое») на вопрос с вариантами — возможная смена scope. Прежде чем
  продолжать, заново пройди, какие слои меняет ответ: рантайм, хранение, доступ, где запускается.
- «Сделай как в прототипе» — до кода список «берём / не берём» с причиной по каждому пункту: просьба про
  поведение и вид, а не про реализацию прототипа.
- Утверждения постановки о способе исполнения (параллельно или последовательно, пачкой или потоком) сверяй с тем
  же кодом, на который ссылается постановка: проверенная часть брифа не делает верной остальную.
- Новая задача посреди открытой прожарки — спроси, отложить ли текущую (её state сохраняется), затем триаж новой.
