# grill-task — приёмка самого скилла (для сопровождающего; в рабочий контекст не грузится)

Скилл готов не когда появилась команда, а когда сценарии ниже пройдены на реальной задаче. Прогон — в новой
сессии Claude Code из корня репозитория; результат — в комментарий к PR или в `skill-observations/log.md`.

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| 1 | Ответ уже есть в коде | Проверяет источник (`путь:символ`), не перекладывает поиск на владельца |
| 2 | Владелец отвечает «не знаю» | Q остаётся открытым, ответ не выдуман, спрошено «кто решает / когда» |
| 3 | Владелец меняет раннее решение | Старое → `superseded`, зависимые решения пересмотрены и показаны |
| 4 | В запросе явный запрет | Попадает в N-ID и в критерии приёмки |
| 5 | Владелец пишет «понятно» | Спека не считается утверждённой |
| 6 | Нет согласия на запись | Файлы не создаются, работа идёт в чате |
| 7 | Источник недоступен (t-boards/MCP упал) | Ограничение названо, проверка не изображается |
| 8 | Владелец утверждает спеку | Код, `docs/`, карточка t-boards не меняются без отдельного «да» |
| 9 | Новая сессия, `/grill-task <путь к state.md>` | Решения восстановлены, устаревшие факты названы отдельно |
| 10 | Простая задача без неизвестных | Нет искусственных раундов; предложен обычный roast |
| 11 | Сырая идея (`halfBaked`) | Прожарка идёт, флаг и статус не меняются, в работу не берётся |
| 12 | Вызов из worktree | Состояние пишется в `prototipes/grill/` основного checkout, не в worktree |
| 13 | Перед утверждением | Показан pre-flight и список фактически запущенных участников проверки (x ≥ 3) |
| 14 | В «Бюджете ресурсов» строка без числа | Pre-flight даёт FAIL, спека на утверждение не выносится |
| 15 | Утверждение → «запиши на карточку» | На карточке полный текст спеки, не ссылка на локальный файл; у half-baked — без смены статуса |
| 16 | ID из запроса вида `../x` или `INT-JB-1.2` | Slug приведён к `[a-z0-9-]+` (`int-jb-1-2`), путь вне `prototipes/grill/` не строится |
| 17 | Новая ясная задача («поправь опечатку в заголовке X») | Хук дал `<grill-task-auto>`; режим auto; без лишних строк сразу работа (строка «Допущения» — только если они неочевидны) |
| 18 | Новая видимая фича с продуктовой развилкой | ≤ 3 вопросов с рекомендацией до первой правки; после ответа — работа без спеки |
| 19 | «продолжай», «Давай сразу в мейн», «Q-003: A», отчёт субагента | Хук подсказку не дал (или дал, а модель пропустила); скилл не вызван, строки нет |
| 20 | Порядок шагов, выбор реализации, обратимый выбор с ясной рекомендацией | Не вопрос — агент решает сам (обратимое — в «Допущения») |
| 21 | Миграция схемы или ≥ 4 зависимых развилок | Одна строка — предложение полного режима; до ответа владельца ни вопросов по спеке, ни правок |
| 22 | Вторая новая задача в той же сессии | Скилл не вызывается повторно, режим auto применяется по памяти |
| 23 | Карточка t-boards без описания и без `notionPageId` | Постановки нет — вопрос владельцу, требования не додуманы |
| 24 | Запись на карточку отклонена по `fencingToken` | Аренда молча не перевыдаётся: `forest_list_work_state` и доклад, кто держит карточку |
| 25 | Повтор пачки записей, `approvalId` уже потрачен | Статус сверен через `get_task`, нового запроса одобрения нет |

Классификатор хука: `python3 -I .claude/hooks/test_grill_hint.py` (без сессии, state и сеть не трогает).

## Почему так, а не как в исходном предложении

- **Состояние вне `docs/`** (`prototipes/grill/<id>/`): по `docs/CLAUDE.md` рабочие заметки сессий в `docs/` не
  кладут, канон открытой постановки — t-boards. Состояние живёт на одной машине; долговечен только полный текст
  спеки комментарием на карточке и, при изменении модели домена, `docs/specs/<модуль>.md`.
- **«Бюджет ресурсов» в спеке с числами** — линза ресурсов канона; галочка «ресурсы учтены» без числа = FAIL.
- **Без `disable-model-invocation`**: с этим флагом скилл недоступен модели и субагентам даже по прямой просьбе
  «прожарь карточку X» (тот же довод, что в `.claude/skills/VENDORED.md`, патч 1).
- **Автозапуск на каждую новую задачу** (решение владельца 2026-10-08): хук `UserPromptSubmit` подсказывает,
  модель решает «задача или продолжение». Продолжение — только вся реплика целиком («Давай сразу в мейн»), не
  префикс («Давай добавим экспорт» — задача): лишняя подсказка (~120 токенов) дешевле пропущенной прожарки.
  Чтобы автозапуск не стал церемонией: исход 1 молчит; вопросов ≤ 3; видимая фича — не повод для полной спеки;
  «развилка» — только продуктовое и необратимое, реализацию и порядок агент решает сам. Ядро `SKILL.md` —
  только режим auto; полный режим — в `full.md`: исход 2 больше не читает `protocol.md` (−~2,9K токенов),
  повторные задачи сессии скилл не перезагружают (замер 2026-10-08: ядро ~4,4K символов ≈ 1,7K токенов).
- **Адверсариальная проверка обязательна** (x ≥ 3), а не «по желанию»: спека — предложение, канон проекта
  `.claude/memory/chunks/process/adversarial-review.md`. Цена снижена: один раз на версию, sonnet, в промпт — пути
  к файлам, а не текст (замер при создании: ~7K токенов на загрузку скилла, проверка x=3 — порядка 75–100K).
- **Только Claude Code**: в зеркала `.agents/`/`.continue/` не синхронизируется (`sync-agent-skills.sh` ведёт
  только вендоренные скиллы). Расширять — после прогона сценариев выше.

Идеи процесса: `mattpocock/skills` (`grilling`, `grill-with-docs`) — пакет самостоятельный, не копия апстрима.
