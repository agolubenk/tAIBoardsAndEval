## 0. Коротко

   что вред окна в 1M в одном: оно позволяет копить. Рычагов три: сколько вызовов, какой контекст в каждом,
   сколько раз он остывает.
2. **Самый большой множитель уже снят.** С начала Т3 стоит потолок `autoCompactWindow=250000`. Средний контекст
   упал с 515K до 141K. Модель «объём работы Т2 в режиме Т3»: $1 298 → ≈ $714 (−45%), то есть с $68 до ≈ $37 на PR.
3. **Главные рычаги теперь другие:**
   - **база** — 83K из 141K, то есть 59% каждого вызова;
   - **координация** — 16% вызовов и 22% денег Т3;
   - **`effortLevel: xhigh`** при дефолте Opus 5.5 `medium`;
   - **вызовы с одним инструментом** — 81%.
4. **12 механизмов** дают ещё −40…50% от модели Т3, цель — ≈ $20 на PR. Снаружи ничего не меняется.
5. **Фаза 1 — только настройки и файлы.** Это дни работы, откат — одной строкой. Сервисы (Нерв, Рой, Капсула)
   идут через тень, затем через пилот.

## 3. Принцип: команда — организм, а не офис

Сегодня команда устроена как офис. Каждый держит в голове всё, сообщает статус письмами, сам проверяет почту и спит
с открытыми папками. У живых систем та же задача решена дешевле:

| В природе | Что это даёт организму | Наш механизм | Какой счётчик сдвигает |
|---|---|---|---|
| Геном и экспрессия генов | клетка читает только нужные гены | **Геном роли** (P1, P5) | база первого вызова |
| Апоптоз | клетка умирает, когда работа сделана, и не тянет ресурс | **Конец сессии на границе задачи** (P2) | холодные «сон», сжатия |
| Рефлекторная дуга | на стимул отвечает спинной мозг, а не кора | **Нерв** — демон без LLM (P8) | Monitor, Cron, опросы |
| Стигмергия (муравьи) | общение через среду, а не адресно | **Доска**: PR, метки, `work_state` (P9) | SendMessage, пробуждения от сообщений |
| Гормоны и нервы | срочное — сразу, фоновое — накопленно | **Две скорости сигналов** (P9) | холодные пробуждения |
| Чувство кворума | бактерии действуют, когда сигналов достаточно | **Кворум-пробуждение Контроля** (P9) | сообщения «собран» |
| Миелинизация | частый путь становится быстрым | **Рефлексы-скрипты и пакетные вызовы** (P6) | вызовы с одним инструментом |
| Иммунная память | антитело появляется при встрече с антигеном | **Уроки по триггеру**, а не весь индекс в каждом старте (P5) | MEMORY.md в базе, повторные ошибки |
| Касты | рутину делают дешёвые особи | **Рой**: Haiku и бесплатные модели (P11) | хвосты Bash/Read, цепочки чтения |
| Сон | память консолидируется ночью | **Ночная консолидация и капсулы** (P10, P12) | чтение истории при старте |
| Метаболизм | энергию тратят по бюджету | **Квота как бюджет**, циркадные режимы (P12) | недельный лимит |

## 4. Предложения

Формат — из `PROTOCOL.md`. Экономия дана двумя цифрами: «факт Т3 / Т3 под нагрузкой». Ключи Claude Code — в
`data/claude-code-controls.md`. Часть ключей требует версию новее локальной 2.1.237.

### P1. Геном роли — профиль сессии команды

- **Механизм.** Запуск `claude --settings pipeline/genome/<роль>.json`. Сессии владельца остаются как есть. В профиле:
  - `enabledPlugins: false` для 10 плагинов, которые команда не вызывает (список — в `claude-code-controls.md`), и
    для плагинов организации, если их можно выключить;
  - `skillOverrides` — `off` или `name-only` для скиллов проекта вне роли;
  - `permissions.deny` для инструментов вне роли: `Artifact*`, `DesignSync`, `PublishPlugin`, `Workflow` у всех, кроме
    Координатора, `mcp__docker`, `mcp__github` (команда работает через `gh`), `mcp__sentry`, `mcp__cloudflare`,
    `mcp__claude_ai_*`, а также один из двух Notion — сейчас он подключён и напрямую, и через хаб;
  - `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH=600`.
- **Экономия.** База 83K → ≈ 50–55K. Оценка по слоям:
  - список скиллов 8.7K → 1.5K;
  - схемы, имена и инструкции ненужных инструментов −10…14K;
  - инструкции −8K (за счёт P5);
  - SessionStart −1…2K.

  Деньги: −$7 (−18%) / −$87 (−12%).
- **Измерение.** §6 аудита — медиана первого вызова ≤ 55K; `вложение:skill_listing` ≤ 2K.
- **Риск.** Роли понадобится выключенный инструмент. Профиль собирается по факту вызовов за Т2 и Т3, при сбое сессия
  запускается без профиля.
- **Откат.** Запуск без `--settings`.
- **d-решение.** Да, d1.

### P2. Апоптоз — сессия живёт одну единицу работы

- **Механизм.** После своей единицы (PR влит, вердикт линзы выдан) сессия пишет капсулу (P10) и завершается.
  Следующую единицу берёт свежая сессия: база ≈ 55K + капсула ≤ 2K. Сейчас вместо этого сессия спит со 100–250K
  контекста (холодное пробуждение стоит $0.8–2) или теряет детали на автосжатии.
- **Экономия.** Факт Т3: «сон > 60 мин» и сжатия — $8.4 (21%), достижимо −$4…8. Под нагрузкой: 107 сжатий заменяются
  ≈ 60 стартами по $0.46, средний контекст падает → −$90…110 (−13…15%).
- **Измерение.** Холодные «сон» и «сжатие» → около 0; средний контекст ≤ 110K.
- **Риск.** Потеря контекста на границе. Защита — обязательные поля капсулы. Первую неделю старая сессия хранится,
  но не будится.
- **d-решение.** Да, d2 — меняет TEAM-0.

### P3. Без двойной загрузки из worktree

- **Механизм.** Ключ `claudeMdExcludes` с путями копий всегда загружаемых файлов в worktree:
  `…/HR_Helper-v2/worktrees/*/*/CLAUDE.md`, `…/worktrees/*/*/.claude/rules/0[01]-*.md`, `…/90-team-t3.md`. Правила с
  `paths:` в worktree продолжают грузиться — они там нужны.
- **Экономия.** В Т2 повторно загружено 566K токенов (хвост $23, 1.8%). В режиме Т3 −$6…8 (≈ 1%). Мелко, но без риска.
- **Риск.** Правки CLAUDE.md внутри ветки сессия не увидит до мёржа. Это приемлемо.
- **d-решение.** Входит в d1.

### P4. Хук на входе — только для человека

- **Механизм.** `UserPromptSubmit` (DAMS-RAG ≈ 820 токенов + `grill-task-auto`) пропускает сообщения агентов,
  уведомления задач и мониторов. Поля происхождения у хука нет, поэтому распознавание идёт по маркерам текста, как в
  `wake_kind()`.
- **Экономия.** 57% токенов хука, −$3 под нагрузкой. Заодно не тратится локальный CPU на RAG.
- **d-решение.** Входит в d1.

### P5. Иммунная память вместо всего индекса в каждом старте

- **Механизм.**
  - MEMORY.md (17.9 КБ, 85 записей, 4.1K токенов) превращается в **«био»** ≤ 1.5 КБ: 10–12 постоянных
    предпочтений владельца и ссылка на полный индекс `memory/INDEX-full.md`, который сам не грузится.
  - Уроки, привязанные к инструменту (≈ 15 из 37 `feedback_*`), уходят в таблицу антигенов
    `regex(инструмент+команда) → файл урока`. Примеры:
    - `git replay`;
    - `gzip`;
    - `"$R:`;
    - `for … in $(`;
    - `mem-gate.sh … |`;
    - `Monitor` с `| grep`;
    - `oq_get` по checks;
    - `vitest --root`;
    - `git` в worktree без `-C`;
    - запись времени HH:MM.
  - Хук PreToolUse вставляет урок (≤ 300 токенов) один раз за сессию — в момент, когда встретился антиген.
- **Почему это не только экономия.** Индекс в каждом старте не помешал ошибкам повториться. В нём есть пары-дубли:
  «Time labels only from date» и «Time only from date»; «zsh `$R:a`» и «zsh: no word splitting». Урок в момент
  действия сильнее урока в начале сессии.
- **Экономия.** −3.5K базы (входит в P1).
- **Измерение.** Журнал срабатываний триггеров; повторные инциденты тех же видов.
- **d-решение.** Входит в d1 — это личная память владельца.

### P6. Миелинизация — рефлексы-скрипты и пакетные вызовы

- **Механизм.**
  1. Хук вставляет местное время в каждый `UserPromptSubmit` и в PreToolUse для `Write`, `SendMessage` и `oq_*`.

  2. 5–8 скриптов-рефлексов, у каждого описание в одну строку:
     - `pr-state <n>` — одной строкой голова, CI, ревью, mergeable; заменяет цепочку `gh pr view` + `git fetch` + `gh pr checks`;
     - `wt-state`;
     - `handoff-read <роль>`.
  3. В геноме роли — правило: независимые чтения идут одним ответом с несколькими инструментами, разведка — одним
     Bash с несколькими командами.
- **Экономия.** −10…15% рабочих вызовов → −$1 / −$30…40 (4–5%).
- **Измерение.** Инструментов на вызов 1.3 → ≥ 1.8; вызовов `date` → около 0.
- **d-решение.** Нет.

### P7. Усилие по роли

- **Механизм.** Сейчас `effortLevel: xhigh` стоит всем. Предлагается `CLAUDE_CODE_EFFORT_LEVEL` в геноме по роли:
  - `xhigh` — где рассуждение и есть продукт: трудный PR автора, линза безопасности;
  - `high` — автор по умолчанию;
  - `medium` — Координатор, Контроль, рутинные линзы.

  Мышление Opus 5.5 остаётся в контексте разговора, поэтому меньшее усилие — это ещё и более медленный рост контекста.
- **Экономия.** Выход −25…35% и меньше сжатий → −$1.5 / −$50…65 (7–9%).
- **Риск.** Качество. Нужен пилот на одной роли с тем же типом PR; мерить «changes requested» и переоткрытия.
- **d-решение.** Да, d3 — xhigh владелец выбрал сознательно.

### P8. Нерв — рефлекторная дуга без мозга

- **Механизм.** Демон launchd на стандартной библиотеке Python. Источники:
  - GitHub (PR, CI, ревью; условные запросы по etag бесплатны);
  - ответы владельца из очереди;
  - хвосты транскриптов («hit your weekly limit», 429);
  - давление памяти;
  - здоровье хаба.

  На каждую роль — свой входящий файл. У сессии **один** Monitor на `nerve-tap <роль>`, который печатает строку
  только когда действовать нужно именно ей — такую форму уже требует правило 6 в `90-team-t3`. Вырастает из
  сторожа Kimi (задание B).
- **Экономия.** −70% опросов (Monitor 79, Cron 51, TaskStop 42, `gh pr view` 137, `git fetch` 134 в Т2) и меньше
  холодных пробуждений → −$2…3 / −$30…40.
- **Качество.** Остановка по лимиту замечается за минуты, а не за часы.
- **d-решение.** Да, d4 — автозапуск.

### P9. Стигмергия, гормоны и кворум

- **Механизм.**
  - Статусы пишутся в среду — комментарии и метки PR, `work_state`. Сообщение получает только «нервный» класс:
    «прод НЕ ОК», «стоп/откат», назначение, d-ответ.
  - «Гормоны» (к сведению, статус) Нерв собирает в дайджест и отдаёт при следующем естественном пробуждении,
    не реже раза в 2 ч.
  - **Кворум.** Нерв сам считает «все нужные линзы одобрили одну и ту же голову и CI зелёный» и один раз будит
    Контроль. Это заменяет поток «#n собран».
- **Экономия.** −50…70% сообщений. В Т2 их 883, и каждое — вызов отправителя плюс пробуждение получателя,
  холодное стоит $0.7–4. Итого −$2 / −$25…35 плюс холодные пробуждения.
- **Риск.** Запоздалая реакция. Поэтому «нервный» класс доставляется всегда немедленно.
- **d-решение.** Да, d2 — правило 3 TEAM-0.

### P10. Капсула — контекстный пакет ≤ 2K

- **Механизм.** Фиксированные поля капсулы:
  - цель и приёмка;
  - решения со ссылками;
  - состояние — ветка, голова, worktree, PR, CI; заполняет скрипт, без токенов LLM;
  - следующий шаг;
  - «не делать»;
  - ссылки на оригиналы.

  LLM дописывает только решения и только на границах. Канон — `work_state` в claude-mem, один источник. Правило
  «`work_state_write` после каждого шага» (661 вызов в Т2, 9.6% всех вызовов) заменяется хуком PostToolUse, который
  пишет механику (ветка, голова, pid) без хода модели.
- **Экономия.** −$1 / −$20…25 и меньше потерь контекста на передачах.
- **Совпадение.** Это «контекстный пакет 2–8K» из Dev4dev.
- **d-решение.** Да, d2.

### P12. Циркадный ритм — квота как бюджет и ночная консолидация

- **Механизм.**

    - день — полный;
    - вечер — только «нервные» пробуждения;

## 5. «Колония» — своё MCP (то, о чём просил владелец)

Это сервер **за существующим хабом**, с тегом `colony`. Второго шлюза нет — тут я согласен с Dev4dev. Шесть
инструментов, около 1.2K токенов схем, и они отложены:

| Инструмент | Что делает | Чем заменяет |
|---|---|---|
| `swarm_run(kind, input_ref, question, out_schema?)` | сервер сам читает файл, glob или вывод команды. Сырые байты в контекст Claude не попадают, возвращается вывод ≤ 300 токенов с ссылками `file:line` | цепочки чтения, длинные логи |
| `swarm_ledger()` | расход и точность по провайдерам | — |
| `nerve_digest(role)` | накопленные «гормоны» роли одной выдачей | поток сообщений |
| `nerve_ack(id)` | отметить, что событие отработано | повторные пробуждения |
| `capsule_get(task)` / `capsule_put(task, decisions)` | капсула задачи; механику заполняет сервер | `work_state` после каждого шага |

Устройство роя:

- **Маршрутизация.** `kind` → цепочка провайдеров. Запасной провайдер — при 429 или 5xx. Квоты берутся из заголовков
  ответов, у каждого провайдера свой предохранитель.
- **Очистка.** Запрет путей `.env*`, `*.pem` и дампов; маскирование ключей, токенов и PII; ограничение размера.
- **Кэш** по хэшу содержимого: тот же лог дважды — без вызова.
- **Проверка.** Каждый ответ несёт утверждения со ссылками `file:line`, Claude выборочно проверяет 1–2. Это
  принцип evidence из Dev4dev.
- **Отбор.** Принятые и отклонённые ответы копятся в журнале, маршрут перестраивается по измеренной точности.

Бесплатные провайдеры. Это кандидаты: условия меняются, лимиты и политику данных проверять при настройке.

- **Groq** и **Cerebras** — очень быстрые открытые модели; подходят для триажа и классификации.
- **OpenRouter** — модели `:free` с дневным лимитом запросов.
- **Google AI Studio** — Gemini Flash. На бесплатном уровне данные могут использоваться для улучшения продукта,
  поэтому только несекретный текст.
- **Mistral** — бесплатный план.
- **GitHub Models**.
- **Cloudflare Workers AI** — дневная квота; аккаунт Cloudflare уже подключён.
- **NVIDIA NIM**, **SambaNova**, **Hugging Face** — стартовые кредиты.
