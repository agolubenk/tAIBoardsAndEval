## Часть A. Линза «продукт и простота»: находки

Формат: [критичность] находка → предложение. Blocker — нет.

### A1. [major] Этап 1 не влезает в окно 06–20.11 даже после Q-101
Риск записан в спеке, но недооценён состав: этап 1 = доски с 7 видами + мобильная вёрстка + RU/EN + MCP + память +
**блокнот** + импорт. Блокнот (чат с источниками как NotebookLM, эмбеддинги, пересказ GLM, R-050–R-053) — отдельный
продукт по трудозатратам, сопоставимый с досками. Приоритет 4 у него — ниже, чем у досок (5).
→ Предложение: блокнот в этап 2, либо v1 блокнота урезать до «источники = карточки t-boards + docs/, без кода через
Serena и без внешних ссылок». Иначе окно 06–20.11 невыполнимо, а риск-запись это уже признаёт.

### A2. [major] Граф связей (R-090) — самый тяжёлый экран при одном пользователе
Кластеризация >200 узлов (AC-018), отдельная загрузка через `import()` — это недели работы ради экрана, которым
пользуется один человек. Лента «что горит, что ждёт вас» и палитра ⌘K дают больше ежедневной пользы.
→ Предложение: граф — этап 2. В v1 связи показывать списком на карточке (данные те же, R-024, рендер тривиален).

### A3. [major, уточнение] R-032: «2500 — потолок на задачу» двусмысленно
Смешаны два потолка: размер одного ответа MCP (150–2500 — разумно) и «контекст-пакет» в той же фразе. Если 2500 —
потолок всего пакета задачи, code-задачи не влезают: символы + diff + правила — это 8–20 K (мой r1-kimi §2, спор №3
с Dev4dev-документом, где пакет 2–8 K назван целью). При приёмке AC-001/AC-012 двусмысленность взорвётся.
→ Предложение: разделить явно — «потолок одного ответа MCP: 2500; бюджет пакета задачи задаётся вызовом
(`input_token_budget`), норма фиксируется по замеру AC-001 (p50/p95), а не заранее». Число 2500 из ответа Q-017
остаётся нетронутым.

### A4. [major по продукту, minor по коду] Нет главного сценария владельца: «кинул мысль → получил карточку»
R-030: человек задаёт ≤ 40 % содержания через UI (текст, скриншоты, формы). Но реальный вход владельца сегодня —
пересланное сообщение в бота очереди. В списке сценариев (§Пользователи) нет «владелец кидает ссылку/голос/абзац →
агент разворачивает в черновик карточки → владелец подтверждает». Именно он снижает долю 40 %.
→ Предложение: сценарий «черновик карточки от агента» в этап 1: форма ввода + вызов GLM/free-модели в рамках R-053
(0–10 000 вызовов уже заложены). По коду — один экран и одна очередь.

### A5. [major по простоте] Семена и «выращивание леса» (R-028) — второй жизненный цикл в v1
Модель леса последовательна, но семена — отдельный механизм (сжатие веток, provenance, выращивание, AC-020).
Вырубка с брёвнами уже закрывает проблему «кладбища задач» (Q-052).
→ Предложение: в v1 — вырубка + брёвна; семена — этап 2. AC-020 режется пополам (остаётся вырубка сектора).
Ветки брёвен не восстанавливаются в любом случае (N-010), так что отсрочка семян ничего не сжигает.

### A6. [minor] EN-перевод интерфейса можно докатить после перехода
R-093: RU + EN в v1. Условие «если дешевле» выполнено (i18next в kaneo есть), но контент-перевод — это работа.
Пользователь один, язык RU. → EN — фоном бесплатными моделями после этапа 1, не блокируя окно.

### A7. [minor] Дубли с продуктом: зафиксировать «почему не модули продукта»
Pre-flight уже отметил: в бэкенде продукта есть wiki, mcp, agent-memory, quick-notes. Q-001 решил «отдельное
приложение». → Одна фраза в спеке «модули продукта не развиваем, потому что …» — иначе через полгода два
quick-notes и рассинхрон, от которого t-boards и строится.

### Сильные стороны (отметить, не трогать)
- N-011 (агент не может поставить «да» владельца) — простое и правильное закрытие целого класса рисков.
- Зеркало Notion read-only + идемпотентный импорт по namespaced ключу (R-080/R-081, AC-026) — эталон осторожности.
- lease с именем владельца захвата в отказе (R-026/R-028) — хороший UX ошибки, дёшево.
- «Не изменилось» по хэшу и курсоры (R-031) — прямое попадание в экономию токенов.

**Итог линзы: approve with changes** — спека утверждаема после решений по A1–A5 (все — сокращения этапа 1,
противоречий с ответами владельца нет: приоритеты Q-049 это позволяют, т.к. граф и семена не названы приоритетом 5).

## Часть B. Стыковка с r1-kimi.md и моим architecture-overview2.0.md

### B1. Q-107 (стек) — расхождение снято
Спека рекомендует TS/kaneo-ядро, Python только адаптерами; мой обзор (§2) аргументировал то же + Bun-мост к
TS-плагинам Claude Code. Архитектура Claude §16.1 (Python) остаётся единственным носителем Python-варианта.
→ Рекомендую владельцу закрыть Q-107 в пользу TS/kaneo + Bun. d-решение.

### B2. Контракты MCP совпадают — закрепить
R-031 (режимы выдачи: сводка, «не изменилось» по хэшу, только изменения с T, бюджет токенов в вызове) = проекции
V0–V2 моего обзора и P4 из r1-kimi. R-043 («компилятор контекста LLM не вызывает») = моё P4 (детерминированная
компиляция). → Предлагаю одну фразу в спеке: «компилятор контекст-пакетов реализуется детерминированно поверх
режимов R-031» — и контракты пайплайна и t-boards совпадают навсегда.

### B3. R-037 + Q-104 = моё P10 (наследники)
«t-boards готовит пакет и проверяет приём наследником; автозапуск — позже, с отдельным да» — совпадает с P10
r1-kimi (snapshot-наследник после d-решения). Конфликта нет; d-решение одно на оба документа.

### B4. R-036 (журнал агента) + моё P9 (выходная экономия)
Шаблон выхода ролей «решение → доказательства (ссылки) → откат» ложится на поля журнала R-036 (токены, стоимость,
ссылка на транскрипт). Предлагаю в R-036 добавить поле «формат финального отчёта» — синергия без нового кода.

### B5. Расхождение размещения форка
Спека: `apps/t-boards` (R-001). Факт: форк склонирован в `boards` (ветка `t-boards`, чистое дерево).
Инженерное ограничение про npm workspaces vs pnpm уже записано в спеке. → Решить до первого коммита: либо перенос
в `apps/t-boards` с переводом на npm workspaces, либо поправка R-001 на «вне apps/, отдельный pnpm-монорепо в
монорепо». Второе дешевле (kaneo остаётся на родном pnpm/Turborepo).

### B6. Подтверждаю критичность paths-ignore
Без `paths-ignore` для t-boards в `deploy-contabo.yml` каждый пуш в main = ~3 мин 502 на проде. Это блокер любого
коммита форка в main — поднимаю приоритет этой строки до «сделать до первого коммита» (в спеке она есть, но без
срока).

### B7. Транскрипты: 130–250 ГБ за 9 месяцев — поддерживаю оценку ревьюера
Мои замеры сессий (wire.jsonl этой сессии — десятки МБ на окно) подтверждают порядок. D-016 (отдельный
зашифрованный том + квота + срок после недельного замера) — правильная форма; добавить: сессии Т2-масштаба
(14 ролей) — это верхняя граница расчёта, Т3 (6 ролей) — нижняя.
