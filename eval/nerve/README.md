# Нерв — нервная система команды сессий (П7, П8, П10)

Решение владельца **d-pipe-nerve = «да»** (28.10, заметка: «все сразу и сегодня, автозапуск и авто-действия делаем»).
Демон на Mac, только stdlib Python, под launchd. Будит сессию **только когда действовать нужно именно ей**,
вместо опросов, «как дела» и копий сообщений (правила 3–6 TEAM-0).

Состояние на 28.10 16:15 МСК: LaunchAgent `space.hrhelper.nerve` загружен, 15 тестов зелёные,
первый проход 59 с (засев GitHub), следующие ~6 с.

## Как устроено

```
источники (раз в 60 с; ночью ×5)          журнал state/journal.jsonl           тапы ролей (Monitor)
 GitHub: PR, головы, вердикты, CI  ─┐      append-only, ключ идемпотентности,   nerve.py tap <роль>
 очередь владельца: ответы, inbox  ─┼──►   запись ДО доставки           ──►     печатает строку, только
 транскрипты: расход $, отказы      │      класс: nervous | digest              когда роли действовать
 система: память, хаб :3050        ─┘      адресаты: роли / all
                    │
                    └─► авто-действия (actions.py) ─► state/mode.json (фаза, пауза, пачки, окно 5 ч)
```

- **nervous** — печатается сразу: ответ владельца на d-пункт, «стоп/откат» из inbox, кворум PR, лимит снят,
  предвестник лимита, критическая память, хаб лёг.
- **digest** — копится и выходит одной строкой раз в 30 мин (×2 в режиме пачек), только днём и не во время паузы:
  новый PR, changes автору, PR закрыт, обычный inbox, сбой и восстановление источника.
- **Кворум**: все ≥ 3 линзы одобрили одну голову, changes на ней нет, CI не в процессе → **один** раз будится
  Контроль (`release`), ключ `gh:quorum:<n>:<голова>`. Это замена сообщения «#n собран» (правило 3).
- **Маршрут ответа владельца**: по полю `source` пункта (`config.json → queue.source_roles`, регэкспы).
  Текст заметки владельца в журнал не пишется — только «есть заметка» (заметки бывают с PII и ссылками).

## Авто-действия (actions.py)

| Событие | Действие |
|---|---|
| Окно 5 ч израсходовано на 80 % от квоты окна | всем активным ролям: «допиши шаг, запиши work_state, тяжёлое не начинай» (не чаще раза в 5 ч) |
| Окно на 60 % | `mode.batch = true`: дайджест реже, линзы пачками |
| Отказ «hit your … limit» в транскрипте | Координатору одна строка; тапы молчат (`pause`) до сброса, кроме `limit.*` и `owner.stop` |
| Сброс прошёл **или** запросы снова проходят (сменили аккаунт) | активным ролям «лимит снят: продолжай с work_state»; придержанное печатается с пометкой |
| Сброс ночью (22:00–08:30) | будить в 08:30 |
| Недельный лимит | пункт владельцу `c-nerve-weekly-ГГГГММДД` (вид check), сначала GET — существующий не перезаписывается |
| Демон молчит > 5 мин | тапы `coord` и `release`: «НЕРВ МОЛЧИТ … launchctl kickstart -k …» (одна строка на эпизод) |

**Квота окна** — медиана расхода до отказа в последних 6 волнах (калибруется сама на каждой волне; на 28.10 — $17.2
по прайсу API). **Окно 5 ч** начинается не раньше последнего отказа или прошедшего сброса. **Неделя** — с четверга 19:00.
Расход — по прайсу API из `usage` транскриптов (как `tools/context_audit.py`): это мерило лимита, не деньги.
Пауза — по факту отказа, не по 502 (связь 502 с лимитом не доказана).

## Команды

```bash
N=eval/nerve
python3 -I $N/nerve.py status              # пульс, режим, лимит, волны, ошибки источников, последние адресные события
python3 -I $N/nerve.py tap <роль>          # ← это ставит Monitor роли (persistent); --once — один проход
python3 -I $N/nerve.py emit <роль> "текст" # назначение вручную (Координатор), класс nervous
python3 -I $N/nerve.py once [--seed]       # один проход руками (демон держит замок — once его не берёт)
python3 -I -m unittest discover -s $N -p 'test_*.py'
```

Роли: `coord plan backend frontend release review` (ключи реестра Т3) и `supertick`, `tboards` (по `source` пунктов).
Сессия роли ставит **один** Monitor: `python3 -I eval/nerve/nerve.py tap <роль>` — фильтр внутри, без `| grep`
(память `feedback_monitor_no_pipe_filters`). Курсор тапа — `state/tap-<роль>.json`, первый запуск начинает с конца журнала.

## Установка и откат

```bash
cp supertick-eval/nerve/space.hrhelper.nerve.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/space.hrhelper.nerve.plist
launchctl kickstart -k gui/$(id -u)/space.hrhelper.nerve      # перезапуск после правки кода
launchctl bootout gui/$(id -u)/space.hrhelper.nerve           # ОТКАТ: сессии возвращаются к правилу 3 TEAM-0
```

Лог — `state/nerve.log` (в норме пуст: ошибки источников идут в журнал как `nerve.error`). Python —
`/Library/Frameworks/Python.framework/Versions/3.14/bin/python3`, не `/usr/bin/python3` (шим Xcode, лицензия не
принята). Перезапуск только при сбое (`KeepAlive.SuccessfulExit=false`), второй экземпляр выходит по замку.

## Границы

- Снаружи не меняется ничего, кроме пункта владельцу при недельном лимите (d4). PR, карточки, бот, прод — как были.
- Токен очереди — из связки ключей (`mcp-secret.sh OQ_TOKEN`), в curl идёт через stdin (`-H @-`), не в argv и не в лог.
- Python `urllib` на этой машине падает на SSL ops-консоли — поэтому curl.
- Смена аккаунта распознаётся эвристикой «после отказа снова есть расход > $0.05». Два аккаунта одновременно на разных
  сессиях она не различит (транскрипт аккаунт не пишет).
- `shadow/watchdog.py` (AUTH, STALE, DISK, APIERR) остаётся отдельным теневым наблюдателем; в Нерв перенесены
  LIMIT и MEM. Перенос AUTH — следующий шаг, если понадобится.
