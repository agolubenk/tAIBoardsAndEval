# Перезапуск роли в терминале (30.10, вечер)

Решение владельца `d-genome-stage0-3010` (21:55): все 6 ролей переезжают из панели VS Code в терминал, теперь с
геномом. Роль, полоса, списки и метка в лесе остаются прежними. Меняется только сессия: дела сдаёт вкладка этой же
роли в панели, её имя — в строке запуска.

## Что прочитать

1. `roles/<N>-<ключ>.md`, `COMMON.md`, `T-BOARDS.md` — для роли, законов и ловушек. Разделы о приёме дел у старых
   сессий уже выполнены 30.10 в 18:42–19:10, повторять их не нужно: «Принимаешь от», «Первым делом», «Сразу»,
   «Захватить в очереди». Отчёты в `$C` заново не разбирай.
2. Дела бери у предыдущей сессии:
   - `work_state_read <ключ>-t3` и списки, на которые он ссылается (у роли 6 — ещё `b13-import`);
   - `forest_list_work_state` своего пространства, метка `t3-<ключ>`.

   Если пусковой файл расходится с ними, верь work_state и лесу: они новее.
3. Если чего-то не хватает, спроси предыдущую сессию одним сообщением, пока её вкладка открыта.

## Первые шаги

1. `forest_set_work_state`: `session: "t3-<ключ>"`, `harness: "claude-code"`, `step: "принимаю дела от <имя>"`.
2. Нерв: один Monitor (persistent) `python3 -I eval/nerve/nerve.py tap <ключ>`.
3. Фоновые задачи и Monitor предыдущей сессии закроются вместе с её вкладкой. Задачу, которая в work_state значится
   запущенной, но без результата, запусти заново сам, по одной тяжёлой за раз.
4. Пункты очереди, где в `checks` agentBy — имя предыдущей вкладки, перехвати через `oq_agent_status` с `session`.
5. Готово:
   - `forest_set_work_state` со `step: "дела приняты от <имя>; моё имя <своё имя из ListAgents>; дальше — <дело>"`;
   - одна строка оркестратору `hr-helper-v2-37`: «дела приняты, роль N, имя …».

   По этому сигналу оркестратор просит владельца закрыть старую вкладку.

имя. Пока новая роль не поставила «дела приняты», пиши её предыдущей вкладке.
