## Что такое «команда»

Это несколько **долгоживущих интерактивных сессий Claude Code** в VS Code на одном Mac
(24 ГБ памяти, macOS) и одной подписке Claude. Модель — Opus 5.5 с контекстом 1M.
Каждая сессия держит свою роль и работает с бэклогом непрерывно, а не над одной фичей:

- берёт карточки из Notion;
- пишет PR;
- отдаёт PR на проверку другим ролям («линзам»);
- PR вливает одна роль, Выпуск (бывший Контроль);
- **влитый в `main` PR сразу деплоится в прод**, если коммит не помечен `[skip ci]`.

Сессии общаются друг с другом через `SendMessage` (сообщения между сессиями). Состояние каждая пишет в claude-mem
`work_state` (список `<ключ>-t3`), а с 30.10 ещё и в лес t-boards (`forest_set_work_state`, ярлык `t3-<ключ>`):
его видят все роли и владелец, поэтому статус больше не спрашивают сообщением. Каждая роль запускается со своим
геномом — `claude --settings ../pipeline/genome/<ключ>.json` (лишние плагины, скиллы и MCP выключены). Решения и действия владельца идут в очередь владельца — консоль ops и
Telegram-бот, MCP `oq_*`.

## Что будит сессию

Сессия тратит токены, только когда её будят. Каждый вызов модели заново читает весь контекст
(чтение кэша — $0.20 за 1M токенов). Если сессия спала дольше TTL кэша, контекст
записывается заново: при часовом кэше это вдвое дороже входа, $8 за 1M у Opus 5.5.

| Источник | Как устроен у нас | Замечания |
|---|---|---|
| Сообщение другой сессии | `SendMessage` | В Т2 — 57% расхода (`../data/cost-t2-2310.txt`) |
| Монитор | `Monitor` — скрипт печатает строку, строка будит. Живёт не больше 30–60 мин, потом сессию будит уведомление об истечении | По правилу Т3 фильтр стоит внутри скрипта, монитор будит только «когда действовать нужно именно тебе» |

## Жёсткие правила Т3 (полный текст — `.claude/rules/90-team-t3.md`, `T/TEAM-0-COMMON.md`)

1. После сжатия контекста — сначала `work_state_read <ключ>-t3`; после каждого шага — `work_state_write` и `forest_set_work_state`.
2. Разрешено шесть видов сообщений: назначение; «PR #n, голова, линзы»; «changes на SHA»; «#n собран»;
   «влито #n, проба ок»; «прод НЕ ОК / стоп / откат». Ни «принял», ни «ок», ни копий.
3. Вердикты пишутся комментарием в PR. Статус не спрашивают, а читают: `work_state_read`, `gh pr view`, очередь.
4. Владельцу пишет только Координатор.
5. Монитор ставится только на скрипт, который печатает строку, когда действовать нужно именно тебе.
   Ночью без задачи — ни кронов, ни мониторов.
6. Читай долю, а не целое. Субагенты и workflow — только по пункту `d-spend-…` с «да» владельца.
7. Мёрж = деплой. Вливает только Выпуск, по одному PR, с `--match-head-commit`.

Общие правила проекта:

- корневой `CLAUDE.md`;
- адверсариальная проверка решения — не меньше 3 участников с разными линзами;
- больше 2 субагентов или любой workflow — только с прямым «да» владельца на каждый запуск и с названной ценой;
- локальные модели Ollama — строго по одной.

## Что ломалось и стоило дороже всего

- **Недельный лимит.** 24.10 в 09:16 все 14 сессий упёрлись в недельный лимит Claude. Команда стояла до 29.10
  19:00, так что выходные потеряны. Главное ограничение у нас не деньги, а лимит подписки.
- **26.10 Т3 дважды стояла на 5-часовом лимите:**
  - в 09:44–09:45, почти сразу после запуска: Координатор, Проектировщик, Фронтенд, Выпуск, Проверка — «resets 2pm»;
  - в 14:28 за одну минуту Бэкенд, Фронтенд, Выпуск и Проверка — «resets 7pm»;
  - Проверка в 14:35 ещё и «Not logged in · Please run /login».

  Лимит общий на аккаунт, поэтому сессии встают разом. В журнале это ответ ассистента с `isApiErrorMessage: true`.

  Никто, кроме Координатора, этого не заметил: отличить тишину команды от её смерти нечем.
- **Сжатие контекста.** Т2 держала средний контекст 515K, пиковый — 967K. Это 54% расхода. Т3 ставит
  `autoCompactWindow 250000` и сокращает сессии до 6 (`T/tools/apply-settings.sh`).
