## Задача, которую он решает

Это плагин Claude Code для одной фичи за прогон. Ведущий режет фичу на задачи, собирает под неё команду
субагентов и доводит до приёмки. Ведущий — обычная сессия, и вот три его беды:

1. **Ожидание стоит денег.** Ведущий просыпается от внешнего события, тишину не отличает от смерти, и каждое
   «посмотрю, как дела» оплачено всем его контекстом. У автора — до 2,18M входных токенов на пробуждение.
2. **Доставка.** Сообщения терялись, ведущий пересылал письма руками, и каждая пересылка была ходом с полным
   контекстом. Одна пересылка при 437K обходилась в $0,38.
3. **Память.** Ведущий, который сам читает диффы, раздувается, а после сжатия забывает, кто чем занят.

## Механизмы

| Механизм | Как сделан | Файлы |
|---|---|---|
| Тик супервизора | Ведущий запускает `supervisor-wait.sh` фоновым Bash и заканчивает ход. Скрипт раз в 20 с гоняет `supervisor-tick.py` по файлам прогона и выходит, только когда есть действие P1+ (`--wake-on`) или истёк `--max` (3600 с). Конец фонового вызова и есть пробуждение. Модель между тиками не работает | `plugins/supertick/scripts/supervisor-wait.sh`, `supervisor-tick.py` |
| Приоритеты P0–P4 | P0: письмо не взято 2 мин, STUCK/ENGINE_DOWN, участник молчит 2 интервала. P1: DONE без приёмки, отчёт готов, вопрос без ответа. P2–P3: первые 60 с тишины, плановая точка, «гоняет тесты — busy». P4: спать дальше | `supervisor-tick.py`, `skills/team-feature/references/supervisor.md` |
| Файловая почта | Одно письмо — один файл `mail/<кому>/<время>_<от кого>_<KIND>[_task<id>].md`. Ответ, которого ждут, сначала ложится файлом, потом уходит сообщением | `team-mail.sh`, `team-wait.sh` |
| Всё на диске | `PLAN.md`, `state.md`, карточки участников, отчёты. После сжатия ведущий восстанавливается по файлам и одному тику | `run-state.py`, `.claude/teams/feature-<имя>/` |
| Приёмка по диффу | DONE — кандидат, а не результат. Разовый приёмщик видит только раздел задачи и дифф. Ведущий видит одну строку `ACCEPT: task #N — PASS/FAIL` | `agents/spec-verifier.md`, `unified-reviewer.md` |
| Короткая жизнь ролей | Кодер живёт одну задачу. Рецензент меняется каждые 3 задачи (без ротации дорастал до ~600K). Архитекторы уходят после дебата | `skills/team-feature/references/phase1-planning.md` (ротация), `team-runtime.md` |
| Механическая сложность | Шесть признаков MEDIUM; 0–1 → SIMPLE, 4+ → COMPLEX, при 2–3 проверяются ещё семь признаков COMPLEX. От уровня зависит состав: техлид, риск-тестеры, три архитектора | `skills/team-feature/references/phase1-planning.md` |
| Внешние движки | Любая роль уходит во внешний CLI (codex, kimi, grok, cursor) через `~/.claude/agent-teams.json`. Запуск — `run-engine.sh`: процесс отцеплен, ответ в `engine/<роль>/`, маркер `.done` пишется последним, журнал — `ledger.jsonl`. Голос движка совещательный; приёмщик всегда на Claude | `run-engine.sh`, `engine-sessions.py`, `references/engines.md` |
| Второе мнение | Только на задачах SENSITIVE (вход, деньги, миграции) и только движком другого вендора. Первого мнения не видит | `references/engines.md` |
| Зависимость от инструментов | Только `Agent` (с `name`), `SendMessage`, `ListAgents`, `TaskStop`. TaskCreate и TodoWrite на Opus 5 нет без `CLAUDE_CODE_ENABLE_TODO_TOOLS` | статья, раздел 2 |

## Цифры автора (по прайсу API)

| Прогон | Работа | Субагентов | Ведущий | Команда | Всего |
|---|---|---|---|---|---|
| SIMPLE, две мелкие карточки | 56 мин | 16 | $11 | $6 | $17 |
| COMPLEX, календарь | 2 ч 20 мин | 20 | $21 | $18 | $39 |

Плюс Cursor-вызовы (composer-2.5, grok) по подписке, в долларах не считались.

Сам автор признаёт, что до/после чисто не сравнить:

- Версия 0.13.1 без тика против 0.14.0 с тиком: пробуждений ведущего стало **больше** (35 → 50), а входных
  токенов на пробуждение — меньше (2,18M → 0,93M).
- Ведущий первой пачки стартовал с ~600K, второй — со свежих ~150K.
- Значит, выигрыш на пробуждение в основном дал свежий контекст, а не тик.

## Ограничения, важные для нас

- Busy-детект (живой pytest или jest = P3, а не ложный P0) читает `/proc`, то есть работает только на Linux.
  **На macOS правило не действует**, и долгие тесты дадут ложный P0. Проверено по коду:
  `supervisor-tick.py`, строки ~295–300.
- Ведущий ждёт **фоновый Bash**. У нас завершение фоновой задачи доходило до простаивающей сессии с опозданием
  на часы (`context/our-team.md`). До пилота нужен замер на нашей сборке.
- Тик не видит смерти Claude-участника (процесса нет). Её ловит только сверка состава на P0.
- Модель — одна фича за прогон, 16–20 субагентов на прогон. У нас больше 2 субагентов — только по прямому «да»
  владельца на каждый запуск.
- Живых прогонов на 1.0.0 — два. Это мало для выводов о стоимости.
