## Как вливать и проверять

**Ждать деплой.** `rc=1` с «error connecting» от api.github.com — обрыв связи, а не провал деплоя:

```bash
for i in 1 2 3 4 5 6; do gh run watch <id> --exit-status --interval 60 > /tmp/w.log 2>&1; rc=$?; grep -q "error connecting" /tmp/w.log || break; done
gh run view <id> --json conclusion,headSha
gh run view <id> --log | grep -E "startup graph|Стек поднят|nginx пересоздан|код 30|✓ https"
```

**После каждого деплоя:**
1. **Браузер, не HTTP 200.** `node <tools>/prod-probe.cjs https://app.hrhelper.space/login` → rc 0: `#root` отрисован,
   pageerror 0, swagger не в preload. Хэш `entry` должен совпасть с локальной сборкой того же дерева (`npm run build` →
   `dist/index.html`) — тогда на проде ровно проверенный бандл.
2. **Снаружи:**
   - `/api/v1/health/ready` → 200;
   - новые маршруты → 401, а не 404;
   - после правок nginx:
     - маршрут частей записи встреч: OPTIONS → 204; PUT с `x-amz-copy-source` → 403 от nginx; PUT/GET без подписи →
       403 MinIO `AccessDenied`, не 429;
     - `node <tools>/limit-probe.mjs` → `VERDICT: per-user buckets live`.
3. SHA, run id и итоги — «Контролю». Свой статус — `oq_agent_status`.

**Склейка в один деплой.**
- Гейты на объединённом дереве — в отдельном worktree:
  - typecheck;
  - тесты затронутых модулей;
  - фронт: `npm run build` + `bundle:startup` + `smoke:dist`;
  - `<tools>/nginx-t.sh`.
- Перед мёржем — `git diff <main после мёржей> <проверенное дерево>` должен быть пуст.
- Мёржи — по одной явной команде на PR. Не циклом `for p in "N ветка"; do set -- $p`: в zsh строка не делится, и 17.10
  #202 из-за этого ушёл первым.
